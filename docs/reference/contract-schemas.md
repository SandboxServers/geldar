# Contract schemas

Every JSON Schema in `contract/schemas/`, what it describes, its required top-level fields, the packages that use it, and whether an agent in the world reads its text. Also the generator that turns the schemas into code and the check that keeps the generated code current. Checked at 1b114276 on 2026-11-16.

Subjects that carry these messages are in [NATS subjects](nats-subjects.md). The MCP tools built from the `mcp-*` schemas are in [mcp-tools](mcp-tools.md).

Validators are generated for each titled schema, for each union member in a schema's `$defs` (a definition whose `type` property is a `const`), and for each tool `Input` and `Result` definition (`scripts/generator.ts`, the comment above `validatorExports`).

The tool list pairs `<Name>Input` and `<Name>Result` definitions across all schemas; the tool name is the snake case of `<Name>` (`ReadBook` to `read_book`). Schemas in `NOT_YET_EXPOSED` keep their validators but stay out of the tool list: `mcp-recall` and `mcp-reach` at 1b114276 (`scripts/generator.ts` line 108). The tool list at 1b114276 has 16 tools:

## Agent-read schemas

An agent in the world reads schema text through the MCP tool list and its results. Two sources say which schemas that covers:

| Source | Schemas | Evidence |
|---|---|---|
| The agent-text test names four schema files and scans every `description` and `const` string in them for marker words | `mcp-world`, `mcp-play`, `mcp-common`, `common` | `contract/test/agent-visible-text.test.ts` `AGENT_SCHEMAS` |
| The same test scans the generated tool list `mcpToolSchemas`, which bundles every tool pair and each definition it reaches | the four above, plus `mcp-see` and `mcp-view` (their tools `see` and `view` are in `MCP_TOOL_NAMES`) | `contract/test/agent-visible-text.test.ts` first case; `contract/src/generated/mcp-tools.ts` |

`mcp-recall` and `mcp-reach` define tools that are not in the list yet (`NOT_YET_EXPOSED`); their text becomes agent-read when they are lifted. Text in any of these files follows the [agents-never rule](../agents/documentation-style.md#agents-never-learn-they-are-watched): never link an operator document from them.

Other schemas shape data an agent may receive (for example `snapshot` and `book-reply`), but their `description` text is not sent to the agent.

## Schemas

Columns:

- **Required**: the top-level `required` list. For a union (`oneOf`) or a file of definitions, the definitions are named instead; their own required lists are in the file. Observation schemas are the exception (next paragraph).
- **Used by**: TypeScript and Java files outside `contract`, excluding tests and fakes, that name the schema's file name, its title, a `$defs` name of an untitled or union schema, a `*Input` or `*Result` definition of a titled schema, or `validate<Name>` for any of those. A file name in a comment counts. This is inferred by name: a generic definition name can match an unrelated identifier, and the cell says so where the command finds one. Re-derive with the command after the table.
- **Agent-read**: from the section above.

Observation schemas (`kino-control`, `lakitu-audit`, `lakitu-feed`, `turn-record-event`) are listed at spec level only, so their Required cells leave the field list out on purpose (plan decision D9 in [documentation style](../agents/documentation-style.md#agents-never-learn-they-are-watched)); the fields are in the files and the design in the [Glass and Kino reference](glass-and-kino.md) (`agents-never`) and decisions 0075, 0100 and 0185. `kino-client` and `kino-feed` are unions and name no fields here either.

```powershell
foreach ($f in Get-ChildItem contract/schemas/*.schema.json | Sort-Object Name) {
  $s = Get-Content $f -Raw | ConvertFrom-Json -AsHashtable
  $names = @($f.Name); if ($s.title) { $names += $s.title }
  $defs = @(); if ($s['$defs']) { $defs = @($s['$defs'].Keys) }
  if (-not $s.title -or $s.oneOf) { $names += $defs } else { $names += $defs | Where-Object { $_ -match '(Input|Result)$' } }
  $pats = $names | ForEach-Object { '-e'; $_; '-e'; "validate$_" }
  $hits = git grep -lwF @pats -- '*.ts' '*.java' ':!contract' ':!docs' | Where-Object { $_ -notmatch '\.test\.ts$|/test/|fakes|fixture' }
  "$($f.Name): $(($hits | ForEach-Object { $p = $_ -split '/'; if ($p[0] -in 'threshold','tools','plugin') { $p[0..1] -join '/' } else { $p[0] } } | Sort-Object -Unique) -join ', ')"
}
```

## Conflicts and open points

1. **Spec event list and the contract.** `event.schema.json` repeats the spec section 7 types and adds `intent`, `action`, `receipt`, `reflex_fired`, `wake`. The contract also defines payloads for `action_outcome`, `chunk_visited`, `day_night`, `decision`, `plan_result`, `roll`, `sheet_adopted`, `sovereign_call`, `turn_record`, which the `event.schema.json` description does not list. The `type` property is a free pattern (`^[a-z][a-z_]{0,47}$`), so the validator accepts them. Spec, envelope description and payload set differ; recorded, not resolved.
2. **`turn_record` storage.** The schema says the sink stores it in a `turn_records` table; at 1b114276 no eventsink code writes `turn_records` (`git grep -n turn_records -- eventsink` finds nothing), and the schema and `sql/0060_turn_records.sql` both say nothing may emit the event until GX-05b. Consistent today because nothing emits it.
3. **Agent-read set.** The test's `AGENT_SCHEMAS` names four files; `mcp-see` and `mcp-view` reach agents through the tool list and are covered only by the tool-list scan, not by the per-file scan. Not a contradiction; a scope note for the agent-visibility check planned in decision D7 of the [docs plan](../analysis/docs-library/plan.md).
