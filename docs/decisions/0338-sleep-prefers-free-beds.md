# 0338: sleep tries the free beds first, and a time-limit stop is a timeout

- Status: Decided (owner-side ruling via geldar-93, 2026-11-15; items 1 and 2 only)
- Date: 2026-11-15
- Cites: 0226 (the bed census and the tried-beds message), 0225 (the bed key for a generic refusal), 0190 (the sleep hard stop), 0215 and 0216 (plain facts on a failed sleep).
- Why: night 306 showed 98 of 147 sleeps failing in 70 minutes. Most failures were `blocked` with "the search time ran out" while 2 or 3 of the 7 to 9 beds in range were occupied, and the loop spent its 30 s budget walking to occupied beds before it reached a free one. The loop also reported a time-limit stop as `blocked`, which the MCP words as "the way was blocked", a claim the world did not make. Read-only diagnosis in the session scratchpad (diag-sleep-beds-306).
- What (1), bed order: the loop finds up to MAX_BEDS (8) beds, nearest first, as before. It then tries the beds that no half reports `occupied` first, nearest first, and the occupied beds last. A bed is occupied when either half says so. A bed whose `occupied` state cannot be read counts as free, as the census does. An occupied bed is still tried when the free ones refuse or the budget allows, so no bed is dropped. The order uses straight distance within each group; a path length per bed would cost a path search per bed inside the budget this change protects.
- What (2), the time-limit case: when the budget ends the search before the loop tries every bed, or the hard stop cuts a bed and ends the search, the sleep fails with reason `timeout` (the existing reason; batch 5 used it for path timeouts). The message reads `tried N of M nearby beds, K occupied; the time limit ended the search`, then the last bed's text and the census and position, as before. K counts the occupied beds among the M found. The text states counts and the fact of the time limit for the event row; the agent reads only the reason (see Outcome words). It gives no advice, names no watcher, and carries no raw Mineflayer text. The all-beds-tried case stays `blocked` ("tried N nearby beds, all occupied or blocked").
- Not in this record: an optional bed target on the `sleep` verb (item 3 of the diagnosis). That needs a contract and prompt change and is not decided here. No contract, MCP, prompt, threshold or world change. `docs/spec.md` is not touched.
- Outcome words: the message does not reach the agent. `outcomeDetailText` (contract/src/outcome-words.ts) drops any detail text that holds a coordinate triple (`DETAIL_COORDS`), and every sleep failure message ends `; ended at x, y, z`. So the agent reads only the reason phrase for `timeout`, "it took too long" (outcome-words.ts line 12). The tried, occupied and time-limit counts stay in the event row, for the operator. Carrying them to the agent needs an outcome-words change (geldar-3b's contract slot), which this record does not make.
- Tests: `sleep-order.test.ts` pins the order (a free bed nearer than an occupied one is tried first; an occupied bed is tried after the free ones refuse; a bed with only its foot or only its head occupied counts as occupied, whichever half is seen first; nearest first inside the free group and inside the occupied group; all beds free; no bed free) and the timeout text and reason; the existing sleep, census, detail and hard-stop tests move to the new reason and wording. Revert checks: the either-half merge fails the foot-only and head-only tests; the free-group and occupied-group reversals fail the nearest-first tests; the ungrouped order fails the occupied-after-free tests; the reason hunk (`blocked` for the time-limit stop) fails the timeout tests.
- Rollback: revert the commit. The change touches only `golem/src/actions/sleep*.ts` and their tests and this record; no state, contract or config changes.
