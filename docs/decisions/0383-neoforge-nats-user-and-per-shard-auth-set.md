# 0383. The NeoForge mod has its own NATS user, `neoforge`; the maintenance notice has its own deploy user; both sit in the NeoForge shard's auth set

- Status: Proposed (lead-accepted 2026-11-17; owner to confirm)
- Date: 2026-11-17
- Spec: section 7 (event bus and NATS auth); builds on 0067 (opt-in NATS users) and 0380 (per-shard NATS)

## Decision

1. The NeoForge mod connects to the NeoForge shard's NATS as a new user `neoforge`, not as `paper`. Its allow list is the Paper publisher's shape for its own shard only: publish `geldar.nf.>` events, subscribe to `geldar.nf.maintenance`, and the JetStream API. It has no other subject.
2. The maintenance notice publishes to the NeoForge shard's own NATS, as its own deploy user (a per-shard deploy user, named in the NeoForge table), never to the colo NATS.
3. Both users are defined in the same per-shard auth set, generated by `shard nats-auth nf` in `geldar.ps1`.
4. The colo table and the colo generated file are unchanged. The colo output of `geldar.ps1` does not change. The `paper` user stays for colo only.
5. The shard token is `nf`; the scratch token is `nf-scratch` with its own auth set.

## Why

Least privilege: a NeoForge mod should not hold the `paper` credential of the colo shard, and a notice to the NeoForge shard should not use a colo deploy identity. Keeping the colo output unchanged keeps the autonomous shard's auth file byte-identical, so a change there cannot restart or re-key colo.

## Consequences

- `geldar.ps1` `Get-NatsUsers` gains a NeoForge branch that emits `neoforge` and the notice's deploy user; the colo branch is not edited. The existing test that pins the colo generated file must stay green (packet a2).
- `deploy/colo-notice.sh` gains a target-shard argument so the notice can reach the NeoForge NATS (packet a6). Its colo default is unchanged.
- The NeoForge mod's default user is UNVERIFIED in the source (`ExportConfig.java` reads `GELDAR_NATS_USER` or a `nats.user` property); the default becomes `neoforge` in the packet that changes it.
- Body, Mind, MCP and Glass for NeoForge are not in this record.

Generator (PR 691 review): the per-shard NATS auth set is written by deploy/nats-auth-nf.ps1, dot-sourced from geldar.ps1 for `shard nats-auth nf`; the NeoForge mod publishes `geldar.nf.*` (its subjects are geldar.nf.<type>), not `geldar.nf.>`.
