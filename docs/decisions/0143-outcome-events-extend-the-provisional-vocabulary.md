# 0143. Per-action outcome events extend the provisional event vocabulary

- Status: Proposed (owner confirmation pending)
- Date: 2026-11-11
- Spec: 5.3.1, 5.3.2, 5.15.3; extends 0033 and 0069 (provisional vocabulary, `no_plan` is not a failure)
- Packets: C5-00, C5-02

## Decision (draft)

Add event types `action` (an action completed) and `action_failed` (it did not), each with an action id, the tool name, a closed `code` enum and, for an intent that failed, an optional `why` code. The human-readable sentence is built by code from fixed text keyed by the codes. No agent-supplied string and no model text enters it. The types are marked PROVISIONAL like the rest of the vocabulary. `no_plan` stays not a failure (0069).

## Orchestrator's recommended default and why

Accept. The Mind currently gets codes such as `blocked` with little cause; readable fixed text lets a local model act on the cause without any new information source. Fixed text keeps 0058 and 0068 intact. Reverse by dropping the two types; the old codes remain in results.

## Consequences

Contract change (generated code regenerated by C5-00); more events in the journal (one per action).
