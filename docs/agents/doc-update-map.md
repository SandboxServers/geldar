# Doc-update map

Which documents a change has to update. Read it before you open a PR, and when you review one.

A change that alters behaviour, an interface, configuration, file layout, a build step or a procedure includes the matching document update in the same PR. **Most of this map is advisory: reviewers enforce it** (decision [0363](../decisions/0363-doc-update-map-is-a-review-duty.md), Proposed). The [gates table](#gates-that-read-documents) lists the few documents a check does read. Write documents with the [style rules](documentation-style.md) and check them with [doc verification](doc-verification.md). To find every document about one component, use [components](../reference/components.md).

## How to read the table

- Every document under `docs/` (outside `decisions/` and `analysis/`) appears in at least one row. Checked on 2026-11-16 at 3f07a4be by a script that lists each of the 122 Markdown files there (`git ls-files docs`) and looks for a link to it in this page; the same check is in [doc verification](doc-verification.md#update-map-coverage).
- **Gate** says whether a check fails the PR when the document is not updated. `gated: <test>` names the test (see the [gates table](#gates-that-read-documents)); `advisory` means only review catches it.
- **(a-n)** marks an `agents-never` document. Never link it from a path an agent reads.
- Grouped by area. Within a row, the first documents named are the ones most often touched.

## Gates that read documents

Read from the sources at cd4499da and re-checked on 2026-11-16 at 3f07a4be: between those commits, outside `docs/`, only the `telemetry/` package, `pnpm-lock.yaml`, `pnpm-workspace.yaml` and `tools/repo-checks/src/release-dates.json` changed (`git diff --name-only cd4499da 3f07a4be`), so no gate source changed. These are the gates that read documents, not every gate; [repo-checks](../reference/repo-checks.md) lists every gate.

Two runners carry the gates: `pnpm check:repo` (`node tools/repo-checks/src/cli.ts`, the checks in `run-checks.ts`) and `pnpm test` (Vitest across the workspace). CI runs both (`.github/workflows/ci.yml`), and `./geldar.ps1 check` runs both locally.

### In `pnpm check:repo`

| Gate | Source | What it checks in documents |
|---|---|---|
| line-endings | `line-endings.ts`, `run-checks.ts` | Fails a tracked file committed with CRLF (from `git ls-files --eol`). `.gitattributes` exempts `*.bat` and `*.cmd`. |
| control-chars | `control-chars.ts`, `run-checks.ts` | Fails a raw control byte or a lone CR in a committed file, a working-tree edit or an untracked file. |
| file caps | `file-caps.ts` | Applies the 500 and 700 line caps to code and config extensions only. Markdown is not capped. |
| decision-index | `decision-index.ts` | Every `docs/decisions/NNNN-*.md` has a row in `docs/decisions/README.md` whose first cell links it; every such link points at an existing record; any other `.md` in that folder (except `README.md`) fails. |
| decision-rows | `decision-rows.ts` | The README rows go up in number and no number repeats. |
| ip-literals | `ip-literals.ts`, `ip-literal-allowlist.json` | Every scanned text file, `docs/` included: loopback, `0.0.0.0` and the RFC 5737 documentation ranges pass anywhere; a private-range address passes only in an allowlisted file; any other address fails (decision [0132](../decisions/0132-ipv4-literal-policy.md)). A line with a `version` key is skipped. |
| MCP token | `mcp-token.ts` | Fails any text file holding a string shaped like a sovereign player's MCP bearer token. |
