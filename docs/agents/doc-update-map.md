# Doc-update map

Which documents a change has to update. Read it before you open a PR, and when you review one.

A change that alters behaviour, an interface, configuration, file layout, a build step or a procedure includes the matching document update in the same PR. **Most of this map is not gated: reviewers enforce it.** The [gates table](#gates-that-read-documents) below lists the few documents a check does read. Write or update documents with the documentation-writer agent and the [style rules](documentation-style.md); check them with [doc verification](doc-verification.md). To find every document about one component, use [components](../reference/components.md).

## How to read the table

- **Update now** lists documents that exist on 2026-11-16: the W0 documents committed at 1b114276, and the W1 and W2 documents under `docs/concepts/`, `docs/architecture/` and `docs/reference/`, written in the working tree on top of 1b114276 (each path checked with `Test-Path` that day), and the W3 documents under `docs/operations/`, written on top of 03c1f5de (checked with `ls docs/operations`, 2026-11-16). Update them in the same PR. **Gated** means a test in `pnpm test` reads that document and fails the PR when it disagrees (see the [gates table](#gates-that-read-documents)). **(a-n)** marks an `agents-never` document.
- **Planned** lists documents the approved [docs-library plan](../analysis/docs-library/plan.md) schedules but has not written yet, with their wave (W3 to W5). The links do not resolve yet. Until a planned document exists, you have nothing to update there: note the debt in the PR. Once it exists, it moves to "Update now".

## Gates that read documents

Read from the sources at cd4499da on 2026-11-16. No file outside `docs/` changed between cd4499da and 1b114276 (`git diff --name-only cd4499da 1b114276`), and the [repo-checks](../reference/repo-checks.md) reference, read at 1b114276, agrees with this table (its conflict 6). These are the gates that read documents, not every gate. `pnpm check:repo` also runs checks that read no document: env-definitions, identity-mode, integration-floor, loopback-ports, pin-rules, release-age and workflow-yaml (the imports of `tools/repo-checks/src/run-checks.ts`); [repo-checks](../reference/repo-checks.md) lists every gate.

Two runners carry the gates: `pnpm check:repo` (`node tools/repo-checks/src/cli.ts`, the checks in `run-checks.ts`) and `pnpm test` (Vitest across the workspace). CI runs both (`.github/workflows/ci.yml`), and `./geldar.ps1 check` runs both locally.

### Not gated

No check reads document metadata, relative links, the section indexes, this map, or audience labels. The plan proposes a link checker, a metadata linter, an agent-visibility check and generated lists as coder packets after the freeze (plan decision D7). Until then, run the manual scans in [doc verification](doc-verification.md#mechanical-scans).

Index entries in [docs/README.md](../README.md) and each section `README.md` stay in sync with the documents they list: adding or renaming a document updates its index in the same PR.
