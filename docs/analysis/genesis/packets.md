# Genesis cards

Cards for the campaign in [README.md](README.md), built on [plan.md](plan.md). **Level of detail:** these are planning cards (goal, files to read or add, dependency, proof, who must be consulted). Before dispatch the coordinator turns each into a prescriptive packet (exact files, code shapes, revert-checks) against the then-current `main`; a card with a `(to confirm)` is not Ready. Numbers (ADR, SQL, prompt) are never taken here: `<allocate via registry>`. Branches are `phase1/gn-<id>-<slug>`, one worktree per card under `.claude/worktrees/`. Shared files with a single owner per wave: `compose/colo.yml` and `compose/*.yml` (G0-03, then G4), `.github/workflows/*` (G1-01, then G4-01, one owner at a time), `docs/decisions/README.md` (the session that merges last in a window resolves it).

**Common rules.** Pin everything exactly (images by digest, actions by commit SHA, versions at least two weeks old). No secrets, account names or addresses in the repo. Every behaviour change has a test that fails when it is reverted. Files: soft cap 500 lines, hard cap 700. Nothing in a card touches the live node; anything that would is marked **node** and needs geldar-93's window. Coder size: Haiku, about 40k working tokens; a larger card is split before dispatch.

Legend: **Dep** dependency; **Who** sessions to consult; **Size** S (about 20k), M (about 40k), L (split first).

## Wave G0: spikes and foundations

- **G0-01 Entra and DNS spike (read-only plus one test tenant action).** Dep none. Who owner (tenant admin), geldar-93. M. Settle: does `Application.ReadWrite.OwnedBy` cover redirect-URI and secret operations on an app the bootstrap app created; can `az ad app update --web-redirect-uris` and `az ad app credential reset --append` run under a federated GitHub identity; the exact Azure DNS role and command for an idempotent A-record upsert. **Prove** by a recorded run in a test tenant scope or a written result with the exact failing call; output is a worknote with commands and the minimum permission list (feeds G2-05, G2-06). No repo secrets.
- **G0-02 Hosted-runner capacity spike.** Dep none. Who geldar-ops. M. Boot Paper (small world, low memory, offline mode, the real `geldar-core` jar), Velocity, Postgres, NATS and the services on a GitHub-hosted runner in a throwaway workflow on a branch; measure memory, boot time and whether a scripted bot can join. **Prove** by timings and the logs; decide the shape of G6-04 (full or reduced). Result is a worknote; the throwaway workflow is deleted.
- **G0-03 Parameterise compose for several environments.** Dep G0-04. Who geldar-93, geldar-ops. L (split by file). Replace the literal ports, project name, network and subnet, volume names and host paths with values from the environment definition, keeping today's values as defaults so `colo` is unchanged byte for byte. The repo check `loopback-ports` rejects interpolated host sources: extend it to accept only `${GELDAR_PORT_<NAME>:-<literal default>}` in an allowlisted form, with its tests. **Prove**: `docker compose config` for the default environment equals the current output (golden file); a second environment name yields no overlapping ports, networks, volumes or container names; the repo-check tests pin the rule.
- **G0-04 Environment definition schema.** Dep none. Who geldar-93. M. Contract schema `environment.schema.json` (generated types), the file `envs/<name>.yaml` format, a validator CLI in `tools/`, and a repo check that every `envs/*.yaml` validates and contains no secret, account name or address (reuse the leak-scan rules). Contract regeneration is serial with other contract cards: allocate its place in the chain with the coordinator. **Prove**: valid and invalid fixtures; a definition holding an address or a key is refused.
- **G0-05 Hard-coded value sweep.** Dep G0-04. M. Replace the remaining fixed names in scripts and workflows (`/var/lib/geldar-colo`, `/mnt/nvme/geldar-colo`, runner label, sudo path, repo gate, image names, `SEED`, `GELDAR_SHARD` defaults) with definition values and defaults equal to today's. List what stays fixed on purpose. **Prove**: shell tests in `deploy/test/` run for two environment definitions; grep check that no new literal path appears.
- **G0-06 Decision record and numbers.** Dep none. S. Take ADR numbers through the registry for the genesis architecture (0188, Proposed) and any later spike results; keep the decisions README and this ledger current.

- **G1-04 Release manifest v2.** Dep G1-01, G1-03. S. Extend `release.env` (or add `release.json`) with plugin and bundle digests and the environment definition hash; keep the existing fields; `colo-cd.sh` ignores unknown keys. **Prove**: the manifest parser tests; the old manifest still parses.

## Wave G3: host bootstrap

- **G3-01 Bootstrap a clean Debian host.** Dep G0-05. Who geldar-93. L (split install, users and paths, docker daemon). An idempotent `deploy/genesis/bootstrap.sh`: packages (Docker Engine and Compose v2 from the pinned upstream repository, curl, jq, openssl, caddy if the edge runs here), the service and operator users and uids, the directory layout from the definition, Docker `daemon.json` address pools (so networks cannot run out), time sync, firewall rules for the environment's ports, sysctl needed by Paper, log rotation, unattended upgrades off for Docker. **Prove**: runs twice on a fresh Debian VM (G3-04) with identical end state; a shell test with a fake root.
- **G3-02 Forced-command deploy channel.** Dep G3-01. Who geldar-93. M. A wrapper at a fixed path that accepts `plan`, `apply`, `verify`, `restore` and a sha, validates the sha shape, runs as the operator account through sudo with a narrow sudoers entry, and an `authorized_keys` line with `command=`, `no-pty`, `no-port-forwarding`. **Prove**: tests that a shell request and an unknown verb are refused; the wrapper runs the same code path as the existing `colo-deploy` entry.
- **G3-03 Edge snippet and reload.** Dep G0-05, G2-06. M. Generate the Caddy site snippets for glass, map and mcp per environment from `deploy/caddy/*.caddy`, validate with `deploy/caddy/validate.sh`, and `caddy reload` (never restart). The gateway firewall and port forward are a checked prerequisite: the stamp tests the public endpoint and fails with a clear message. **Prove**: snippet golden files for two environments; the validator passes.
- **G3-04 Create the node 3 test VM.** Dep none (operator run); reuses scriptorium's F-01 `New-HostVm.ps1` and seed once it exists (do not write a second script). Who owner, scriptorium-orchestrator. M. A parameterised PowerShell run over SSH from the operator machine that creates a Hyper-V Generation 2 VM on node 3's `Internet` switch from Debian's **`generic`** cloud image (not `genericcloud`, which kernel-panicked on Hyper-V), converted to VHDX, with a cloud-init NoCloud seed ISO, the secure-boot template `MicrosoftUEFICertificateAuthority`, data disks from the definition, the deploy public key injected, and the host's SSH fingerprint printed. **Collision rules**: a distinct VM name (for example `Geldar-Test`, not `Geldar-Hosts`), distinct VHDX file names and mount points, and a **pinned** address (the ranger host uses DHCP). **Size small**: about 16 to 32 GB RAM and 8 vCPUs (node 3 has 512 GB and 32 threads and the ranger host already uses 128 GB and 28 vCPUs). It never runs in CI. **Prove**: a dry-run printout; a recorded run creating and destroying one VM.

## Wave G4: the stamp workflow

- **G4-01 `stamp.yml` skeleton.** Dep G0-04, G2-04, G3-02. Who geldar-93, geldar-ops. M. A reusable workflow plus a `workflow_dispatch` entry: inputs `environment`, `ref`, `mode`; `permissions` minimal; `environment:` declared; a concurrency group per environment with no cancel-in-progress; actions pinned by SHA; `azure/login` via OIDC; a job that calls the forced command. **Prove**: a `plan` run against the test VM that changes nothing. Single owner of `.github/workflows/`.
- **G4-02 Plan mode.** Dep G4-01, G1-04. M. The target compares the definition and manifest with what runs (image digests, compose config hash, plugin digests, secret names present, migration head, NATS user set, DNS records) and prints a names-only drift report; exit codes distinguish "no drift", "drift" and "error". **Prove**: fixtures for no drift, one image drift, a missing secret; a drift report of an unchanged environment is empty.
- **G4-03 Apply orchestration.** Dep G4-02, G2-01, G2-02, G2-03, G3-03, G1-03. L (split by phase). Implements the apply order in plan.md section 3 as ordered phases with health waits (`up --wait`, `depends_on` conditions, one-shot init for migrations), a pg dump before migrations, and per-phase resume. **Prove**: a stamp of the test VM from bootstrap to services up; a failed phase can be re-run.
- **G4-04 Seeds and first admin.** Dep G4-03. Who geldar-registration, owner. M. Seed the roster, owners and a scripted test player from operator inputs (GitHub Environment variables, never in the repo) using the existing admin verbs; first-admin bootstrap follows the registration runbook. Admin verbs run as non-disruptive one-shots: `--no-deps`, never recreating or detaching a running container (a hand-run verb once stopped Postgres and detached it from its network). **Prove**: seed twice, same state; a test player token is minted and revoked; a test asserts every container keeps its id and network attachments across the seed.
- **G4-05 Idempotency and no-op proof.** Dep G4-03. M. A test workflow that applies twice and asserts the second `plan` is empty and the second `apply` made no change (no container recreated, no secret rewritten, no migration run, no DNS write). **Prove**: the workflow on the test VM.

## Wave G6: verification

- **G6-01 Smoke suite.** Dep G4-03. Who geldar-ops. M. A script run by the `verify` mode: containers healthy at the expected image digests, schema at head, a NATS round trip, MCP and register health endpoints, Glass answers, no "fatal" lines for a set time, the disk precheck. **Prove**: passes on the test VM; each check has a failing fixture.
- **G6-02 Scripted test player.** Dep G4-04. Who geldar-ops, geldar-registration. M. A disposable scripted client joins through Velocity with a minted token, reads status and wait through MCP, performs one action and one say, and is revoked afterwards; it never calls a model. **Prove**: runs on the test VM and on the ephemeral stamp; its token is deleted.
- **G6-03 Health gate.** Dep G6-01. Who geldar-ops. S. The checks geldar-ops listed: all expected Body hosts running at the expected revision label, restart policy `on-failure:5`, RestartCount 0, zero "fatal" lines for 10 minutes, presence KV matching running hosts, a Body status and look round trip per host, and the MCP present-reflex-coverage test green. **Prove**: a failing case per check.
- **G6-04 Ephemeral CI stamp.** Dep G0-02, G4-03, G6-02. L. A workflow that stamps the `ephemeral` environment on a hosted runner (shape decided by G0-02), runs the smoke suite and the scripted player, and tears it down; runs on changes to the stamp surface and nightly. **Prove**: green on a branch and on a deliberately broken change.
- **G6-05 Real-ranger acceptance checklist.** Dep G7-02. S. A written checklist for the owner and scriptorium: point one ranger at the test environment, confirm the Body and Mind connect and act, record the result. It is a human step and never in CI.
