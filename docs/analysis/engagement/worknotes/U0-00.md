## How it was run

- **Who:** the orchestrator session (Claude Code, on the owner's desktop) on 2026-11-18, logged into the node as its ssh user through the `cimmeria-colo` alias.
- **Access:** `docker exec -i geldar-ch clickhouse-client --readonly=1 --multiquery`, which is ClickHouse's `default` account with session `readonly=1`. The setting was checked: `getSetting('readonly')` returned 1.
  - The owner approved this as a one-off on 2026-11-18. It is not a standing route; D-EN-03 is.
  - The `geldar_reader` password is a root-only file on the node, so it was not used.
  - Nothing was written on the node.
- **When the queries ran:** about 21:28Z to 21:50Z on 2026-11-18. This window comes from the newest span each query returned (21:28:16Z for the first query, 21:48:35Z for the last), so it is a lower bound on each run time. Use it to pick these queries out of `system.query_log`.
- **Source:** `signoz_traces.signoz_index_v3`, spans named `mcp.tool_call`, covering 2026-11-17 03:48:37Z to 2026-11-18 21:28:16Z (about 42 hours).
- **Scope:** MCP span arguments only. Shape counts came from `act`; phrase counts came over `act`, `journal` and `say`, and only counts are published. The events table and chat were not read.

## Capture

All 44,714 `mcp.tool_call` spans carry a `geldar.content.tool_arguments` event, so the arguments are captured. The span attributes are `gen_ai.tool.name`, `outcome` and `error.type`. No attribute names the agent: `service.instance.id` is the MCP instance. Every count below is therefore across all agents, and "agents sent" means at least one agent.

## Phrase counts: unmeasured

The planned count of hold, equip or wield text did not produce a usable number:
- The query matched case-insensitively over the whole argument JSON, field names included.
- The `equip`, `wield` and `armed` patterns used `\\b` word boundaries that did not survive the shell escaping, and returned 0.
- An "in hand" count came back at 1,112 for `act`, 708 for `journal` and 103 for `say`, but it has the same whole-JSON problem.

Treat this section as unmeasured. Those queries were not kept.

## What it means for U0

- At least one agent already sends the item-only shape that decision 0389 makes work: at least 29 weapon actions in about 42 hours, the first at 11-17 06:08:49Z. After U0-01 deploys, these should succeed with no change to what agents are told.
- The 178 item + at actions stay refused after U0-01, by design (0389 point 3).
- Hypothesis for U0-02: the item-only shape was refused "use needs a block position", so agents added `at`. The first item-only action came 19 seconds before the first item + at (06:08:49Z, then 06:09:08Z). If this holds, item + at keeps failing after the fix, and item-only use may rise once it starts succeeding.
- The item + entity actions include a sword "used" on Billy himself (11-18 04:16Z). One reading is showing Billy the sword. Entity use is out of U0's scope.

## Queries (kept)

```sql
-- the readonly check
SELECT getSetting('readonly');

-- capture
SELECT count(), countIf(arrayExists(e -> e LIKE '%tool_arguments%', events)), min(timestamp), max(timestamp)
FROM signoz_traces.signoz_index_v3 WHERE name = 'mcp.tool_call';

-- shapes
WITH JSONExtractString(JSONExtractRaw(arrayFirst(e -> e LIKE '%tool_arguments%', events), 'attributeMap'), 'geldar.content.tool_arguments') AS args
SELECT multiIf(JSONHas(a,'item') AND JSONHas(a,'at'),'item+at', JSONHas(a,'item') AND JSONHas(a,'entity'),'item+entity', JSONHas(a,'item'),'item alone', JSONHas(a,'at'),'at, no item', JSONHas(a,'entity'),'entity, no item','nothing') AS shape,
       match(JSONExtractString(a,'item'), '_(sword|axe)$') AS weapon, count() AS n
FROM signoz_traces.signoz_index_v3 ARRAY JOIN JSONExtractArrayRaw(args, 'actions') AS a
WHERE name='mcp.tool_call' AND attributes_string['gen_ai.tool.name']='act' AND JSONExtractString(a,'do')='use'
GROUP BY shape, weapon ORDER BY weapon DESC, n DESC;

-- by item and shape
WITH JSONExtractString(JSONExtractRaw(arrayFirst(e -> e LIKE '%tool_arguments%', events), 'attributeMap'), 'geldar.content.tool_arguments') AS args
SELECT JSONExtractString(a,'item') AS item, multiIf(JSONHas(a,'at'),'item+at', JSONHas(a,'entity'),'item+entity','item alone') AS shape,
       count() AS n, min(timestamp), max(timestamp)
FROM signoz_traces.signoz_index_v3 ARRAY JOIN JSONExtractArrayRaw(args,'actions') AS a
WHERE name='mcp.tool_call' AND attributes_string['gen_ai.tool.name']='act' AND JSONExtractString(a,'do')='use'
  AND match(JSONExtractString(a,'item'),'_(sword|axe)$')
GROUP BY item, shape ORDER BY n DESC;
```

The examples query used the same filter with `groupArray(3)` per shape, ordered by time.
