# W6-12 worknotes: the Adam run report generator

## What exists (part 1)

Package `tools/adam-report` (`@geldar/adam-report`, pg 8.23.1, yaml 2.9.1, @types/pg 8.23.1).

- `criteria.yaml`: the owner's readings from decision 0061. `max_gap_seconds` and
  `model_floor_verdict` are null, so their measures print "not computed: definition pending".
- `src/types.ts`: row shapes (thoughts, intents, actions, receipts, events), manifest, measure types.
- `src/snapshot.ts`: the `Snapshot` input (manifest, criteria, rows) and `toLiteSnapshot`, the mapper
  from `thoughts.snapshot` JSON. No database access below this file.
- `src/db.ts`: the read-only loader. One transaction per read (`BEGIN READ ONLY`, then `COMMIT`, or
  `ROLLBACK` on error). The client closes on every path. Connection from env: `POSTGRES_HOST`,
  `POSTGRES_PORT`, `POSTGRES_DB`, `GELDAR_REPORT_DB_USER` (default `geldar_glass`), and the password
  from `GELDAR_REPORT_DB_PASSWORD_FILE` or `GELDAR_REPORT_DB_PASSWORD`. The connection string is never printed.
- `src/survival.ts`, `src/intents.ts`, `src/calls.ts`, `src/continuity.ts`: the pure measures.
- `src/report.ts`, `src/render.ts`: the report (JSON and Markdown), with stable key and row order.
- `src/cli.ts`: `adam-report --life <id> --from <iso> --to <iso> --manifest <file> --out <dir>
  [--criteria <file>] [--format md|json|both]`. Exit 0 when written, 2 for usage (including an `--out`
  inside `.git`), 1 for a database or file error. `generated_at` is the only wall-clock field.
- `test/smoke.test.ts`: an empty snapshot gives UNKNOWN for every measure.
- `test/db.test.ts`: the loader's close, rollback and abort paths, with a fake client.

## Interface note: the `events` table

The report reads `events` (rows with `type` of `death` or `sleep`, selected by `agent_id` and the
window). The `geldar_glass` role needs `SELECT` on `events`. The W6-09 coder was asked to grant it.
Until that grant exists the loader fails with a permission error (exit 1).

## What part 2 must cover

Table-driven tests for each measure, with a revert-check per row:

1. Survival: `survivalMeasure` and `dayChecks`. Covers: death inside the window (FAIL), short coverage
   (UNKNOWN), missing bed, food (`ateOnDay`), stone pickaxe (`hasStonePickaxe`), no snapshot (UNKNOWN).
2. Intents completed without a model call: `intentsWithoutCall`, `intentMeasures`. Covers the tick
   range boundaries (inclusive), unmeasured intents, the chatter count and the minimum of 3.
3. Receipts: `receiptMeasure`. Covers one final receipt per terminal action, and prepared for economic actions.
4. Checkpoint resume: `resumedIntents`, `resumeMeasure`. Covers zero restarts (UNKNOWN) and a restart with no resume (FAIL).
5. Model floor: `modelFloor` echoes the owner's value; it never computes a verdict.
6. Calls per useful minute: `usefulMinutes`, `busyMinutes`, `callsMeasure`. Covers the minute boundary
   and the case of no useful minute (UNKNOWN). Its PASS means "recorded, no threshold in the spec".
7. Latency: `percentile` (nearest rank), `latencyMeasure`. Covers p95 under and over, and the hard limit.
8. Continuity: `longestGapSeconds`, `continuityMeasure`. Covers each of the duration, world-day, gap
   and restart conditions, and the pending gap threshold.
9. The IT case: a run against a real Postgres with the `events` grant, read-only enforced.

## Survival measure (part 2a, done)

- Day-boundary bed check: a day passes the bed half when a place action of any `*_bed` block has a
  committed receipt on that day or an earlier day of the window (`bedPlacementDays`). The sleep half
  is a `sleep` event that day. Both are required; a FAIL note names the missing half and the day
  (`day 3 (bed placed)`, `day 3 (slept in bed)`).
- The loader reads the place block: `ACTIONS_SQL` selects `kind` and `args->>'block'` for place
  actions; `ActionRow` gains `kind` and `placeBlock`. Covered by a fake-client test in `db.test.ts`.
- The thoughts' snapshots are mapped with `toLiteSnapshot`, as the loader does. The earlier tests
  passed the raw contract snapshot and failed on `inventory`, not on `events`.
- Revert-checks run (one line each, restored from a backup copy): the earlier-day rule, the
  committed-receipt rule, the any-colour bed rule, and the sleep rule. Each named test failed.
  The `place`-block SQL mapping in `db.ts` was not reverted (no check run).
