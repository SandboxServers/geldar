## Part 1: done

- Model pins. Ollama reports bare hex digests and the default `:latest` tag (`nomic-embed-text:latest`). The pins
  carry `sha256:<hex>` and bare tags. The digest is compared in full, in lower case, with the `sha256:` prefix removed
  on both sides; a prefix of the pinned digest is a mismatch. The tag is compared without `:latest`, for both the pins
  and the loaded models. The pin key path and the `/api/ps` JSON parse were already correct.
- Benchmark gate. The old `.geldar/runs/benchmark-gate.json` is no longer read. The gate is the newest
  `bench-results/*.json` by the timestamp in its name (`YYYYMMDDTHHmmssZ-<commit>.json`), not by mtime. The bench
  writer records no gate field, so the gate reads the file itself:
  - `meta.commit` is the 7-character short sha; it must equal the first 7 characters of HEAD.
  - `truncated` must be `false`.
  - Every 20 TPS summary row must have `successPct` 100. The 10 and 5 TPS rows are recorded in the manifest but not
    required (decision D-P0-17).
- Refusals name the file and the fix: no file, not JSON, not a bench result, truncated, a different commit (both short
  shas shown), no 20 TPS rows, and each 20 TPS cell below 100% (listed by scenario).
- The manifest records the bench file name, its commit and the 20 TPS rows (`bench` block).

Code: `tools/adam-run/src/bench-gate.ts` (pure), `adapters.ts` (lists `bench-results/`, reads the newest file).
