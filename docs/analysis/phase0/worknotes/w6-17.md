# W6-17 worknote: the tier select and the clean-tree check

Owner item O-1 in [adam-run-owner-decisions.md](../adam-run-owner-decisions.md) asked how `adam select` (which rewrites `shards/phase0.yaml`) can run before `adam-run start` (which refuses a dirty tree).

## The choice

Of the two options O-1 gave, the code takes the second, narrowed: the clean-tree check ignores the tier select's rewrite and nothing else. The first option (the orchestrator commits the tier at the run's HEAD) was not taken: it would make every run start from a commit the run did not choose, and it would move HEAD, which the benchmark gate checks against. The owner has not ruled on the choice; this is the implementation to review.

The classifier is `classifyShardEdit` in `tools/adam-run/src/shard-edit.ts`. It compares the working copy with the committed copy, key by key, and accepts a change only when:

- every changed key is one of `mind.run_tier`, `mind.agent.username`, `mind.agent.tier`;
- `mind.run_tier` names a life in `mind.lives`, `mind.agent.username` equals that life's id, and `mind.agent.tier` equals `mind.run_tier`.

Any other changed key, any comment or layout change (texts differ with no key changed), and any other dirty path refuse the start.

## The three keys (deviation to review)

The brief for this packet names three keys, and `select` writes all three, so the classifier accepts three. The original packet text is not in this worktree, so I could not check it against the spec's own list. If the packet named fewer keys, the third (`mind.agent.tier`) is the deviation, and it is the one that makes `run_tier` and the agent's tier agree before a start.

## Manifest record

`manifest.json` gains `shard_edit`: the changed keys with their `from` and `to` JSON values, and the shard file's sha256 before (committed) and after (working copy). It is `null` when the start ran on the committed file. `git.clean` is `false` for a run started on a select edit, so the manifest still shows that the tree was not clean.

## Revert checks

- The classifier's agent-tier check had no test. Reverting it passed all 176 tests. A test was added for a select whose `mind.agent.tier` was not rewritten; reverting the check now fails it.
- The manifest's `sha256_before` mapping was reverted to `sha256_after`; the manifest test fails.
