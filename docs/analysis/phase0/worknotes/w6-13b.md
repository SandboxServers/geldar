# W6-13 part b: glass and adam-run wrappers

## Usage

    ./geldar.ps1 glass up|down|status|logs
    ./geldar.ps1 adam-run <32b|8b|smoke> start|status|stop|report [args]

- `glass` runs tools/glass-ctl: one detached Glass server on 127.0.0.1 (default port 8787), with a format-2 PID file
  under `.geldar/` (git-ignored). `status` prints the process state and one probe line
  (`GET /api/thoughts?limit=1` on loopback). `logs` prints the last lines of the Glass log.
- `adam-run` passes its arguments to tools/adam-run/src/cli.ts.

## Preconditions

- `./geldar.ps1 setup` has run (the glass-ctl workspace package has no dependencies, so the lockfile is unchanged).
- The password file `compose/secrets/postgres-glass.txt` exists and holds the geldar_glass password (glass/README.md).
  `glass up` refuses without it and says so.
- `GELDAR_GLASS_HOST` must be unset or `127.0.0.1`; any other value is refused before anything starts.

## What ops verifies live

1. `./geldar.ps1 glass up`, then open http://127.0.0.1:8787/ (or the port in `GELDAR_GLASS_PORT`).
2. The thought stream shows rows.
3. `./geldar.ps1 glass down` leaves no Glass process running and removes the PID file.

These steps are not run by this packet.

## Deviations and design notes

- glass-ctl never opens the password file. It sets `GELDAR_GLASS_PG_PASSWORD_FILE` to the file path in the child
  environment, and Glass reads the file itself. The password canary test in tools/glass-ctl checks that the password
  never reaches output, the PID file, the log, or a spawn argument.
- Glass has no `/health` route, so the status probe is `GET /api/thoughts?limit=1` on 127.0.0.1.
- The env-leak guard for these functions lives in tools/glass-ctl (`geldar-ps1.test.ts`), not in
  adam-cli/src/env.test.ts, which does not parse geldar.ps1. The guard checks that the Glass and adam-run functions sit
  between the Wave M functions and the dispatch, and that every `$env:NAME =` they make is restored in a `finally`.
- An unverifiable PID file (live process whose start time or command line cannot be read) is kept, and nothing is
  signalled or started over it. This holds for both `up` and `down`.
