Verdict: fix (17 findings). Reviewer: packet-reviewer, read-only. Orchestrator decision D1: switch the sink to `@nats-io/transport-node` and `@nats-io/jetstream` (see overnight-decisions row 18).

1. HIGH `eventsink/src/consumer.ts:76-81`, `writer.ts:25-37`: a permanent DB error (NUL in jsonb 22P05, `world_day` overflow of INT, `world_tick` 1e21 rendered "1e+21", `at` year 0000) naks the whole batch forever; no `max_deliver`. Fix: on pg error class 22/23 retry row by row, send the bad row to the DLQ with the error text and ack; nak only for connection/timeout errors; set `max_deliver` (about 20) as a backstop; test with a fake writer that throws 22xxx for one event.

4. MEDIUM `main.ts:9`, `consumer.ts:155-169`: no `pool.on('error')`, no connection/query timeouts; a lost stream/consumer is never re-created. Add the handler and timeouts; after N consecutive fetch failures re-ensure stream and consumer, or exit(1) so compose restarts.
5. MEDIUM `NatsEventPublisher.java:121-128`: a failed publish drops the event. Requeue at the head (`offerFirst`, no drop count); `Nats-Msg-Id` makes the retry idempotent.
6. MEDIUM `NatsEventPublisher.java:50-64`: `dropped()/published()/failed()/connected()` have no callers. Log drop count changes (rate limited) and add `dropped` and `connected` to the `server_tps` payload.
