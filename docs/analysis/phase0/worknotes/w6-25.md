# W6-25: adam-run ops fixes (secrets, report, up line, stop)

Base: `e3a0b0a` (wave6-main). Branch `phase0/w6-25`.

## Cause and evidence (from ops)

A live Adam run was prepared with the run worktree, not the checkout that holds the secrets. Four faults showed up:

1. **Missing secrets junction, no stderr kept.** The run worktree had no `compose/secrets` junction. `adam up` exited 1 and the harness recorded only the exit code. The stderr that said which secret file was missing was lost, so ops could not tell the cause from the run record.
2. **Report needed the glass password.** `adam-run <profile> report` could not read the glass reader's password. The reporter takes it from the environment, and the env had no password file path and no DB address.
3. **`adam up` printed the wrong life.** The last line said `up: life <lives.fast>` whatever the Mind had selected. With the strong tier selected, the line named the 8B life.
4. **`stop` without `--run-id` missed the live run.** `status` and `report` took the profile's newest run folder, but `stop` used the id the current time gives, so it found no run.

## Done

- **A (report env), commit `3f9ddf4`.** The report step gets the glass reader's password file path (`GELDAR_GLASS_PG_PASSWORD_FILE`, default `compose/secrets/postgres-glass.txt`) and the DB address (`reportEnv` in `tools/adam-run/src/adapters.ts`).
- **B (stderr tail), commit `6845289`.** A supervisor failure carries the last 20 stderr lines of the failed child, redacted, in the abort reason. A failed `adam up` now says why.
- **C (secrets preconditions), commit `212358f`.** A start checks that `compose/secrets/postgres.txt`, `rcon.txt`, `velocity-forwarding.txt` and the glass password file exist and are readable, and refuses with each missing path listed. Only access is checked; no file is opened for its contents. Test: `preconditions.test.ts`, "refuses, listing each missing secret file by path". Revert-check: the loop over `f.secretsMissing` replaced by an empty list; that test fails (1 failed, 32 passed). Restored; diff empty. The same commit fixes a `exactOptionalPropertyTypes` error in `adapters.test.ts` that came in with `3f9ddf4` (the runner's `env` type).
- **D (up line), commit `779a97a`.** `adam up` ends with `up: life <username>`, where the username is the one the shard file selects now. The line is built by `upLine` in `tools/adam-cli/src/cli.ts`. Tests: `cli.test.ts`, "names the username the shard selects, not the fast entry of mind.lives" and "names the fast life after adam select points the Mind at it". Revert-check: `upLine` reads `mind.lives.fast`; the first test fails. Restored; diff is the intended change only.
- **Stop resolution, commit `fc2e430`.** `stop` takes the profile's newest run folder when no `--run-id` is given, as `status` and `report` do (`readsRun` in `tools/adam-run/src/cli.ts`). A `stop` with no run folder for the profile now returns 1 with "no <profile> run" and writes no safe-stop run. Test: `cli.test.ts`, "stop with no --run-id asks the newest folder of the profile to stop". Revert-check: `stop` removed from `readsRun`; that test fails. Restored.

## Ops checklist changes

`docs/analysis/phase0/adam-run-ops-checklist.md` now says that the `compose/secrets` junction must exist in the run worktree for the whole run, not only at start, and that `report` needs `compose/secrets/postgres-glass.txt`. Ops checks that the files exist and never opens them.

## Not done
