## Area A (plugins, compose, security)
- A1 (J) MEDIUM: the identity gate fails open when the plugin does not load; the velocity healthcheck is a bare TCP connect and `Assert-PluginJar` only checks the file exists. Fix: healthcheck requires the "Geldar identity enabled" line in the Velocity log, or `shard up` checks the log after `--wait` and fails.
- A2 (J) MEDIUM: if `GeldarCore.onEnable` throws (bad shard, NATS constructor), Paper stays healthy with no command block and no export. Fix: shut the server down on enable failure, or add a Paper healthcheck on the "Geldar-Core enabled" line.
- A3 (J) MEDIUM: the registry cache is never reset; a wiped or recreated bucket leaves old keys admitted and a dead watch is invisible. Fix: on each (re)watch build into a fresh map and swap at end of data; treat a watch error or lost consumer as unsynced (fail closed); narrow the threat-model claim about revocation during an outage.
- A4 (J) MEDIUM: a duplicate login by a registered name releases the live session's admission (the DisconnectEvent of the conflicting login releases the shared UUID). Fix: ignore the disconnect when the login status is CONFLICTING_LOGIN or cancelled, or key by Player identity; add a test.
- A5 (J) MEDIUM: names are canonicalised loosely (Kelvin sign maps to `k`; no check of `[A-Za-z0-9_]{1,16}`; non-canonical keys collide). Fix: `admits()` rejects names not matching `^[A-Za-z0-9_]{1,16}$`; ignore bucket keys that are not canonical lowercase; tests for Kelvin sign, dotted capital I and mixed-case key collisions.
- A6 (J) MEDIUM: the publisher does not self-heal after a mid-session stream loss (connection stays up, every send fails, queue stalls, `connected` still true). Fix: after N consecutive failures leave drain so the loop re-runs `ensureStream`, and set connected false.
- A7 (J) MEDIUM: missing test layers: `RegistryClient.Watcher` DELETE/PURGE branch (extract a testable seam taking an entry), `IdentityPlugin.onDisconnect`, the requeue call site and `flushOnClose` in `NatsEventPublisher` (extract a `send` seam), `Assert-PluginJar` missing and directory cases (a Pester-free script test, or a documented manual check recorded in the report).
- A8 (orchestrator) not proven live: revocation (delete a key, log in again), mid-run NATS outage, malformed entry, `geldar:cmd` drop for a non-admitted source, Paper whitelist as the second layer, command typed by the bot is cancelled, `death` events in Postgres, dedup path, `shard up` with a missing or directory jar, the gate failing to load (A1). Plus L3 (craft with no `recipe give`) and B11 (`GELDAR_IT=1`).
- A9 (J) LOW: backoff capped at 30 s so a first denial can last that long; log "bucket absent" apart from a connection error (this is L4). Cap at about 5 s.
- A10 (J) LOW: `.github/workflows/mcp-mock-image.yml:86-100` pushes a rebuild from cache, not the tested image. Push the loaded, tested image, or build once and push that output.
- A11 (J) LOW: command-log sanitising should drop all Unicode control/format characters (U+2028, U+0085, bidi); denial logs flood at INFO (rate limit or log denies at a lower rate); document in the README that every player's commands are cancelled (Phase 0 has no humans; owner debugging in game needs an RCON/console path).
- A12 (J) LOW: `exclusiveContent` for the Paper repository; stale "(not verified without Docker)" comment at `compose/phase0.yml:113`; blank line before `secrets:`; threat-model ingress row should say the host loopback can also write the registry; note that registry values and key count are unbounded.

## Area B (sink, Golem, docs)
- B1 (T) MEDIUM-HIGH: `max_deliver: 20` also counts transient DB failures; after about 7.5 minutes of Postgres downtime JetStream stops redelivering and the sink never DLQs or logs those events (live finding L1 hit this path). Fix: when `deliveryCount >= MAX_DELIVER` on a transient failure, dead-letter instead of nak (or set `max_deliver` -1 and keep the row-by-row poison guard); unit test with `deliveryCount: MAX_DELIVER`; README says what max_deliver does.
- B2 (T) MEDIUM: with `GELDAR_NATS_URL` unset, the bench or a live test is denied at the proxy with "This connection is not admitted.", which the connection manager treats as a normal disconnect: it retries forever, silently (bench logger is a no-op); the live lane dies at its 180 s timeout. Decision (orchestrator): the manager treats a kick whose reason is "This connection is not admitted." as FATAL with a clear message naming `GELDAR_NATS_URL`; the bench CLI and the live fixture default `GELDAR_NATS_URL` to `nats://127.0.0.1:4222` when unset and a loopback check passes.
- B3 (T) MEDIUM: `lifeIdFor` is lossy and can collide (`Steve_1`/`Steve1`, long shared prefixes) and mangles a username that already is a LifeId (`ag_kestrel_01`), so registry life ids and plugin `agent_id` disagree. Fix: a username that already matches the LifeId pattern is used unchanged; otherwise a deterministic suffix from a short hash of the exact username; test that distinct inputs give distinct ids. Also fix L2 (the live registry test expectation).
- B4 (T) MEDIUM-LOW: `unregister` silently does nothing when `opened` is null; a stop during an outage or a stop racing a register leaves the key behind (no TTL); `fail()` can override `stopped`; overlapping `register` can open two connections. Fix: reopen in `unregister` and log failures; set `registered` before the put; `fail()` must not override `stopped`; single-flight `open`; manager test with a failing put then `stop()`. Consider a bucket TTL with refresh as a decision note in the report (do not build it).
- B5 (T) MEDIUM: no tests for `startConsumer` re-ensure after 5 failed fetches, `onFatal` after 20, `ensureStream`, `ensureConsumer`. Fake `NatsConnection` and consumer tests.
- B6 (J) LOW-MEDIUM: `.github/dependabot.yml` needs a security-only gradle entry for `/plugin` and a docker entry for `/eventsink` (decision 0005).
- B7 (T) LOW: `.claude/skills/run-shard/SKILL.md` identity row has unescaped `|` in the table cell.
- B8 (J) LOW: `docs/threat-model.md:59` should say the host loopback (`127.0.0.1:4222`) can also write the registry.
- B9 (orchestrator) LOW: stale ledger rows, RESUME, `work-packets.md` nats version line, `retro/wave-2.md` wording at README:69. (T) fixes the READMEs: `golem/README.md` unreachable-NATS wording (first connect vs later), `eventsink/README.md` test commands and the duplicated DLQ body description.
