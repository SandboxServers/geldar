# W6-09: Glass server worknote

Packet W6-09 (`glass/` server, loopback, read-only, the `geldar_glass` role). Branch `phase0/w6-09`.

## What exists

- `glass/` (`@geldar/glass`): a `node:http` server bound to `127.0.0.1` only, with routes
  `/api/agents`, `/api/thoughts`, `/api/thoughts/:id`, `/api/receipts` and `/api/stream` (SSE).
  Every route is GET; other methods get 405. Headers on every response include the CSP, `nosniff`
  and `Referrer-Policy: no-referrer`. There is no CORS.
- `sql/0005_glass_reader.sql`: creates `geldar_glass` as NOLOGIN with the grants below.
- `tools/migrate`: `--set-role-password` accepts `geldar_glass` (in addition to `geldar_mcp`).
- `sql/test/check-schema.sql`: asserts the role's grants (see below).
- Tests: six unit files in `glass/src` (the route table, loopback refusal, the 405 and header
  behaviour, the SQL allowlist, SSE client caps, abort and close paths), and the gated IT case
  `glass/test/glass.it.test.ts`.
- `glass/README.md`: what Glass is, the routes, the configuration, the role setup and the threat
  model.

## Deviations from the card

1. **SSE polls Postgres, not NATS.** The card describes an ephemeral NATS consumer. Phase 0 has
   no NATS consumer for Glass: the stream starts from `now()` and polls the `thoughts` table every
   `GELDAR_GLASS_SSE_POLL_MS` (default 1000 ms). Glass holds no NATS credentials and has no publish
   permission. The NATS read-only consumer is a Phase 1 item (see W6-03).
2. **`agents` grant is by column, not by table.** The card says `SELECT` on the table `agents`.
   A table grant includes `personality_seed`, which Glass must not read. The grant names the nine
   columns Glass shows (`agent_id`, `name`, `life_seq`, `shard`, `mode`, `tier`, `born_day`,
   `died_at`, `death_cause`). This is the same narrowing migration 0003 made for the MCP.
   `check-schema.sql` asserts no table-level `SELECT` on `agents` and the exact column set.
3. **`events` is granted by column.** `events.payload` holds raw world text, so the role gets
   `SELECT` on six columns only: `type`, `agent_id`, `world_day`, `world_tick`, `at`,
   `source_event_id`. The report generator (W6-12) reads the same role; if it needs `payload`, it
   files an interface request and the orchestrator decides.
4. **The IT case copies its scratch-database helper** instead of importing
   `threshold/mcp/test/it/scratch-db.ts`, so `glass/` does not depend on another package's test
   code. It still imports `tools/migrate/src/migrate.ts` and `scram.ts` (the migrate tool's own
   exports), as the threshold cases do.
5. **The IT case has not been run here.** It needs the dev Postgres and `compose/secrets/`. The
   local checks cover the typecheck and the skipped case; the SQL is reviewed by reading, not run.

## What ops must run

Run these from the repository root against the dev stack (the secret files are the operator's):

```powershell
# 1. Apply every migration, including 0005 (creates the NOLOGIN role and its grants).
./geldar.ps1 db migrate

# 2. Create compose/secrets/postgres-glass.txt with a fresh password on one line (gitignored),
#    then give the role its login. The password is never printed.
./geldar.ps1 db migrate --set-role-password geldar_glass --password-file compose/secrets/postgres-glass.txt

# 3. The integration cases: Glass, and the schema check that runs sql/test/check-schema.sql.
$env:GELDAR_IT = '1'
./geldar.ps1 pnpm exec vitest run glass/test/glass.it.test.ts threshold/mcp/test/it/schema-check.it.test.ts
Remove-Item Env:GELDAR_IT
```

Set `POSTGRES_HOST` and `POSTGRES_PORT` first if the dev Postgres is not on `127.0.0.1:5432`.
The Glass server itself starts with `./geldar.ps1 pnpm --filter @geldar/glass start`, with the
`GELDAR_GLASS_*` variables from `glass/README.md`. `./geldar.ps1 glass up` arrives with W6-13.
