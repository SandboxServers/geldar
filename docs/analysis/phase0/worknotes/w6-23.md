# W6-23: adam-report reads the adam-run manifest

Branch `phase0/w6-23`.

## Cause

`adam-report` read the W6-13 manifest shape, but `adam-run` writes `adam-run-manifest/1`, so
reports on a real run read the wrong fields or failed. No test put the two sides together.

## Fix

- The reader follows the writer. `tools/adam-report/src/config.ts` takes its field names and
  schema from `tools/adam-run/src/manifest.ts` (`MANIFEST_SCHEMA = 'adam-run-manifest/1'`).
- The old shape is refused, with a message that names the expected schema:
  `manifest: schema must be adam-run-manifest/1`. Test: `config.test.ts`
  ("refuses the W6-13 shape, which no adam-run writes").
- `tools/adam-report/test/fixtures/adam-run-manifest.json` is a real manifest from the W6-20
  smoke run, sanitised: no account names, hosts, addresses or tokens. Its run id and life id are
  the smoke fixtures.
- Round trip: `tools/adam-run/src/report-roundtrip.test.ts` has `adam-run` write a manifest and
  `adam-report` read it back, so a field rename on either side fails in one place.

## Tests and revert checks

- Round trip (commit `11922ec`). Renamed `started_at` to `started_att` in
  `tools/adam-run/src/manifest.ts`: the round-trip test failed (1 of 2). Restored from a scratchpad
  backup; `git diff --stat` was empty.
- Abort before start (commit `a8a3f7a`). `cli.test.ts` already asserted the status path, but
  its only UNKNOWN check was `tpsMin`, and the report path reused the status output. The new test
  `report on its own prints the reason and every criterion UNKNOWN` covers report alone. Changed
  the criteria line in `tools/adam-run/src/cli.ts` to lowercase `unknown`: two tests failed (the
  new one and the existing status test). Restored; the tree matched the commit.
