# W6-13 worknotes: the adam-run protocol (harness core and CLI)

Status: the run sequence, the safe stop, ports and fakes (a2) and the CLI and the real adapters (a3) are written.
The live lane is not run here. The adapters are verified by the ops steps listed below, not by unit tests.

## Usage

```
node tools/adam-run/src/cli.ts <32b|8b|smoke> <start|status|stop|report> [--run-id <id>] [--hours <n>]
  [--restart-at-hours <n>] [--body-kill-after-minutes <n>] [--dry-run]
```

- `start` runs the sequence in the foreground. `--dry-run` (start only) checks the preconditions, prints the plan
  and starts nothing: no supervisor call.
- `status` reads the run folder. `stop` writes `stop-request.json` for a live run, or runs the safe stop when no
  live run owns the folder. `report` runs the W6-12 report step on the folder.
- `--restart-at-hours` must be positive and before the end of the run. `--body-kill-after-minutes` sets the minute of
  the mid-intent Body restart.
- The `./geldar.ps1 adam-run ...` wrapper arrives with W6-13b. Until then, run the script with `node` directly.

## Preconditions

`checkPreconditions(facts)` returns every missing item with what to do. A refused run writes and starts nothing.

- The benchmark gate (`benchmark-gate.json`, OPS-0) is present and passed.
- The git tree is clean.
- The model pins match `shards/phase0.yaml`.
- The life id for the profile is free (`32b` ag_adam_01, `8b` ag_adam_02, `smoke` ag_smoke_01).
- For 8B, the fresh-volume marker is present.
- Loaded models are limited to the profile model and the embedding model.

## Run folder layout

`.geldar/runs/<run-id>/` (ignored by git):

- `manifest.json`: the profile, life id, pins, seed, planned restart and TPS target. No secrets.
- `status.jsonl`: one JSON line per simulated minute, plus harness lines (`restart_stack`, `body_kill`, `abort`,
  `safe_stop`, `report_failed`, `end`).
- `run.pid.json`: the PID, start time and run id of the process that owns the run, for `status` and `stop`.
- `stop-request.json`: written by `stop`; the sequence checks it each minute and ends through the safe stop.
- `abort.json`: written once by the safe stop with the rule (or reason) and the result. A second call changes nothing.
- `run-report.json` and `run-report.md`: written by the W6-12 report step.

## Adapters ops must verify live

The unit tests use fakes. Before the first live run, check each adapter against the real stack:

- Clock: wall time advances one minute per sample; the minute index matches `status.jsonl`.
- FileStore: files land under `.geldar/runs/<run-id>/` with forward-slash paths on Windows; `status.jsonl` is append-only.
- Processes: `list` finds the Body, Animus and lantern-local PIDs; ownership is `owned` for our own and `other` for a
  reused PID (start time and command line are compared).
- Supervisor: `adam up` starts; `adam down` runs once per service on stop (order lantern-local, animus, body);
  `restartStack` restarts only the Paper, Velocity and eventsink services with `docker compose restart`, never
  dropping the data volumes; `restartBody` runs `adam-cli restart-body` (see below).
- Sampler: the Mind's Postgres counts, the status probes, `ollama ps`, `nvidia-smi` and disk. TPS and
  `errorsSinceLast` are not sourced (see deviations).
- Reporter: the W6-12 step reads one life in a read-only transaction and writes the two report files.
- Runner: every command is an argument array through execFile; no shell string.

## Body restart mechanism

Nothing restarts a killed Body process by itself. `adam-cli restart-body` (`tools/adam-cli/src/body-restart.ts`):

1. Reads the Body's owner record beside its PID file and checks it: the PID is alive, the start time matches the
   record, and the command line has the Body entry point. Any mismatch refuses the restart and signals nothing.
2. Signals only the Body: SIGTERM, then SIGKILL after the grace period.
3. Respawns it through `startService`, the same spawn path `adam up` uses.
4. Waits for `body_started` in the new Body's log. A fresh Body that exits first, or never logs it, is an error.

The sequence calls `restartBody` once at an active intent. A refused or failed restart throws, and the run aborts.

## Deviations from the card

- Stop order is lantern-local, animus, body (the reverse of the start order in `tools/adam-cli/src/procs.ts`).
- The Reporter is a separate port, not a call inside the sequence, so the report step can be replaced in tests.
- `startBody` is removed. The Body restarts with the stack or through `restartBody`; the sequence never starts it alone.
- TPS and `errorsSinceLast` are not sourced yet. The abort rules that need them skip when the value is unknown, so
  the TPS floor (`tpsMin` in `abort-criteria.json`) is not enforced in this version.
- `stop` calls `adam down` per service rather than one stack-wide `down`, so that the no-orphan check sees each one.
- The sequence has a `stopRequested` hook, checked each minute; the CLI wires it to the `stop-request.json` file.
- Two abort rules are not on the card: `body_not_recovered` (the Body does not reconnect after the restart) and
  `error` (an `adam up`, restart, sampler or restart call fails). Both abort through the same safe stop and report path.
- Path normalisation: run paths and the manifest path use `path.posix` in one place, so the Windows and Linux
  runs compare the same keys.
- The start flag is `--restart-at-hours`, not an ISO time; the earlier `--restart-at <ISO>` is gone.
