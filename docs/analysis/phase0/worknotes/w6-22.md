# W6-22: tests independent of select-rewritten shard keys

## Problem

`select` rewrites the tracked file `shards/phase0.yaml`. Inside a run tree
(a checkout where the shard was selected or rewritten), `check` failed,
because several tests read the committed shard keys and expected them to
stay fixed. A run tree is not a clean checkout, so those expectations
broke.

## Reproduction

With the select rewrite applied to `shards/phase0.yaml`, `check` showed
14 failures in six test files. Each file asserted on the literal shard
keys from the committed file.

## Fix

- `animus/src/phase0-shard.fixture.ts` (new): a shared fixture that builds
  the shard keys the tests need, so they no longer read `shards/phase0.yaml`.
- Four animus tests (`config.test.ts`, `main.test.ts`, `mind-e2e.test.ts`,
  `mind.test.ts`) and `golem/src/mind-link/senses.test.ts` and
  `tools/adam-cli/src/cli.test.ts` now use the fixture.
- One test still reads the committed shape of `shards/phase0.yaml`, so the
  committed file is still validated.
- `tools/repo-checks/src/shard-selects.test.ts` (new): a guard test that
  fails if a test reads the shard keys that `select` rewrites.

## Verification

- Four revert-checks: each fix was reverted in turn and the test it
  guards failed without its fix.
- Full `check` passed with the smoke edit applied: 3750 tests.
