# Wave 4 review, round 2 (area A verdict fix, 6 substantive findings; area B verdict fix, 10)

Round 1 items A1 to A17 and B1 to B16 verified fixed except as noted; the fixes introduced the findings below. Owners: P = Body behaviour coder (reflexes, view, runtime, executor, programs, craft), Q = records/restart/docs coder.

## Area A (owner P)
- F1 HIGH: `view.ts:120` `attacking` uses `(-sin(yaw)*dx + cos(yaw)*dz)`; mineflayer's forward vector is `(-sin y, -cos y)`, so the z term has the wrong sign: a zombie due south facing north at the Body reads as not attacking, one facing away reads as attacking; x-axis mobs are right, which is why tests and the live pass passed. Fix: `-sin(yaw)*dx - cos(yaw)*dz`; `view.test.ts` cases for the mob north and south, facing and facing away.
- F2 MEDIUM: the orphan dig-out (A7, `panic-burrow.ts:172-188` `planBreakout`) takes the first of E,W,S,N with diggable cells and a solid floor, which mostly picks natural rock, leaves the Body in a 1x2x2 hole (the old cell is open so `enclosed` is false), and never checks the cells beyond for fluids. Fix: prefer the side where the cell two steps out at feet level is open; refuse a cell with a fluid neighbour; test with an outside beyond one specific side (the current test is a solid stone box).
- F3 MEDIUM: `planBurrow`'s `isDiggable` accepts any solid block but `digCell` refuses names outside `DIGGABLE_BLOCKS`; in a sandstone, terracotta, planks or ore wall the plan succeeds, the reflex cancels the intent's action, then the dig refuses; every 200 ticks all night. Fix: `planBurrow` applies `DIGGABLE_BLOCKS` to the pocket cells; assert `cancels === 0` in that test.
- F4 MEDIUM: the action slot clears when the run result settles, not when the handler ends: `cancelAction` finds `current` null after the step's action has ended, so the first immediate action can start while the old handler's late `pathfinder.stop()` or window close still runs; a second `cancelAction` during the grace returns at once; `timeScale` is unvalidated (0, NaN, Infinity). Fix: keep a `winding` promise (handlerEnded raced with the grace) on the runtime; `cancelAction` and `runAction` await it; sanitise `timeScale` like `registry.ts`; fake-timer tests for the grace expiry and the double cancel.
- F5 MEDIUM: `submit` checks `reflexRunner.idle()` once before `pauseForActions`; reflexes run `runAction(ctx.registry, ...)` directly (not in `runtime.current`), so a reflex that starts between plan actions drives the bot concurrently with `runOne`; `idle()` has no timeout. Fix: await `idle()` before each `runOne`, bounded by a scaled timeout with a warn log; or route reflex actions through the runtime slot.
- F6 decision (orchestrator): a blocked walk can spin until `max_world_ticks`: `stopOf` keeps returning `running` while a report is live, the hook re-reports every blocked `goto` (refreshing the TTL), and the reflex's abandon does not end the intent; the hook also reports blocked `goto`s that are immediate plan actions. Decision: once the reflex has abandoned a report for an intent, the program fails (`blocked`) with a wake to the Mind on its next step (a per-intent `abandoned` flag in the checkpoint); and the hook reports only gotos run by the program (`ownActions`).
- Lows: `attacking` reach 3.5 blocks drops skeleton triggers at 3.8 to 4 (use 4); `dig-cell.ts` swallows errors with no log and treats an unloaded cell as open (log the cause into the outcome detail; unloaded means refuse); `craft-table.ts` is 518 lines (split) and with `want` a full inventory gives zero gain every time (exit early after two zero-gain crafts with a clear inventory-full style failure); stray literal backslash-n in a comment in `craft-table.yield.test.ts:17`; time-scale tests only for fight-or-flee (add one each for retreat, hazard-escape, eat, burrow); the `swimUp` and `walkOutOfHazard` movers are only mocked.
