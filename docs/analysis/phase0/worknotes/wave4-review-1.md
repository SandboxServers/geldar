## Area A
- A1 (X) HIGH: panic burrow digs by block NAME with `mine` (nearest block of that name, not the planned cell): flank or floor cells get dug, the closed cells are never re-checked, `leave` mines a wall block. Likely cause of live finding L3. Fix: dig the exact cell (`bot.dig(bot.blockAt(cell))` or an exact-position mine helper), re-check the closed cells before stepping in, allowlist diggable names (no chests, ore, obsidian), exact-cell leave; tests with a stone floor and flank assertions (the current fake mines the nearest stone, so the test passes with a breached flank).
- A2 (X) HIGH: panic-burrow cancels the running action BEFORE planning (`planBurrow` null in open terrain makes it cancel the intent's action every 200 ticks all night); hazard-escape cancels before its "burning but not in a hazard block" early exit. Fix: decide first, cancel only when about to act; add `cancels() === 0` assertions.
- A3 (Y, with X for reflex.ts/runtime.ts if needed) HIGH: reflex pre-emption does not reach program-step actions (`programs/action-step.ts` calls `runAction(ctx.registry...)` directly, so `runtime.current` is null and `ctx.cancelAction()` is a no-op for them); the reflex does not wait for the action to wind down (item on the cursor, late `pathfinder.stop()` cancelling the reflex's new goal); `submit()` immediate actions never check `reflexRunner.busy`. Fix: route program-step and reflex actions through one "current action" slot, make `cancelAction` resolve only after the action has ended (the handler, not just the signal), make `submit` wait for `!busy`; one integration test with a real program, runtime and reflex.
- A4 (Y) MEDIUM: `blocked_path` fires after the intent already failed (`action_failed` wake) so the detour never helps and can fight the Mind's next plan; `pending` has no tick, expiry or intent check. Fix: programs return `running`/a `blocked` wake when a report is pending, or run the alternate inside the step; expire a report after N ticks or when the intent id changes.
- A5 (Y) MEDIUM: a Mind-supplied `checkpoint` in a thought is routed to `resume` (`executor-intent.ts:89`), so a foreign-shaped checkpoint (the spec example has one) fails the intent. Decision (orchestrator): `submit` always calls `start`; only the restart path (`executor.resume`) uses a checkpoint. Update the test that codifies the old behaviour.
- A6 (X) MEDIUM: fight-or-flee and retreat blame any hurt on the nearest "hostile" (fall, fire, drowning); neutral and suicide mobs (enderman, creeper, zombified piglin, spider by day) get meleed. Fix: exclusion list by name, require that the mob is actually attacking (within reach and facing) or that damage came from an entity.
- A7 (X, decision) MEDIUM: burrow state is a `WeakMap` per view, lost on reconnect or restart: a Body that restarts while sealed never leaves. Decision (orchestrator): at dawn, if `enclosed` and it is day and no burrow state, dig out through any adjacent non-wall placed block (exact cell, same helper as A1), instead of persisting state.
- A8 (X) MEDIUM: hazard-escape steering fallback ignores walls and lava; drowning with no stand within range never swims up; `view.ts` reads only the feet-cell fluid (kelp, seagrass, bubble columns read as dry). Fix: swim up with jump when there is no target, use `bot.entity.isInWater`/`isInLava`.
- A9 (X) LOW-MEDIUM: the `eating` flag is a module singleton shared across Bodies (`basic.ts`). Fix: per-Body reflex instances (a factory) or drop the flag and keep `usingHeldItem`; update `create-body.ts` to call the factories (Y: accept the one-line call-site change).
- A10 (Y) LOW-MEDIUM: the intent is not re-validated after the immediate actions (`executor.ts:303-305`). Fix: validate before `startIntent`; test.
- A11 (Y) LOW-MEDIUM: limit accounting: `>=` ends a `gather` that hits exactly `max_block_operations` as `failed`; failed or cancelled mines that already broke blocks are not counted; a resumed intent gets a fresh tick budget and a zero block count. Fix: evaluate step completion before the limit check, count partial `mined` from the result detail, carry the used budget in the checkpoint.
- A12 (X for reflexes, Y for programs) LOW-MEDIUM: `timeScale` is not applied to program-step and reflex actions. Fix: add `timeScale` to `ProgramContext` and `ReflexContext`, pass it to every action run, scale the fixed wall limits.
- A13 (Y) LOW: `gather` without `item` fails `not_possible` for stone (drops cobblestone) and rejects the spec's `radius`. Fix: derive the drop item from the registry's `drops`, accept `radius` (as a search bound).
- A14 (Y/X) LOW: two guard lines no test covers: `executor.ts` `a.pause !== null` in `noteAction` (Y), `safe-spot.ts` `bed = null` (X): add tests that fail without them.
- A15 (X) LOW-MEDIUM: `bedNearby` runs `bot.findBlock` (radius 32) every tick at night. Cache about 20 ticks.
- A16 (X, decision) LOW: fall-stop fires on planned parkour or a descent beside a cliff and then the intent walks back every 5 ticks. Decision (orchestrator): a 20-tick backoff after a firing and no firing while the pathfinder holds a goal.
- A17 (Y) LOW: `executor.ts` 541 lines and `executor.test.ts` 531 lines: split along a natural seam.

## Area B
- B1 (Z, decision) HIGH: an intent that ends `interrupted` (the ordinary end on a wake or on `stop()`) is never projected, so its row stays `running` forever. Decision (orchestrator): project `interrupted` as `cancelled` with `end_reason` starting `interrupted:`; `paused` stays events-only. Record in a decision (0043 below).
- B2 (Z, decision) HIGH: `NatsRecordSink` drops `action` and `receipt` records after 5 retries (about 3 s) or when 10,000 are queued; decision 0020 needs exactly one final receipt per action. Decision (orchestrator): `action` and `receipt` records are never dropped on retry exhaustion (retry with capped backoff, forever, ordered); when the queue is full the oldest NON-audit record (`reflex_fired`, `wake`, `intent` pause) is dropped first; audit records are dropped only if the queue is full of audit records, and that raises a loud error log and a counter. `reflex_fired` and `wake` stay droppable.
- B3 (Y for the executor part, Z for the live test and restart) MEDIUM: nothing is checkpointed at intent start, so a restart during the first program step finds no checkpoint (live finding L2; the wave4 live-pass note's earlier diagnosis was wrong, the test already shared one KV). Fix: write the checkpoint when the intent is installed (state running) and again after each step; the live test waits for the first checkpoint put before tearing the Body down.
- B4 (Z) MEDIUM: a failed checkpoint delete after `ended()` leaves a stale checkpoint (resumed after the next restart). Fix: bounded retry with backoff on delete; test with a failing delete.
- B5 (Z) MEDIUM: `restartBody().stop()` flushes checkpoints but not the record sink; the `interrupted` event can be lost. Fix: await `flush()` on a sink that has one; test with a sink double.
- B6 (Z) LOW-MEDIUM: resume trusts `expires_tick - tick` after a clock regression (`restart.ts:142`) and `view.tick ?? 0` skips the expiry check. Fix: cap with `intent.limits.max_world_ticks`, treat a null tick as "cannot resume yet" (wait for a tick) with a test.
- B7 (Z) LOW: a KV read error is reported as `no_checkpoint`. Fix: retry `load()` a few times, distinct reason `checkpoint_unreadable`.
- B8 (Z) LOW: the restart live test uses fixed ids and is not hermetic against real NATS. Fix: unique life and intent ids, delete the keys in `finally`.
- B9 (Z, decision) MEDIUM: the `intents` columns (goal, program, arguments, preconditions, wake_on, limits, thought_id, checkpoint) are never filled. Decision (orchestrator): add those fields to the `accepted` intent event payload and project them (checkpoint filled from the latest checkpoint-carrying event or left null with the reason documented).
- B10 (Z) MEDIUM: `eventsink/README.md` is stale (projection, the single transaction, the tables, dead-lettering a second final receipt, the new integration test).
- B11 (orchestrator, later) the ledger, RESUME and `golem/README.md` are stale; Z updates `golem/README.md` (the Body, the buckets, `restartBody`, the NATS opt-in text) and `run-shard`'s table note for the new tables; the orchestrator does the ledger and RESUME at the wave close.
- B12 (Z) LOW: schema descriptions disagree with the code (intent id derivation, wake `no_plan`); packet text vs build (restart wired in `create-body.ts`/`restart.ts`, the live test tears down a Body, not a process); spec 5.2 says durable state is in Postgres but checkpoints live in NATS KV: the orchestrator files decision 0043.
- B13 (Z, decision) LOW: receipt ids are random, so a replayed `action_id` after a restart writes a second receipt (dead-lettered). Decision (orchestrator): `receipt_id` is derived from `(action_id, phase)`; a replay after a restart is rejected by the body_generation validity check; record in 0043.
- B14 (Z) LOW: `openRestartKv` sets `reconnect: false` and skips the loopback guard; checkpoints are put on every step without change detection and "not written" is logged every step. Fix: reconnect with backoff, the loopback guard, skip an unchanged put, throttle the log.
- B15 (Z) LOW: `writer.ts` releases the client after a failed ROLLBACK without `release(true)`; projection treats a same-`receipt_id` different-phase row as a redelivery; a new-row race under two sink replicas is latent (document; one sink in compose).
- B16 (orchestrator) LOW: run `GELDAR_IT=1` for `eventsink/test/projection.it.test.ts` and record it; the P0-17 and P0-18 coder reports give no revert-check evidence: Z records the revert-checks for the new fix tests properly; add tests for `MAX_PENDING` drop behaviour (now audit-aware), a failing delete, a null view tick, sink flush on stop.
