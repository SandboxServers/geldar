# w6-24: bounded awaits in the thinking cycle

Question: in smoke run smoke-w6-20-a the Mind made no model call after 14:12:42Z. Which await hung?

## Finding

The stuck await is **not proven**. The code shows no await on the cycle path with an unbounded
wait on the Thinker or the Body link. The unbounded ones are the database and event-publish calls,
whose only bounds live in the pool and the NATS client, not in the loop.

## Every await in `ThinkingLoop.run` and `handle`, and its bound

| Await | Bound before this packet | Chosen bound |
| --- | --- | --- |

| `recordLostWake` | none in the loop (journal write) | `STEP_TIMEOUT_MS`, reason `journal` |

| `journal.journalSince` | none in the loop (pg bounds only) | `STEP_TIMEOUT_MS`, reason `journal` |

| `writeThoughtRow` (journal insert, in `record`) | none in the loop (pg bounds only) | `STEP_TIMEOUT_MS`, reason `journal` |

`STEP_TIMEOUT_MS` is 60 s (`animus/src/loop/cycle-await.ts`), overridable with `LoopOptions.stepTimeoutMs`.
It is far above the p95 of 15 s for a thought and above the dependencies' own bounds (5 s NATS,
10 s pool connect, 30 s statement). The Thinker bound adds the job's own deadline, so a high-effort
thought (deadline up to 60 s) is not cut short. The released prompt templates are untouched.

## Behaviour

A step past its bound throws `CycleAborted(reason)`. `handle` logs `cycle_aborted{reason}`,
reports the failure, and settles the thought as `model_error`, which clears the in-flight flag.
The next wake runs. The abandoned work is not cancelled, but the cycle does not run any step after
the bound, so a late reply cannot submit a plan.

The thought row is not written for a cycle aborted at the Thinker or the journal, because the
row is written after the model answers. The `cycle_aborted` line is the record of that cycle.

## Log lines (INFO, per cycle)

`thought_started`, `snapshot_ok`, `thinker_request_sent`, `thinker_reply` (ok or error code),
`thought_committed`, `cycle_aborted{reason}`. Each carries `life_id`, `wake_reason` or `thought_id`
where relevant, and `elapsed_ms` from the injected clock. No prompt, model text or secret is logged.

## Tests

`animus/src/loop/thinking-loop-timeouts.test.ts`: a hung snapshot, memory retrieval, journal read,
thought row write, Thinker answer and event publish each end the cycle with the matching
`cycle_aborted` reason, and the next wake plans. A happy-path test checks the log sequence.

## Revert-checks (commit 9c7e493)

Each check replaced one bound in `thinking-loop.ts` with `3_600_000` ms, ran
`thinking-loop-timeouts.test.ts`, then restored the file from a scratchpad backup (hash checked,
`git diff --stat` empty). Only the named test failed each time, 1 of 7:

- snapshot bound (`snapshotBudget + this.stepMs`): "ends a cycle whose snapshot never comes".
- thinker bound (`thinkerBound`): "ends a cycle whose Thinker never answers".
- memory bound (retrieve, `this.stepMs`): "ends a cycle whose memory retrieval never returns".
- journal read bound (`journalSince`): "ends a cycle whose journal read never returns".
- thought row write bound (`writeThoughtRow`): "ends a cycle whose thought row write never returns".
- publish bound (`publishThoughtEvent`): "keeps a committed plan when its event publish never returns".

The write and publish checks are separate runs, since they are separate await sites.

The thinker bound is `deadlineS*1000 + thinkerWaitMs + stepMs`, so it is always larger than the
model deadline it wraps. The deadline is at most `HIGH_DEADLINE_CAP_S` (60 s) at high effort.
The default 60 s step limit therefore does not cut a legitimate 32B thought.
