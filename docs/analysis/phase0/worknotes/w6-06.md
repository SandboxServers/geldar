## Deviations

- **No injectable timer.** The keep-alive uses the global `setInterval`. The stop test spies on it
  (`vi.spyOn`) and restores the spies after each test. An injectable clock was not added: it would
  change the Thinker's options for one test.
- **Shard `keep_alive: 30m` kept.** The ping every 600 s refreshes it well inside 30 minutes; the
  shard value is unchanged.
- **Warm-up runs before `hello`** (already the case in 3b86461). A cold 32B load can take minutes;
  `warm_timeout_s` (180 s) bounds each model.
- **Re-warm and pings run outside the job timer.** They are `void` calls, so they do not use the
  thought budget (`deadline_s`) and do not count as thoughts.
- **Warm-up still loads both chat models when `run_tier` is unset.** `warmOrder` is unchanged, so the
  start-up load can take both models into VRAM before the keep-warm set limits the pings. The
  warning says so. This is a finding for the orchestrator: set `run_tier` in the life's shard (it is
  set to `strong` in `shards/phase0.yaml`).
- **Single-tier rule.** When `run_tier` is unset and exactly one tier has models, that tier's models
  are kept (the spec says "the strong model"; with one tier configured that is the only tier).
- **Tests.** Five new tests in `keep-alive` / `keep-warm set`: strong pings strong + embedder only;
  fast pings fast + embedder only; unset pings no chat model and logs the warning once; a failed
  embedder ping is logged and pings go on; the re-warm does not touch a chat model outside the set.
  The keep-warm config rule (`keepWarmSet`) has no direct unit test yet.
