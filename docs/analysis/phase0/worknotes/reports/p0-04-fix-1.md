## Fix 2: why it is blocked

The fix assumed Ajv error `schemaPath` values start with `#/$defs/<X>Frame`. They do not. With the root `oneOf` of `$ref`s, Ajv inlines most frame branches, so their errors read `#/required`, `#/additionalProperties`, `#/properties/type/const`, identical across branches. Only frames without nested refs (goodbye, drain) get the `#/$defs/...` prefix. Errors cannot be attributed to a frame by path.

Shapes tried, none workable:
- Root `allOf` of `if`/`then` per type: errors scoped to the matching frame, but `json2ts` drops `if`/`then`, so `ThinkerFrame` becomes `{ [k: string]: unknown }` and the nine named frame types are not generated (the packet exports them).
- `oneOf` of `if`/`then`/`else: false` branches: same `json2ts` collapse.
- Per-branch `schemaPath` filtering: impossible, as above.

Result: a bad `job` still reports about 30 errors, and `errors[0]` is a hello error (`"" must have required property 'thinker_version'`). The test "reports only the job frame errors for a job with a bad deadline" fails.

Options for the orchestrator:
1. Extend `contract/scripts/generator.ts` (outside this packet) to export a per-frame validator for each `$defs` frame, and have `validateThinkerFrame` call the matching one. This keeps the `oneOf` and the generated union types.
2. Accept an unscoped error list and drop that test.
