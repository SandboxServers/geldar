# P0-05 fix 1 (sql)

Commit `cd6b2b7` on `phase0/p0-05-sql`, on top of `b2939e3`. Answers `p0-05-review-1.md` findings 1, 2 and 3.

## Changes

1. Finding 1, option (b): composite skill keys.
   - `books`: `edition INT` added. `FOREIGN KEY (skill_id, edition) REFERENCES skills (skill_id, edition)`. `CHECK ((skill_id IS NULL) = (edition IS NULL))`.
   - `skill_library`: `edition INT` added. Primary key is now `(agent_id, skill_id, edition)`. `FOREIGN KEY (skill_id, edition) REFERENCES skills (skill_id, edition)`.
   - Every change is marked `differs from spec Appendix D`.
   - NOT NULL choices:
     - `skill_library.edition` is NOT NULL, because it is part of the primary key. A library row is "this agent knows this edition of a skill", so it always names one.
     - `books.edition` is nullable, and only allowed to be null when `skill_id` is null. A book with no skill (`skill_id` nullable as in the spec) stays valid. A book that names a skill must name its edition. Without the CHECK, a row with `skill_id` set and `edition` null would skip the foreign key, because MATCH SIMPLE does not check rows with a null column.
   - `sql/README.md` states that Appendix D needs this correction. spec.md and docs/decisions were not touched.
   - The header comment of `0001_init.sql` now says "the changes below" instead of "the three changes".
2. Finding 2: `sql/test/check-schema.sql` now collects problems and raises one `RAISE EXCEPTION`. It checks:
   - a unique index or constraint on `receipts` over exactly `(action_id, phase)`, and none over `action_id` alone (via `pg_index`, so `CREATE UNIQUE INDEX` is covered too);
   - `receipts.detail` and `actions.snapshot_revision` exist;
   - schema `archive` exists;
   - `books` and `skill_library` each have a foreign key to `skills` over `(skill_id, edition)`.
   The table and pgvector checks are unchanged.
3. Finding 3: the `ci.yml` header now says the `sql` job has no local `check` counterpart.
