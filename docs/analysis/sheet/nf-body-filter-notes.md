## 2. Unverified items

1. **Does NeoForge send human player entities to a mineflayer Body?** Under the vanilla protocol, a player inside another player's tracking range is sent to that client as a player entity, and every online player is listed in the player-info (tab list) packet. Nothing on the geldar-nf project changes that: the mod has no player-hiding code (`neoforge/src/main` has no spectator, ghost or hide path; searched). No run has had a human and a Body on the NeoForge shard at the same time, so it has never been observed. If it holds, every row of section 1 applies as written, and `bot.players` lists every online human by name to every Body (see OQ-11).
2. **Are spectator entities sent?** On NeoForge, humans are not held in spectator: decision 0387 item 3 drops the 0137 ghost rule for the NeoForge human listener, and the mod has no ghost code. On Paper, ghosts are held in spectator (`plugin/core/src/main/java/dev/geldar/core/GhostListener.java`). Whether a vanilla or Paper server sends a spectator's player entity to a survival client in tracking range was not checked. If it does, a Paper Body puts a ghost's username into `agents[]` today (`entities.ts:244-256` does not check the game mode). That would be a Paper finding outside these cards: they leave Paper unchanged by design (OQ-8).
3. **Ghost behaviour on NeoForge.** No ghost path exists there (the Paper `GhostListener` is a Bukkit class in `plugin/core`, not in the mod). Whether the human lane's Velocity sends the `geldar:ghost` plugin message on NeoForge, and whether anything would read it there, was not checked. Nothing in the mod listens on that channel.
4. **Chat delivery on NeoForge.** Vanilla chat reaches every online player. With no NF-CHAT, a Body would hear every human line on the server (delta note section 8 item 2: no NeoForge run with chat has been done). Whether `/say`, `/me` and `/msg` reach mineflayer as `playerChat` or `chat` (`ears.ts` reads those two only), or as system chat (which the ears ignore), is unverified.
5. **The username shape of future NeoForge Bodies (NF-BODY).** The predicate admits a contract `LifeId` or a managed id. A NeoForge agent with any other username would be hidden from other agents when the switch is on. That fails closed, but it is a visible failure, so NF-BODY must use one of the two shapes. The probe's `ag_nfprobe_01` is a LifeId.
6. **The minimal fake for `viewFromBot`** (NF-F4): whether it can be built without a live world. NF-F4 stops and reports if it cannot.
7. **The deployed NATS conf on the node** matches the generator in `deploy/nats-auth-nf.ps1`. The repo cannot show the node's file. Section 3 reads the generator.
8. **Forged identity across lanes.** 0388 residual risk 1 (one forwarding secret shared by three proxies) means a compromised public proxy could present an agent-shaped name to the NeoForge server. The predicate trusts usernames, so it inherits that accepted risk. These cards do not change it.

## 3. Live exposure: can an agent Body run on the live NeoForge shard today?

**No agent Body (a Body driven by a Mind or the MCP) can run on the live NeoForge shard today.** The only Body that can run there is the P0 probe, which has no Mind, no snapshot consumer and no ears.

Evidence (VERIFIED in the repo; the node itself was not inspected):

- **The base project has no Body service.** `compose/nf-live.yml` (project `geldar-nf`) declares `nats`, `postgres`, `eventsink`, `identity-seed`, `velocity` and `neoforge` only. `deploy/nf-deploy.sh` says so twice: its header ("It never names golem-body or players-host (they are not services of compose/nf-live.yml)") and its plan text (`:463`, "golem-body and players-host are not in this project and are never started"). The runbook says the same (`docs/runbooks/nf-live-project.md`, the refresh-secrets section). The other overlays add no Body: `nf-live-human.yml` (`velocity-human`, `velocity-human-init`), `nf-live-bluemap-web.yml`, `nf-live-mod-*.yml`, `nf-live-telemetry*.yml`. There is no MCP, no players-host, no body-helper and no Mind service in any `compose/nf-live*.yml`.
- **The one Body is the probe.** `compose/nf-live-probe.yml` declares `probe` (profile `probe`, image `geldar-body:geldar-nf`, entrypoint `node src/p0/probe.ts`, `restart: "no"`). `up` never activates the profile. It runs only through `deploy/nf-deploy.sh probe` (`cmd_probe`, `:566-584`), as `run --rm --no-deps`. The probe (`golem/src/p0/probe.ts`, header) joins as `ag_nfprobe_01`, runs one `goto` to a fixed position east of spawn (`golem/src/p0/probe-steps.ts:21-29`) and one `mine`, prints receipts to operator stdout, and cleans up. It imports no perception, no ears and no Mind link (its imports are actions, connection, registry, RCON, isolation, cleanup, steps, verify). It builds no snapshot and wakes no model. The isolation guard accepts `geldar-nf` on main (`golem/src/p0/isolation.ts:20-23`; commits `17bb5402`, `174b4e8f`).
- **No other agent can be admitted.** The agent lane is the loopback Velocity (`127.0.0.1:46565`, 0388 decision item 3), gated by the life registry. In the NeoForge NATS user table (`deploy/nats-auth-nf.ps1:42-66`), the only user that may write a registry key is `body`, and only the key `ag_nfprobe_01` (`:54-59`; "Real Bodies on geldar-nf will need their own role and a later owner decision; this user is the probe's only"). `seed` creates and updates the buckets but holds no `$KV` put. `velocity` and `human` read only. The body-helper and players-host run in the colo project with their own `GELDAR_MC_HOST` and `GELDAR_MC_PORT`, and nothing in `body-helper/src` names the NeoForge port or project (searched).
- **Can the public human lane and agents coexist today?** Humans and the **probe** can. With `NF_HUMAN=on`, `check_human_orphan` lets `probe` run while `velocity-human` exists (`deploy/nf-human-lib.sh:113-127`; it refuses only with `NF_HUMAN` off or unset), and humans and bots share `MAX_PLAYERS = 100` (0388, Amendment). Humans and a **Mind-driven agent** cannot, because no such agent can be admitted (above).
- **What a visible human gets from the probe right now:** the probe's Bot receives the human's entity and chat lines in memory (unverified item 1), but no code in the probe reads them, and its output is operator stdout receipts only. Nothing reaches an agent, because there is no agent.
- **What a visible human would get from a Mind-driven Body if one were admitted there with today's code:** everything in section 1. The human's username and stance in `agents[]` (`entities.ts:244-256`). The human as a resolvable give, goto and follow target, including by tab-list display name (`visible-agent.ts:112-130`). The human as an attack target, by name or by the word `player` (`attack.ts:59-73`). Every chat line from anywhere on the server, with the username, in `heard`, in `speech` events and as an `addressed by <name>` wake (`ears.ts:63-130`, `executor.ts:168`). A drawn player figure in the text view and the image (`viewport.ts:211`, `reader.ts:41-58`). The MCP passes the names through (`surroundings.ts:27`, `untrusted.ts:5-9`, `handlers/speech.ts:9`). Hurt and death stay nameless.

## 4. Open operator questions (listed, not answered)

- **OQ-1. Human speech.** Does a human's chat reach agents at all? If it does, in what form: words with no speaker, a muffled notice, something else? Does it wake a Mind (`directly_addressed`), and does it enter the `speech` event stream that the eventsink stores? Blocks NF-F3.
- **OQ-2. The intervention channel.** How does a human act on the world: an in-world avatar playing as a player, a command or nudge channel, a mod that produces "acts of nature"? The cards filter player entities and take no position here.
- **OQ-3. Avatar versus nudge.** If humans have avatars, are they physically present to agents (they block a placement, take a hit, pick an item up, push), and what does the agent perceive of such a body, if anything? Blocks NF-F2w. It also bounds NF-F4: what, if anything, is drawn in a hidden player's place.
- **OQ-4. Wording for a filtered cause.** Today's person-words for an unseen cause ("someone is standing there", "someone else picked the items up") would describe a hidden human. Should they stay, become the existing thing-word ("something is standing there"), or get new text (a `prompts/` or outcome-words change with OWNER APPROVAL)? Blocks NF-F2w.
- **OQ-5. Human-written world text.** Signs, books and named items written by humans reach agents as untrusted world text (`untrusted.ts`, signs). Do they stay (as "mystery"), or are they filtered? No card covers this.
- **OQ-6. Hurt bearing.** A hurt from a human is nameless but carries a bearing. Is that an acceptable "act of nature"? No card changes hurt.
- **OQ-7. What of 0329 survives.** The revision decides NF-1 to NF-6, A6 and A7, and AN-NF-25 (a named `PlayerActor`), which conflict with this model. NF-6 (human block owners logged by name) concerns logs, not perception. Which rulings stand?
- **OQ-8. Paper.** The cards leave Paper unchanged (switch off). Should the predicate also apply on Paper as a second line against ghosts or admins (unverified item 2)? That would change Paper behaviour and needs its own ruling.
- **OQ-9. The predicate shape.** An allow-list (`LifeId` or managed id, the cards' proposal) or the 0388 complement (any `ag_` prefix, any case)?
- **OQ-10. Operator logs and stored events.** With the Body filter on, a human's username can still be written by operator diagnostics (`give-not-in-sight` facts) and, until OQ-1 is answered, in stored `speech` events. Is that telemetry privacy question (as 0375 and 0329 Q5 put it) the operator's to rule separately?
- **OQ-11. The tab list.** The protocol gives every Body the names of every online human (`bot.players`). After the cards, no code path makes them agent-facing. Is holding them in Body memory acceptable?
- **OQ-12. Observer disclosure.** 0329 Q6 (whether a NeoForge identity block says anything about the world's other inhabitants) is still open, and the new model reframes it.
- **OQ-13. Activation.** Who turns `body_perception.players: agents_only` on for a NeoForge shard file, and when? The cards hold it until NF-F3 is ruled and merged and NF-BODY exists.
