# S12-03b worknote: the sheet path records no decision when no roll was drawn

## Change

`golem/src/character/runtime.ts`, `record(call, facts)`: after the non-finite health guard, a decision with
`call.roll === null` (or with no `lastRoll`) returns before any audit call. The only recorded decision is the d20
event keyed by its roll and citing it; the deterministic branch is removed, so no roll-less decision event can be
written.

This supersedes the roll-less-decision lines in `AN-12a.md` (line 24: "is kind `deterministic`, with fx `threat`
and a fresh key under the Body generation") and `S12-03.md` (line 16: "records one deterministic decision event per
threat decision"). Both describe behaviour that this card removes; those files are left as dated records.

Effect: with the all-3 control sheet and rolls off, the sheet path emits no audit decision event and no roll
event, the same as today's Body (`LEGACY_THREAT`, used when `character` is omitted). Outcomes were already equal
(S12-03); events are now equal too.

## Decision record

No decision record is needed. The behaviour matches decision 0328's control rule and the S12-03 card. There is no
spec or contract change. The Body decision function is unchanged.

S12-04b can therefore claim no Body decision change and no event change.

## Tests

- `golem/src/character/runtime.test.ts`: the roll-less deterministic test now expects no decision event;
  `records no decision for a roll-less decision even when rolls are on` covers the at-floor, above-band and
  unarmed-flee cases with rolls on; `still records a rolled decision as a d20 decision keyed like its roll, citing the roll` keeps the rolled case
  (rolls on, health 8, armed, inside the band).
- `golem/test/character-control/threat-equivalence.test.ts`: `records no decision and no roll for any decision
  that uses no roll` asserts `recordDecision` and `recordRoll` are not called for all `allFacts()` with rolls off.
  The `HOSTILE_NAMES` loop is trimmed to `['creeper', 'zombie']`; the `ALWAYS_HOSTILE` import is dropped.

## Revert-checks

1. Early return removed (`if (call.roll === null || lastRoll === null) return;` deleted): `call.roll.fx` is read on
   a null roll, so the decide path throws. 8 failures across `threat-equivalence`, `proficiency-equivalence` and
   `runtime.test.ts`, including `decides the same as LEGACY_THREAT` and `draws an unarmed flee`. (Before the
   review-1 fix the same check was the `fx` ternary plus early return: 2 of 139 failed.)
2. `record()` made to return unconditionally (`if (call.roll === null || lastRoll === null || true) return;`): the
   rolled-decision test `still records a rolled decision as a d20 decision keyed like its roll, citing the roll`
   and `draws an unarmed flee as a d20 keyed threat_unarmed` fail. 2 of 140 failed.
3. Rolls-on roll-less guard (review 1, finding 1): the pre-fix code's guard `if (call.roll === null) return;`
   mutated to `if (call.roll === null && !rolls) return;` makes a rolls-on roll-less decision reach the
   deterministic branch. `records no decision for a roll-less decision even when rolls are on` fails. Run on the
   review-1 base, before the dead branch was removed (1 of 9 failed in `runtime.test.ts`). After the fix, the same mutation cannot reach
   `recordDecision`: `lastRoll` is null for a roll-less decision, so the `lastRoll` guard returns. That mutation
   therefore survives on the fixed code (140 of 140 pass). This is by design, not a gap in the tests.
