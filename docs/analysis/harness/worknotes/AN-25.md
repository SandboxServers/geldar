# AN-25: visible attacker identity (worknote)

Status: the hurt trigger can name a visible player as the cause of a hurt. Nothing passes the resolver yet, so behaviour and bytes are unchanged.

**Paper-only in behaviour; do not enable on NeoForge until the human-handling question is decided.**

## What changed

- `golem/src/perception/provenance/visible-actor.ts` (new): `observedActor(bot, username, lifeIdOf = lifeIdFor)`. Null when the name is missing, is the Body's own name, fails `^[A-Za-z0-9_]{3,16}$`, or `isUsernameVisible` finds no visible player with that exact username. Otherwise `{ name, life }`.
- `golem/src/perception/hurt.ts`: `HurtInput.actor?` and `HurtEvent.actor?` (`ObservedActor`). `hurtEvent` copies the actor only when it is present.
- `golem/src/perception/hurt-trigger.ts`: `watchHurts(bot, reporter, tick, resolve?)`. On each `entityHurt` on the Body it calls `resolve` with the cause's username (a player other than the Body), or `undefined` for a mob or no cause. `hurtWorldEvent` adds `payload.actor` only when the hurt has one.
- `golem/src/perception/hurt-trigger.ts`: `actorFor(resolve, username)` wraps the resolver call. A resolver that throws gives no actor and does not throw into mineflayer's packet handler.
- Tests: `visible-actor.test.ts` (9, including the loose-name refusal and one wiring test that passes `observedActor` as the `watchHurts` resolver), and a `watchHurts: the named attacker` block in `hurt-trigger.test.ts` (12). The no-resolver test is named `no resolver: the damage event bytes are identical to today`.

## Revert-checks (run on the committed fix)

1. Skip `findVisibleAgent` (`void findVisibleAgent;` in place of the check in `observedActor`). Fails: `a player out of sight stays anonymous`, `a player who is not in the world at all stays anonymous`.
2. Fall back to the nearest player when the cause is not a player. Fails: `a zombie hit with an innocent player nearby has no actor`, `fall, fire and starvation have no actor`.
3. Always set the actor on the payload (`payload.actor = hurt.actor ?? null`). Fails four tests, including `no resolver: the damage event bytes are identical to today`, and the existing `hurt WorldEvent names no one` guards.
4. Loose check (review fix 1): `observedActor` also accepts a name that `findVisibleAgent` resolves loosely (`!isUsernameVisible(bot, username) && findVisibleAgent(bot, username) === null`, with `findVisibleAgent` imported). Two lines changed, the import and the check. Fails `a loose spelling of a visible player is not named`.
5. Drop the player-type check in `actorUsernameOf` (`entity.type !== 'player'`, review fix 3). Fails `a non-player cause with a username is not asked`.
6. Drop the self-id check in `actorUsernameOf` (`entity.id === selfId`, review fix 3). Fails `the Body as its own cause is not asked`.
7. Let a resolver fault escape: the `catch` in `actorFor` rethrows (`throw fault;`) in place of `return undefined;` (review fix 5). The old code could not throw there, so this stands in for the pre-fix behaviour. Fails `a resolver that throws gives no actor and does not throw`.

Each mutation was a one- or two-line edit, restored from a scratchpad backup; `git diff --stat` was empty after each restore.

## Notes

- `registry.ts` imports load without NATS, so `lifeIdFor` stays the default parameter. The required-parameter fallback was not needed.
- The resolver is called with `undefined` for every `entityHurt` that has no player cause, including falls. That is by design: the resolver decides nothing for a non-player.
- Loose names are refused: `observedActor` uses `isUsernameVisible`, the exact-username check, so `Bob` or `bob` for a visible `ag_bob` is never named. `findVisibleAgent` (which does match loosely) is not used here.
- The resolver must not throw. `actorFor` turns a throw into no actor, so a fault in `observedActor` cannot reach mineflayer's packet handler (AN-28b relies on this).
