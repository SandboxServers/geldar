## The standing rule for later cards

Every later card that edits `psyche/src/` (AN-08a, and AN-42 in W10) must:

1. run `node tools/psyche-release/src/cli.ts --write`;
2. bump `version` in `psyche/package.json`;
3. be followed by a new tag `psyche-v<new version>` after merge.

`release.test.ts` fails in CI until step 1 is done, so the rule is enforced first by the test.

## The tagging command (ops, after merge, with owner approval)

```
git tag -a psyche-v1.0.0 <merge sha>
git push origin psyche-v1.0.0    # owner approves this push; the coder never runs it
```

Replace `<merge sha>` with the sha of the merge commit that carries `psyche/RELEASE.json`.
