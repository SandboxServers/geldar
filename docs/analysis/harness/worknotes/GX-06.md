# GX-06 worknote: source on the sovereign call (world side)

Status: ADVISORY. Part 1 (contract), part 2 (MCP wiring) and the fix pass are in. The `source` class stays ADVISORY until the kit's denial test (HC-19, kit side HC-L1 by scriptorium-orchestrator) passes. Nothing is on by default: no connection is an instinct connection unless `GELDAR_MCP_INSTINCT_KEY_FILE` names a usable key file, and none is set in the repo or in any shipped shard config.

## Part 2 (MCP): what is in

- `threshold/mcp/src/http/instinct-key.ts`: `loadInstinctKey(text)` (one trailing LF/CRLF removed; then the key must be printable ASCII with no edge space, at least 32 bytes, or it is refused; an empty file is refused too), `sameKey(presented, key)` (sha256 of both sides, then `crypto.timingSafeEqual`), `connectionSource(req, key)` (reads `rawHeaders`; a repeated, absent, wrong or different-length `X-Geldar-Instinct-Key` is `model`; no key loaded is `model`).
- `threshold/mcp/src/config.ts`: optional `instinctKeyFile` from `GELDAR_MCP_INSTINCT_KEY_FILE` (unset: no instinct class).
- `threshold/mcp/src/main.ts`: `instinctKeyOf(path, readSecret)` reads the file as the pepper is read. Unset is no class. A set variable whose file is unreadable, empty, short or unusable refuses start-up with one constant `ConfigRejected` line that names only `GELDAR_MCP_INSTINCT_KEY_FILE`; the path, the file text and the key are never in it.
- `threshold/mcp/src/http/front.ts`: `instinctKey` option. `connectionSource` is read by the mock only after the bearer check has passed, when the session is made.
- `threshold/mcp-mock/src/server.ts`: `connectionSource` option; `createSession(playerId, signal, { source })` with the class as an optional third argument (default model). `threshold/mcp-mock/src/registry.ts`: `ToolContext.source`.
- `threshold/mcp/src/world-session.ts` and `world.ts`: the class reaches `callerOf`, which sets `source` only for `instinct`. `threshold/mcp/src/tools/act.ts` (`callPayload`) records it.
- `tools/act.ts` is unchanged in this part: tool input never sets `source`.

## Which tools record the class

Only `act` records `source` (its sovereign-call event, `callPayload`). `say`, `journal`, `sleep`, `unavailable` and the other tools called on an instinct connection carry no `source`, so by the absent-means-model rule they read as `model`. An analysis must not count their absence as model-authored: a `say` or `journal` call on the instinct connection is not marked as instinct.

## Not done: sessions per (player, class) (stopped)

Ruling A (keep an instinct session and a model session of one player live at once) was NOT done. The change is not small: in `threshold/mcp-mock` every session of a player is built on one shared `McpWorld` (`app.ts` `createSession` uses the same `world`, and `sim/hub.ts` keeps one `PlayerSim` per player). Two live sessions would share one life, one wait cursor and one budget, and the per-player bookkeeping in `server.ts` (`byPlayer`, `starting`, `superseded`, `openResponses`, revoke, `sessionCount`) would need a class key too. That is the per-player world state and the one-in-flight-call rule the brief names as a stop. Consequence, which the operator must respect: any initialize for a player (either class) supersedes that player's live session. The instinct step and the model's session for the same player must not be live at once; the model's next request gets `session_superseded` if the instinct step initializes, and the reverse.

## Operator and kit constraints (not done here)

- DECISION NEEDED (owner and kit orchestrator). The mock allows one session per player: `byPlayer` in `threshold/mcp-mock/src/server.ts` is keyed by player id, and any `initialize` of either class supersedes that player's other session (its signal is aborted; the superseded side gets 404 `session_superseded` on its next request). So the instinct step and the model must never be live for one player at once. HC-19 must run the instinct step strictly BETWEEN model sessions, never while a waking is live: the model's waking must have ended (its session closed, nothing in flight) before the instinct initialize, and the model must not re-initialize while the instinct step runs. Nothing in this repo enforces that ordering; it is an operator and kit rule until the owner rules otherwise (keying sessions per (player, class) is the alternative, not done).

- The key file is delivered by geldar-93 as a compose secret on the node, mounted read-only into the MCP container. The operator then sets `GELDAR_MCP_INSTINCT_KEY_FILE` to its path. Nothing is on by default: with the variable unset there is no instinct class.
- A set variable with an unusable file stops the server at start-up (by design). A key is read once at start; there is no hot reload, so rotating the key needs an MCP restart. A changed or removed file has no effect until then.
- The instinct connection uses an internal address (the container network or the node's private address), never the public tunnel: a public proxy may log request headers, and the key is in one.
- Until the kit's HC-19 denial test passes, `source` is advisory: say so in any analysis that reads it.
- The instinct step and the model must not hold sessions for the same player at once (see above): an initialize supersedes the other class's session.
- The kit side (HC-L1: the model uid cannot read the key, and the key is not in the model's environment, files or stream) is scriptorium-orchestrator's. This repo does not prove it.
