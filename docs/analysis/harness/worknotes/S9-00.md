## Matcher

A table counts as erased when the comment-stripped text of `sheet_erase_life` plus `register_account_delete` holds `DELETE FROM [public.]<table> WHERE <not false>`. SQL `--` comments are removed first; `WHERE false` does not count.

## Known limits

- Regex over function text: a DELETE in a string literal, dynamic SQL, a `/* */` comment, or a branch that never runs still counts; a trivially true or wrongly keyed WHERE (`WHERE true`, wrong column) counts. The gate proves a delete exists, not that it is correct. The real erase behaviour is asserted by `check-schema-account-delete.sql` (including the S9-00a `turn_records` block, which calls `register_account_delete` on fixture lives) and `check-schema-character-audit.sql` (`sheet_erase_life`); this file adds only a dead-life `sheet_erase_life` case and does not add a new `register_account_delete` call.
- Keys seen: only columns named `life_id` and `agent_id`. Other keys (`other_id`, `thinker_id`, `proposer`, `owner_id`) are invisible to the gate.
- `proposals.proposer` (and `skills.author`, `books.author`, `laws`) are shared world objects kept on purpose (decision 0040); `proposals` has no `life_id`/`agent_id` column, so it is not on the exemption list and the gate cannot see it.
- Exemptions: `agents` (retired in place, row stays as world history). `kino_audit` is keyed by the viewed life; `register_account_delete` deletes it by the viewer's `login_hash`, so the regex finds a delete and the exemption entry is redundant; it stays to document the open owner question (rows of an erased viewed life).
