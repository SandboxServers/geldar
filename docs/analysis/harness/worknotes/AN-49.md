# AN-49 worknote: bilateral conversation exchange and social award keys

Packet: `docs/analysis/harness/work-packets-sheet-w6-w8.md`, section AN-49. Decisions D-CS-04, D-CS-15.

## What shipped

- `eventsink/src/xp/exchange.ts`: `ExchangeTracker`, which wraps `awardsFor` from `awards.ts` and
  adds the speech exchange. `awards.ts`, `projection.ts` and `writer.ts` are untouched.
- `eventsink/src/xp/exchange.test.ts`: 14 tests (two-way, monologue, one-way overheard, same
  speaker, greeting spam, wrong recipient, overlapping windows, two windows, reply after window,
  replay, restart, give in window, LRU bound, malformed payload).
- No SQL, no LLM call. Inert: nothing instantiates `ExchangeTracker`.

## Owner parameter (unmeasured)

`EXCHANGE_WINDOW_TICKS = 600` is PROVISIONAL. It is an owner parameter and has not been measured
against real conversation pacing. The window index in the key is `floor(openTick / 600)`.

## Rules implemented

- The speech schema (`contract/schemas/speech-event.schema.json`) has `from`, `text`, `distance`
  and `own`; `agent_id` is on the WorldEvent envelope. All fields the card names exist.
- The speech payload carries no life id. A non-own line's speaker is resolved from the in-game
  name in `from`, bound to a life by that life's own line (`own: true`). A name never seen
  speaking is ignored.
- A window opens at a pair's first line. It qualifies at the second speaker's first line, heard by
  the opener's Body. Both lives get one `social` award, key `exch:<lifeLow>:<lifeHigh>:<windowIndex>`,
  with lifeLow and lifeHigh in plain string order.
- A repeated line (same text, same speaker, same pair) opens nothing and qualifies nothing.
- A pair idle for two windows is forgotten. Pairs and names are LRU-bounded at 512.
- Limits: state is in memory, so a restart loses open windows and name bindings. The payload has no
  addressee, so a reply heard by a third party does not count for that party.

## Revert-checks (run on the committed files)

Recipe: copy `exchange.ts` to the scratchpad, change one line, run
`corepack pnpm exec vitest run src/xp/exchange.test.ts`, confirm the failure, copy the backup back,
confirm `git diff --stat` is empty.

1. Qualify at the first speaker's line (`pair.qualified = false;` also returns `bothAwards`):
   12 of 14 fail, including "a monologue is not an exchange".
2. Drop the window index (key window becomes `0`): "two windows, two awards with different keys"
   fails.
3. Let a repeated greeting open a window (remove the repeat check): "greeting spam: a repeated
   greeting does not open a window" fails.

## NeoForge

Do not enable on NeoForge until the human-handling question is decided. Speech there is not
proximity-limited (NF-CHAT), so this tracker would award lines the Body could not have heard.
