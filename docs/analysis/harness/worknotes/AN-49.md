## Owner parameter (unmeasured)

`EXCHANGE_WINDOW_TICKS = 600` is PROVISIONAL. It is an owner parameter and has not been measured
against real conversation pacing. The window index in the key is `floor(openTick / 600)`.

## Rules implemented

- The speech schema (`contract/schemas/speech-event.schema.json`) has `from`, `text`, `distance`
  and `own`; `agent_id` is on the WorldEvent envelope. All fields the card names exist.
- The speech payload carries no life id. A non-own line's speaker is resolved from the in-game
  name in `from`, bound to a life by that life's own line (`own: true`). A name never seen
  speaking is ignored. Names are folded with `toLowerCase()` on both the own and the heard side.
- A window opens at a pair's first line. It qualifies at the second speaker's first line, heard by
  the opener's Body. Both lives get one `social` award, key `exch:<lifeLow>:<lifeHigh>:<windowIndex>`,
  with lifeLow and lifeHigh in plain string order. The window index is the opener's window, not
  the reply's.
- A repeated line (same text, same speaker, same pair) opens nothing and qualifies nothing. A
  repeated line refreshes the pair's idle clock, and identical text from either speaker anywhere in
  a warm pair never opens a window.
- A pair idle for two windows (`2 * EXCHANGE_WINDOW_TICKS`) is forgotten. Pairs and names are
  LRU-bounded at 512; a touch of a pair (any line in it) makes it most recent.
- Replay: a redelivered qualifying line (same `source_event_id` as the one that qualified the open
  window) re-emits the same awards with the same keys, so a batch rolled back by the writer and
  redelivered gives the same ledger keys, and the ledger drops the duplicate. Greeting spam has
  different event ids and still does not qualify. Replay after the pair expires is not covered.

## Limits (documented, not fixed)

- State is in memory. A restart loses open windows and name bindings.
- The payload has no addressee, so a reply heard by a third party does not count for that party.
- Ordering: the speaker's own line must reach the sink before the heard line it answers. If the
  heard line arrives first, the name is unbound and the opening line is lost.
- Rebirth: a new life under the same username binds that name to the previous life until the new
  life's own line arrives. Awards in between go to the dead life.
- Tick 0: the Body publishes `world_tick` 0 when the tick is unknown. With all ticks 0 the window
  never expires, so a pair gets exactly one award. The sink must not enable this tracker with a
  Body that cannot report ticks.

## Index for AN-50a

- AN-50a chooses how the sink runs the tracker: a sink-held `ExchangeTracker` called beside
  `awardsFor` in `writer.ts`, or a `case 'speech'` arm. Its `awardsFor(event)` already includes the
  stateless awards, so it replaces `awardsFor` at the call site and does not add to it.

## NeoForge

Do not enable on NeoForge until the human-handling question is decided. Speech there is not
proximity-limited (NF-CHAT), so this tracker would award lines the Body could not have heard.
