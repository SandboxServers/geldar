## What changed

- `contract/schemas/mcp-play.schema.json` (`WaitInput`): optional `peek`, boolean, additive. Its description is neutral and names no class, key or ticket: "Read-only wait: returns events after the cursor without marking them as seen." No default is written into the schema. The rule for who gets it is the server's, not the text's (decisions 0058, 0059, 0068).
- `threshold/mcp/src/tools/wait.ts`:
  - `peekHonoured(source, peek)`: true only when `source === 'instinct'` and `peek === true`. This is the one gate.
  - `WaitRequest.peek`: when true, `wait()` skips `state.open` registration (so it neither replaces nor is replaced), `state.lastWakeMs`, `rememberDelivered`, `failures.observe`, `applyWaitDelta`, and every presence touch and `wantBody` call.
  - A peek on a Body that does not answer still polls to its deadline and returns `body_unavailable`, as a plain wait does. It just never asks for the Body.
  - It still reads the log after the cursor and honours its own signal (`session_superseded`).
- `threshold/mcp/src/world.ts` (`waitTool`): `peek: peekHonoured(ctx.source, input.peek)`. `ctx.source` is set by the server from the verified key check (`connectionSource`, GX-06), never from tool input.
- `threshold/mcp/src/world-session.ts`: `forConnection(tool, source)` removes the `peek` property from the advertised `wait` input schema for every connection that is not the instinct class. The model class's `tools/list` has no `peek` field. The server still validates a sent `peek` against the full bundled contract, so a model's `peek: true` is an ordinary wait, not an error.
- `threshold/mcp-mock/src/sim/wait.ts` (the mock's wait): the same gate inline (`input.peek === true && ctx.source === 'instinct'`). A peek records no suppression and does not set `sim.lastWakeMs`.

## Decisions

- Presence (owner, coordinator): an instinct peek does NOT wake or hold the Body. It does not call `touchPresence` or `wantBody`. A plain wait keeps both. (This reverses the earlier judgment that presence stayed on a peek.)
- Hiding `peek` from the model class: done, because it was small (one function in `world-session.ts`, about 15 lines, and tests). The model class's advertised `wait` input has no `peek`. Its server-side behaviour is unchanged: a sent `peek` is validated against the full contract and then ignored, so it is a plain wait. No error text names the class.
- The peek does not register as an open wait, so a later model wait cannot end it early (`wait_replaced`). It ends on its own deadline or its signal.
- A peek with no cursor starts from the delivered mark (a read only).
- The failure memory (`failures.observe`) is not fed by a peek: a peek must not advance what the repeated-failure memory has seen.

## Model class

A model connection that sends `peek: true` gets `peekHonoured('model', true) === false`, so the request is an ordinary wait: same fields, same code path, same timing. Its advertised `wait` schema has no `peek` field. No error text names the class (0059, 0068). The GX-06 header check is unchanged.

## Tests

- `threshold/mcp/src/tools/wait-peek.test.ts` (unit, `wait()` directly):
  - gate: `peekHonoured` is true only for instinct with peek true.
  - plain wait (the model case): advances the delivered mark, sets `lastWakeMs`, records `sent` for session `s1` (delta on for every life), replaces an open wait, and calls `failures.observe`.
  - instinct peek: returns the events after the cursor; `delivered`, `lastWakeMs`, `sent` and `open` are unchanged against a plain wait made first; `failures.observe` is not called.
  - in flight: a peek is not in `state.open` while it waits.
  - a cursor at the head returns no earlier event and leaves the mark alone.
  - an open model wait is not replaced by a peek, and runs to its own end.
  - presence: a peek on a down Body calls neither `touchPresence` nor `wantBody` and ends `body_unavailable` at its deadline; a plain wait on a down Body calls both and ends the same way.
  - Removed as not differential: the old "superseded session" test (a plain wait ends the same way, with no state moved, so there was no differing counterpart) and the old "Body down" test (replaced by the presence pair).
- `threshold/mcp/src/instinct-door.test.ts` (door, real keys, fake clock):
  - `a model peek is an ordinary wait; an instinct peek never ends a model wait`: a model wait of 60 s is open; an instinct peek of 5 s returns at 5 s and the model wait is still open; a second model connection's `peek: true` replaces the model wait (`wait_replaced`), and returns the same field set as the instinct peek.
  - `the model is not advertised the wait peek field; the instinct class is`: `tools/list` for `wait` on each class.
  - The door test file now has about 510 lines (soft cap 500).
- `threshold/mcp-mock/src/sim/wait.test.ts`: an instinct peek leaves `lastWakeMs` (null) and `suppressedSeqs` (empty) and records no suppression; a plain wait (no class) records all three.
- `contract/test/wait-peek.test.ts`: `peek: true` and `false` validate; a plain wait validates; a non-boolean `peek` fails. New: no `mcpToolSchemas` input property description contains `instinct`, `key`, `keyed` or `GX-` (scan does not follow `$ref`), and the scan itself is checked.
