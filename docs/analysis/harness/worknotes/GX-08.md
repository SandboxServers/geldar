# GX-08 worknote: non-advancing wait (`peek`) for the instinct class (world)

Status: the server gate, the mock and the contract slot are in this commit. The contract output is NOT regenerated in this worktree (no `node_modules`), so the generated files must be regenerated by ops before `check:generated`, the generated-type use in `world.ts` and `sim/wait.ts`, and the new contract test can pass. See "Generated output" below.

## What changed

- `contract/schemas/mcp-play.schema.json` (`WaitInput`): optional `peek`, boolean, additive. The description says it is honoured only for the instinct class (GX-06 keyed connection), is ignored otherwise, and defaults to false. No default is written into the schema.
- `threshold/mcp/src/tools/wait.ts`:
  - `peekHonoured(source, peek)`: true only when `source === 'instinct'` and `peek === true`. This is the one gate.
  - `WaitRequest.peek`: when true, `wait()` skips `state.open` registration (so it neither replaces nor is replaced), `state.lastWakeMs`, `rememberDelivered`, `failures.observe` and `applyWaitDelta`. It still reads the log after the cursor, honours its own signal (`session_superseded`), and returns the same result shape.
- `threshold/mcp/src/world.ts` (`waitTool`): `peek: peekHonoured(ctx.source, input.peek)`. `ctx.source` is set by the server from the verified key check (`connectionSource`, GX-06), never from tool input.
- `threshold/mcp-mock/src/sim/wait.ts` (the mock's wait; `registry.ts` needed no change, it already carries `ToolContext.source`): the same gate inline (`input.peek === true && ctx.source === 'instinct'`). A peek records no suppression and does not set `sim.lastWakeMs`.

## Deliberately kept (judgment calls, flag to the owner)

- `touchPresence` and `wantBody` still run on a peek. Presence is Body liveness, not delivered state; skipping it would change the Body's awake behaviour. The spec's "no side effects" is read as the four listed items plus the failure memory and the wait-delta mark.
- The peek does not register as an open wait, so a later model wait cannot end it early (`wait_replaced`). It ends on its own deadline or its signal.
- A peek with no cursor starts from the delivered mark (a read only). It is still "after the cursor" in the sense that a cursor is what the caller sends.

## Model class

A model connection that sends `peek: true` gets `peekHonoured('model', true) === false`, so the request is an ordinary wait: same fields, same code path, same timing. No error text names the class (0059, 0068). The default and the model wait semantics are unchanged; the GX-06 header check is unchanged.

## Tests (new files, nothing existing edited)

- `threshold/mcp/src/tools/wait-peek.test.ts`:
  - gate: `peekHonoured` is true only for instinct with peek true (model, no class, instinct with false or absent are false).
  - (a) plain wait (the model case): advances the delivered mark, sets `lastWakeMs`, replaces an open wait.
  - (b) instinct peek: returns events after the cursor (seq 1 after `c_0`, cursor `c_1`); leaves `delivered`, `lastWakeMs`, `open` and `sent` empty.
  - cursor at the head returns no earlier event and leaves the mark alone.
  - an open model wait is not replaced by a peek, and runs to its own timeout.
  - a superseded session still ends a peek with `session_superseded`.
  - a Body that goes down ends a peek with `body_unavailable` and moves no state.
- `contract/test/wait-peek.test.ts`: `peek: true` and `false` validate; a plain wait validates; `peek` as `'yes'`, `1` or `null` fails. (d).
