## Target shape

`contract/src/index.ts` becomes about 80 lines: the module comment, then `export * from './<domain>.ts';` lines (type re-exports use `export type * from` where a file only re-exports types), plus the few exports that are already one-liners. Each domain file holds its blocks verbatim: the local `import`s of `./generated/validators.js` and `./validation.ts`, the `validateX` functions and the `export type { ... }` lines. Nothing changes inside a block.

New files: `core-records.ts`, `perception-events.ts`, `world-tool-inputs.ts`, `thinker.ts`, `mind-channel.ts`, `sovereign.ts`, `character.ts`, `proficiency.ts`, `turn-record.ts` (each well under 150 lines).

Rule for later cards: a card adds its exports to its own domain file (or a new domain file), never to `index.ts` beyond one `export * from` line. Put that sentence in the work-packets dispatch rules.

## Packets

**CS-0 public-surface golden (tiny, first, merges alone).** Add `contract/test/public-surface.test.ts`: it imports `@geldar/contract` and compares `Object.keys(ns).sort()` with a committed `contract/test/public-surface.golden.json` (runtime exports) and checks a list of type names compiles by a `tsc` fixture (`contract/test/public-types.check.ts`, a `satisfies`-style file listing every currently exported type as `import type { A, B, ... }`; generated by a one-off script, committed). Revert-check: delete one export from `index.ts` and the golden fails. This pins the surface before the move so the move can be proven pure. May-edit: the three new test files and a worknote. About 20k.

Exit: `index.ts` under 120 lines, every new file under 200, surface test unchanged and green, `check:generated` clean, `check:repo` clean. About 40k; split in two coders at the thinker block if the first runs out. Revert-check: the golden test (a dropped re-export line fails it).

**CS-2 split `contract/test/mcp-world.test.ts` (518 lines).** It has four `describe` blocks (coverage 376, rows 404, no drift 426, descriptions 495). Move the "no drift from the Action schema" block with its helpers to `mcp-world-drift.test.ts` and keep the other three; shared fixtures go to a named file `mcp-world-fixtures.ts` only if two files need them (named for its content, not `helpers`). ## Order and gates

1. CS-0 merges. 2. CS-1 merges (it changes only `contract/`; CI drift check and the repo-wide typecheck are the gate). 3. CS-2 any time. Only after CS-1 merges may another contract card start (AN-47b, AN-45a/b, S9-01). Contract regeneration slots are untouched; this plan neither takes nor needs one.

## Risks

- `export *` hides a name clash between two blocks: CS-1 stops on it. Today a clash would already fail `tsc` in `index.ts`, so none exists.
- Type-only blocks need `export type`: the surface check file catches a dropped type export.
- A consumer deep-importing `contract/src/index.ts` internals: none found by the surface test, but CS-1 runs `tsc` across all consumers.
- Merge conflicts with an in-flight contract card: none in flight now (AN-46b merged); do not run CS-1 while any other branch edits `contract/src/index.ts`.
