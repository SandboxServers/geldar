# P1-C1-06b worknote: component NATS credentials

Card: `docs/analysis/phase1/packets/c1-packets.md`, "Card C1-06b". Decision 0087 is cited, not added (shared with C1-06a). The card names the worknote `C1-06b.md`; this file is `P1-C1-06b.md`, as the C1-06a worknote is `P1-C1-06a.md`.

## What was built

Each component reads `GELDAR_NATS_USER` and `GELDAR_NATS_PASSWORD_FILE` (decision 0067) through the shared `natsAuth` in `contract/src/nats-connect.ts`. The TypeScript components add a thin per-package wrapper that supplies the role default when only the password file is set. The Java side reads the same two names in its own `withCredentials` method.

Commits on `phase1/c1-06b-nats-creds`: 08222a1 (golem), b5ef54c (animus), 9f159fe (eventsink), 522b3c6 (MCP), then the CoreConfig javadoc fix.

Before this packet, each TypeScript connect call passed no `user` or `pass`. Every connection was anonymous.

The TypeScript tests (per package) cover: undefined when neither variable is set; the role default with a trimmed file password; no user or password passed when neither is set; `GELDAR_NATS_USER` overriding the role; a missing file naming the variable and path; a user without a file naming `GELDAR_NATS_PASSWORD_FILE`; an empty file.

The Java tests cover the same rules, including `failsOnAMissingPasswordFileWithoutEchoingAnything` and `failsOnAnEmptyPasswordFile`.

## Java and Velocity findings

- Both Java readers already supported the two names on main, with tests. No code change was needed.
- No per-role default was added for Paper or Velocity. The existing tests expect a password file without a user to fail (the password-only case in `NatsEventPublisherTest` and `RegistryClientTest`). A default user would make that case connect instead of fail, so the default would contradict a test that must not be weakened.
- The overlay sets `GELDAR_NATS_USER` for Paper and Velocity (`compose/nats-auth.yml`). It also sets it for `eventsink` and `mcp` in the same file. The overlay is therefore not limited to Paper and Velocity as the card's wording suggests.
