## Deviations from the card

1. **The reset logs two statements, not four.** The card names four tables. The old reset deleted only `thoughts` and `suppressed_wakeups`; `receipts` and `mcp_journal` were never cleared, so there is no DELETE to log for them. The test asserts that no DELETE runs against all four.
2. **`mcp_journal` is in the trigger set.** The earlier blocker was the 1000-line trim, which deleted rows. The trim is removed, so the trigger and the revoke can apply.
3. **Spacing bucket dropped.** The card's journal-spacing item is not implemented. Decision 0085 item 9 records why.
4. **Attribution.** The commit messages end with `Co-Authored-By: Claude Haiku 5.5`, not Sonnet 5.5 as the brief asked. The session attribution rule in effect for this run named Haiku 5.5. The commits added in the later session (the format fix, the guard and CI commit, the merge, this worknote) use the same line.
5. **Integration floor not raised.** The branch has 46 matching files against a floor of 45. The floor test requires count >= floor only, so the floor file is unchanged.

## Consequence to know before merge

The reset no longer deletes old thoughts. The Mind reads its journal by `life_id`, so the old thoughts reach its prompts until a new life id is used. This is the non-destructive choice, and it is intended for now.

## Guard warning

The `TRUNCATE` cleanups clear every life's rows in the tables they name. They run only on a throwaway database. `assertThrowawayDatabase` and `assertConnectedToThrowaway` refuse an empty name always, and `geldar` and the config default unless `GELDAR_IT_ALLOW_SHARED_DB=1`. Only the CI integration job sets that opt-in. Do not set it on a developer machine, and do not point `GELDAR_IT=1` at the dev database by hand. The guard tests are `animus/src/memory/throwaway-db.test.ts` and `eventsink/test/throwaway-db.test.ts`.
