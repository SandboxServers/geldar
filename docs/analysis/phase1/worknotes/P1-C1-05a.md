## Why the packet stopped

The card's may-edit list does not cover the code the rule has to change. Four conflicts, each checked against the tree at `774af5b`:

1. **Existing integration tests delete rows that the triggers would refuse.** The card's migration refuses `DELETE` and `UPDATE` on journal and receipt tables. Two tests outside the may-edit list delete those rows in cleanup:
   - `eventsink/test/projection.it.test.ts:191` runs `DELETE FROM receipts WHERE action_id = $1`.
   - `animus/src/memory/memory.it.test.ts:66-67` runs `DELETE FROM suppressed_wakeups` and `DELETE FROM thoughts` for the test life.
   With the triggers in place, both fail in the CI `integration` job. Fixing them needs edits to `eventsink/test/` and `animus/src/memory/`, which the card does not list.

2. **`mcp_journal` cannot take a DELETE refusal as the card states.** `threshold/mcp/src/store/pg-journal.ts` (`APPEND_SQL`) inserts a line and deletes the life's older lines in one statement, to keep 1000 lines per life. Migration 0003 and 0004 grant DELETE on this table by design. A DELETE refusal on `mcp_journal` would make every append fail. `threshold/mcp/` is not in the may-edit list, so this table is not in the trigger set of this packet.

3. **`thoughts` is written with an upsert.** `animus/src/memory/journal.ts:22` is `INSERT ... ON CONFLICT (thought_id) DO UPDATE`. An UPDATE refusal turns a repeat write of the same thought into an error. The write path is in `animus/`, outside the may-edit list.

4. **The reset cannot create a new shard without code outside the may-edit list.** There is no shard table in `sql/` and no shard column in the journal tables. The Mind reads its journal by `life_id` (`ag_adam_02`, from `golem/test/live/adam-stack.ts`). A new shard id only isolates the history if the Mind's reads filter on it, and those reads are in `animus/`. The reset in `golem/test/live/adam-reset.ts` runs `DELETE FROM` on `suppressed_wakeups`, `memories`, `goals`, `relationships` and `thoughts`. Replacing those deletes is in scope. Making the Mind see only the new shard is not.

Two smaller points:

- **Which tables are journals.** The card says "each journal and receipt table". Decision 0064 item 5 calls journals "append-only evidence". The reset docstring calls `suppressed_wakeups`, `memories`, `goals`, `relationships` and `thoughts` the journal tables. `memories`, `goals` and `relationships` are mutated state: `animus/src/memory/pg-memory-store.ts` updates `memories` (`active = false`, `resolved = true`, `embedding`) and deletes and reinserts `goals`. Making those three append-only would break the memory store. Proposed set for the owner to confirm: `receipts`, `suppressed_wakeups`, `thoughts`, plus `mcp_journal` if its trim is moved out of the packet's way.

- **Spacing bucket not located.** `grep -rn "spacing\|bucket"` finds the attention controller's `minWakeupSpacingS` (`animus/src/attention/controller.ts`, default 20 s, already read from config). That spacing defers wakes; it does not bucket journal writes. The `recorded` flag in `animus/src/attention/coalesce.ts:62` is the nearest journal-side dedupe. Which of these the card means is for the owner to say, and the code is in `animus/`, outside the may-edit list.

## What the packet needs from the owner

1. Confirm the table set for the triggers (see point above), and whether `mcp_journal` is in or out.
2. Either add `eventsink/test/projection.it.test.ts` and `animus/src/memory/memory.it.test.ts` and `animus/src/memory/journal.ts` to the may-edit list, or move the append-only rule to a later packet.
3. Name the shard concept: a new column or a new journal partition, and which package reads it. Until that is named, the reset's "new shard id" has no effect on what the Mind reads.
4. Name the spacing bucket: which journal write it guards, and the default with its reason (the default is recorded here once known).
