# C7-06 worknote: account page v2

## C7-06b (follow-up, same branch)

- Wired the HTML error pages (`threshold/register/src/errors.ts`) into `server.ts` for the page routes: the kill switch
  (503), the source limit (429), the sign-in window (429) and an unknown page (404). The `/api/` branch is unchanged and
  keeps problem JSON. The order is kill switch, source limit, router, as before.
- `account.ts`: the owner window 429 on account POSTs and the banned-owner 403 now answer the HTML pages.
- Visibility fields: `PlayerRow` gains `publicCamera` and `thoughtsDelayedPublic`. `PgStore.listPlayers` reads the
  flags from `register_owner_list_players` (migration 0036), keyed by the owner id found from the identity hash.
  `register_list_players` (0012) has no flags, and 0036's function has no harness column, so both calls are needed.
  No SQL was added or changed.
- Glass and Kino links on the account page: "View in Glass" (`/`) when `thoughtsDelayedPublic` is on, "View in Kino"
  (`/kino/`) when `publicCamera` is on. The links carry no agent id. This is a reading of 0138 and 0139 that needs an
  owner ruling (see below).

## Open items and findings

- Card path mismatch: the card names `threshold/register/src/pages/account*.ts`, `src/static/account.css` and
  `src/pages/errors.ts`. None of those directories exist. The code lives in `src/account-pages.ts`, `src/account.ts`,
  `src/account-style.ts` (a TS constant, so no static copy step) and `src/errors.ts`.
- Glass has no per-agent deep link (no agent parameter in `glass/web`), so both links open the view root. Kino exists only
  when `GELDAR_KINO_ENABLED` is on (`deploy/caddy/glass.caddy`). The register does not know that flag, so the Kino link can
  lead to a 404 on a host where Kino is off.
- The card's Glass rule ("absent when the visibility does not allow it, 0138") is read here as: the link shows only when
  `thoughtsDelayedPublic` is on. Glass 0020 always lets the owner see their own agent, so an owner ruling is needed.
- Visibility toggles: kept as the existing form POSTs to `/register/players/{id}/public-camera` and `/public-thoughts`.
  The card says the toggles call `PATCH /agents/{playerId}` (C7-04e). That was not done in this packet.
- Not shown, because there is no data: body state, credits left, token expiry and last used. No renewal is claimed.
- The account view's `listPlayers` now runs two queries. The flag query has no unit test against Postgres (the fake
  store returns the flags it is given), so the join path is covered only by review and a live run.
