heap (6G) plus 1 GiB.

### Wiring decisions

- Players host profile `sovereign`: `players-host` starts only with `docker compose --profile sovereign up`,
  so a node without a sovereign ranger runs no player process.
- One process per player: `main.ts` runs one ranger (`--player <id>`). The compose service passes the id from
  `GELDAR_PLAYER_ID`, so one `players-host` container serves one ranger per `docker compose --profile sovereign up`.
  The id must be a `sovereign.players` entry of `shards/colo-mind.yaml`. The compose comment says the presence
  record starts and stops the process; that per-ranger lifecycle is not built yet (see FOLLOW-UPS).
- MCP NATS wiring inside `colo.yml`: `geldar-mcp` connects as NATS user `mcp` through the `nats-mcp` secret
  (`GELDAR_NATS_PASSWORD_FILE: /run/secrets/nats-mcp.txt`), not as a shared user. `nats-mcp` is in the
  top-level secrets block and in `geldar.ps1`'s NATS secret check.
- In-network RCON host: `players-host` uses `GELDAR_RCON_HOST: paper` with `GELDAR_IN_NETWORK_HOSTS=1`. The
  check is in `golem/src/config.ts`: any other host is refused.

### The MCP publish job

`.github/workflows/colo-images.yml` has a fourth image job, `mcp`, with the same pattern as body, mind and
eventsink:

- Builds `threshold/mcp/Dockerfile` from the repo root and pushes `ghcr.io/sandboxservers/geldar-mcp` with
  tags `:main` and `:<sha12>`. Provenance and SBOM off. The digest is the `mcp` job output.
- `packages: write` only on the four image jobs. Each has the upstream-repository guard. The actions are
  pinned by the SHAs already in the file.
- The `manifest` job needs `mcp`, validates four digests, and writes `GELDAR_MCP_IMAGE=ghcr.io/sandboxservers/geldar-mcp@sha256:...`
  as a fourth line of `release.env`. `deploy/release.env.example` carries a placeholder with the same key.
- `paths:` gained `threshold/mcp/**`, `shards/phase0.yaml` and `tools/repo-checks/src/identity-mode.ts`. The
  last two are added because the MCP image copies them (its `Dockerfile.dockerignore` re-includes them).
- Image hygiene checked, not changed: the MCP Dockerfile runs as `1000:1000`, every `FROM` is digest-pinned,
  and `threshold/mcp/Dockerfile.dockerignore` excludes `**/.env*`, `**/secrets` and `**/*tokens*.json`.
- `deploy/common.sh` `load_release` has no fixed key list (it accepts any `*_IMAGE` digest reference), so
  it needed no change. `deploy/test/colo-deploy.test.ts` uses its own two-line fixture and needed no change.
- `compose/colo.yml` `geldar-mcp` already reads `image: ${GELDAR_MCP_IMAGE:-geldar-mcp:c1}`.
- `tools/repo-checks/src/first-party-images.json` prefix `ghcr.io/sandboxservers/geldar-` already covers it.
