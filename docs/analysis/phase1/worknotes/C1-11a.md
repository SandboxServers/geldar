# C1-11a worknote: sovereign services on the colo stack

## Finisher 1

What was done, on `feat/colo-sovereign-services`:

- `compose/colo.yml` gained two services, both under the `sovereign` profile except where noted.
  - `geldar-mcp` (threshold/mcp): the only published port is `127.0.0.1:8788`, a literal (the loopback
    rule rejects interpolation). Read-only root, `cap_drop: ALL`, `no-new-privileges`, budget 0.5 CPU,
    512m, 128 pids. NATS as the `mcp` user through the `nats-mcp` secret. Postgres password and token
    pepper are file secrets. The Mind's shard file is mounted as `shards/colo.yaml`.
  - `players-host` (golem/src/players/main.ts): the Body image, `--player ${GELDAR_PLAYER_ID:-}`, budget
    1 CPU, 2048m, 256 pids, no published port. RCON reaches Paper through `GELDAR_RCON_HOST: paper`.
- `shards/colo-mind.yaml` gained the `sovereign` block with `players: []`. `shards/colo.yaml` totals are
  9 CPU and 18944m, the sum of the per-service budgets.
- `geldar.ps1`: `Assert-ColoNatsSecrets` also requires `nats-mcp.txt`.
- `golem/src/config.ts`: `GELDAR_RCON_HOST` is honoured through `hostAllowed`. Unset or empty means
  `127.0.0.1`. The closed in-network list is accepted only with `GELDAR_IN_NETWORK_HOSTS=1`. Any other
  host is refused. The previous hard-coded `127.0.0.1` was a defect: the players host cannot reach
  Paper's RCON inside the compose network without it.
