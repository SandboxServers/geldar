## Item 2: compose/colo.yml

- Standalone file, `name: geldar-colo`, own network `geldar-colo` (explicit `name:`). Services: postgres, nats, paper, velocity, eventsink, the same images and digests as phase0.yml (already in the release-age list through the Phase 0 pins).
- Every published port is `127.0.0.1:` and literal. The Minecraft bot ingress is `127.0.0.1:25567:25565`: the brief says the node never binds 25565 (the production game server) or 25566, so the host port is 25567. shards/colo.yaml sets `minecraft_port: 25567` to match, and geldar.ps1 refuses a different value.
- `deploy.resources.limits` on every service through one anchor (`x-limits`). The values come from `GELDAR_COLO_CPU_LIMIT` and `GELDAR_COLO_MEMORY_LIMIT`, which geldar.ps1 sets from shards/colo.yaml. The defaults in the file (4 and 8g) equal the first guess, so the offline config works.
- Deviation: the shard-config contract declares one CPU and one memory budget. Each service's ceiling is that budget, not a split. A split needs a contract change (C1-00 owner) or measurement in C1-10.
- Paper heap `MEMORY: 6G` is a literal first guess below the 8g default limit. Not from the contract.
- Slots at the end of the file are comments, one per later packet (C1-03 golem-body, C1-06a nats-auth, C1-07 metrics, C1-09 bluemap).
- `docker compose -f compose/colo.yml config --quiet`: exit 0.
