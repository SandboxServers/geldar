# C7-14b worknote: owner admin verbs and idempotent owner-add

## Where the list-before-set check lives

The card asked the wrapper tests to record the calls: `owner admin list` before `owner admin set`, and no
second `set` after a re-run. The wrappers (`deploy/colo-admin.sh`, `tools/admin/admin.sh`) pass the verb
through to the CLI, so a recorded-calls test at that level cannot see the list call. The check therefore
lives in the CLI: `runOwnerAdmin` in `tools/mcp-tokens/src/owner-admin.ts` reads `listOwnerAdmins` first and
writes nothing (no UPDATE, no audit row) when the flag already has the requested value. The CLI tests in
`owner-admin.test.ts` cover this: the set-twice case, the unset-twice case, an unknown owner on a no-op
request, and the audit row written only on a real change. This placement is accepted (review 04c2, note 3).

## Races (accepted, single operator)

- Two operators must not run `owner-admin set` or `unset` for the same owner at the same time. The list
  check runs outside the transaction in `setOwnerAdmin`, so two concurrent runs can both see the flag
  unset and each write an `admin_set` audit row. The UPDATE itself is one statement, so the flag is never
  half-set.
- `owner-add` reads the row, then inserts it. Two concurrent adds for one id can both pass the read; the
  loser fails on the primary key and exits non-zero with the database error. It is visible, not masked.

## Hardening from the review

- `roster_owner_ok` in `deploy/colo-admin.sh` also refuses a leading `-`, so `-x` and `--dry-run` do not
  reach the container. It is the one id rule for `owner-admin`, `roster-add`, `roster-list` and
  `owner-set-cap`; the CLI's `OWNER_ID` rule already refused a leading dash.
- `player-flags` checks its `ag-` id with a case pattern (`player_flags_id_ok`), not a line-based grep, so a
  newline or a space in the id is refused by the wrapper as well as by the CLI.
- `tools/admin/admin.sh` has no id check of its own; the CLI refuses a bad id before any database call.
- The owner-admin and player-flags tests live in `deploy/test/colo-admin-flags.test.ts`; the shared harness is in
  `deploy/test/colo-admin-fixture.ts`. The two newline rows pass their id through the environment, not argv, because
  MSYS sh on Windows splits an argument at a newline.
