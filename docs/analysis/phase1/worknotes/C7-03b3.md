# C7-03b3: supervisor Postgres and Docker adapters (worknote)

Carry-forward from C7-03a (see `C7-03a.md`).

- Exact-case login name: done through migration 0033, `supervisor_player_display_name(owner, name)`.
  It is a SECURITY DEFINER function, executable by `geldar_supervisor` only, with a pinned
  search_path. The supervisor role gets no SELECT on `mcp_players`. It returns the exact display name
  of the owner's non-retired players whose name matches the roster name in any case, when they agree on
  one spelling; otherwise NULL. A NULL refuses the start (`login name unknown`), before any container
  call. The Docker runtime passes the name to the container as `GELDAR_LOGIN_NAME`; the container name
  stays lower-cased. Gap: the Body image (golem) does not read `GELDAR_LOGIN_NAME` yet. It takes its
  username from the shard file, so the env is the contract for a later golem change.
- Log read: the Docker logs are not used. The log read uses `body_ops` (the supervisor's own start rows,
  bounded to the roster record), as in `pgLogs`.
- Stop by name: the gap stays documented. `runtime.stop(name)` still addresses the container by its
  lower-cased name; a name shared with a newer attempt can be stopped by name. Removal is by id only.
- Dependency: `pg` 8.23.1 is pinned in `supervisor/package.json` (exact version, as the orchestrator set).
- Verification: supervisor tests (88 pass), typecheck, format, lint. Real Postgres: a throwaway
  pgvector image, all migrations 0001 to 0033 applied, every check file in ci.yml order passes. The new
  check fails when the PUBLIC revoke is removed. No other real-Postgres adapter run.
- Live: pending (the orchestrator runs the live lane).
- Review fix I (wave 2 review, notes 5 to 8 and 10):
  - Ctl subject binding: `CtlMsg` carries its subject; an op that does not match its subject is refused
    `invalid` before the handler runs. In-flight cap: `CTL_IN_FLIGHT_CAP` = 16; the 17th request gets
    `busy`. A throwing subscription counts as `subscribeFailed` and `serveCtl` resolves.
  - Body container hardening (docker.ts, limits.ts, ports.ts): PidsLimit 256, NetworkMode `geldar-colo`,
    User `1000:1000`, LogConfig json-file 10m x 3, CapDrop ALL, no-new-privileges. Pinned by literal in
    `docker-hardening.test.ts`. Deviation: `golem-body` in `compose/colo.yml` sets neither CapDrop nor
    no-new-privileges, so the Body container is stricter than its compose service (per ruling). The User
    literal is not read from compose (the supervisor reads no compose env); it must match the
    players-host service user in `compose/colo.yml`.
  - Engine timeouts: every Engine call has a 30 s timeout (`ENGINE_TIMEOUT_MS`). Post-abort and failure
    removes are bounded by `AbortSignal.timeout(cleanupMs)`, 10 s.
  - Login name: the name must match `^[A-Za-z0-9_]{3,16}$`, else `login name unknown`, before any engine
    call.
  - Test split: the allowed-helper test moved to `tools/repo-checks/src/nats-auth-ctl.test.ts`; a new
    `ci-schema-wiring.test.ts` checks that all ten check files are wired in ci.yml.
  - Docs: the real hostname in `c7d-packets.md` is replaced with `glass.example.invalid`; the C7-04c card
    says the login-name error body must tell the owner why.
  - Unmirrored container flags (not yet in the C7-03b2 contract): read-only root filesystem, tmpfs
    mounts, labels, restart policy. C7-03b2 must mirror these or record them as deliberate gaps.
  - Carry-forward: invalid-JSON requests are counted, not audited.
