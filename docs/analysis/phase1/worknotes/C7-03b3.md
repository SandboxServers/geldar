# C7-03b3: supervisor Postgres and Docker adapters (worknote)

Carry-forward from C7-03a (see `C7-03a.md`).

- Exact-case login name: done through migration 0033, `supervisor_player_display_name(owner, name)`.
  It is a SECURITY DEFINER function, executable by `geldar_supervisor` only, with a pinned
  search_path. The supervisor role gets no SELECT on `mcp_players`. It returns the exact display name
  of the owner's non-retired players whose name matches the roster name in any case, when they agree on
  one spelling; otherwise NULL. A NULL refuses the start (`login name unknown`), before any container
  call. The Docker runtime passes the name to the container as `GELDAR_LOGIN_NAME`; the container name
  stays lower-cased. Gap: the Body image (golem) does not read `GELDAR_LOGIN_NAME` yet. It takes its
  username from the shard file, so the env is the contract for a later golem change.
- Log read: the Docker logs are not used. The log read uses `body_ops` (the supervisor's own start rows,
  bounded to the roster record), as in `pgLogs`.
- Stop by name: the gap stays documented. `runtime.stop(name)` still addresses the container by its
  lower-cased name; a name shared with a newer attempt can be stopped by name. Removal is by id only.
- Dependency: `pg` 8.23.1 is pinned in `supervisor/package.json` (exact version, as the orchestrator set).
- Verification: supervisor tests (88 pass), typecheck, format, lint. Real Postgres: a throwaway
  pgvector image, all migrations 0001 to 0033 applied, every check file in ci.yml order passes. The new
  check fails when the PUBLIC revoke is removed. No other real-Postgres adapter run.
- Live: pending (the orchestrator runs the live lane).
