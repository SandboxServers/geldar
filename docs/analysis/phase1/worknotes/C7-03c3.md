# C7-03c3: the supervisor controls Bodies through the helper

Decision 0260. The supervisor holds no Docker socket. `supervisor/src/helper-client.ts` sends the helper's four verbs
(`start`, `stop`, `status`, `logtail`) as NATS requests on `geldar.<shard>.helper.body.<verb>`, with the verb, the roster
name and the owner, and nothing else. The Docker adapter (`docker.ts`) and its test leave the supervisor. The container
config test moves to `body-helper/`.

## Reply mapping (step 4)

Each helper reply reaches the register as one fixed code. The raw helper text never reaches the reply. Tested in
`supervisor/src/service-helper.test.ts` over the real helper client.

| Helper reply | Register code | Row | Compensating stop |
| --- | --- | --- | --- |
| login display name missing or outside `^[A-Za-z0-9_]{3,16}$` | `login_name` | none | none (helper not called) |
| roster refusal, or any `refused` other than "already running" | `unknown` | none | none (helper refused) |
| `refused` with "already running" | `busy` | none | none (helper refused; the running body stays) |
| `capacity` (global cap) | `error` (audited `error`, 503) | none | none (helper refused) |
| `timeout` (client 20 s; service backstop 25 s) | `error` | none | yes: the start may have landed |
| `unavailable` (no responders, closed link) | `error` | none | yes |
| `failed` (helper failure, unreadable reply, unknown state) | `error` | none | yes |

A start the helper refused created and started nothing, so a stop after it would stop a body this call did not start.
Only a start whose outcome is unknown is compensated (`startNotMade` in `supervisor/src/service.ts`).

A timed-out start may still land in the helper: the register must read `status` before retrying. A timed-out start
leaves no row, so it does not count; the helper's own 120 s deadline removes what it made, but it may land first.

Stop: a `not_running` reply counts as stopped.

## Findings

- A display name that is bad for an owner off the roster now answers `login_name` instead of `unknown`. The login check
  runs before the roster-owned check fires (accepted).
- The helper client builds `inspect`'s `ownerId` from the request, so the service's foreign-owner checks on `inspect`
  never see another owner's id. The helper's owner-and-name roster check is the only guard for that path. Follow-up:
  carry the owner the helper reports, and let the service check it.
- The client ignores the abort signal the service passes to `start`. Accepted: the compensating stop covers a start that
  is still running when the caller gives up.
- `supervisor/src/limits.ts` constants are kept, as the brief directs.

## Review pass 1 (fixes to the review of c67051ed)

- Owner: the helper's `status` reply carries `owner`, the label owner (`geldar.owner`). `stop`, `status` and `logtail` act on a helper Body whose label equals the request owner; no roster row is needed (decision 0108). A Body labelled for another owner is refused `not your body`. `start` refuses a Body labelled for another owner with `name in use by another owner's body`. Finding 1 (stop after a roster move) is resolved by this, with the supervisor's own check behind it.
- Finding 2 resolved: `inspect` returns the owner the helper holds (`reply.owner`), not the request's owner, so the service's foreign-owner checks apply. A status reply with no owner is `failed`.
- Mappings (the exact helper strings, held once in `supervisor/src/helper-client.ts` as `HELPER_REFUSAL_TEXT`): `already running` and `name in use by another owner's body` are `busy`; `not your body` and every other refusal (`not on roster`, the name-taken string) are `unknown`. Capacity, timeout, unreachable and failed stay `error`. Raw helper text is never passed on.
- Fix 7: `act()` checks the roster owner before the login name. A name the caller does not hold is `unknown`; a held name with a bad login is `login_name`. No helper call happens in either case.
- Fix 5: the default client bound is 20 s (tests with fake timers: no reply at 19.9 s, timeout at 20 s); no timer is pending after a fast reply.
- Fix 6: the guard test scans `supervisor/src` recursively, matches `from`, `import()` and `require()` specifiers (`dockerode`, `docker-modem`, local `docker*` modules), and asserts that `supervisor/package.json` has no Docker dependency. The compose bind test (no docker.sock in compose/colo.yml) belongs to C7-03b2.
- Fix 9: the C7-03b5 card now requires `nc.request(subject, payload, { timeout })` and the shard from config.
- Accepted: logtail still reads the database event log, not the helper's `logtail`, so raw container log text never reaches the owner. The client never sends `logtail`. A `failed` start is compensated by name (accepted in review). Review finding 8 (a mixed-case name test in body-helper) is not in this pass.
