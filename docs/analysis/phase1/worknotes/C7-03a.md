# C7-03a worknote: supervisor agent binding, roster scoping, audit and failure handling

Wave C7-1 fix B (review fix notes 2, 6, 7, 8). Code: `supervisor/src/service.ts`.

## Rulings recorded

- Ruling (a), orchestrator: bodies are keyed on the roster player name, not on `agentId`. The control request no longer carries `agentId`. The roster owner of the name must match the caller on start, restart, status and logtail; stop checks the record owner (fix D). A repeat start by the owner returns `started` and counts nothing.
- Enforcement scope: `max_agents` above 1 is enforced only at `player add`. The supervisor runs one body per roster name, so one agent has at most one running body (Q3: 1 running body per agent).
- C7-03b's adapter must key containers on the player name, not on an agent id, so that the supervisor's one-body-per-name rule holds in Docker.
- Ruling (b), orchestrator: the admin check goes through `supervisor_is_admin` (added by the fix-A coder in migration 0027). That function is on this branch (migration 0027). This branch has no Postgres adapter, so the supervisor cannot call it yet. Once the adapter exists, the admin check must call `supervisor_is_admin` and not read a local flag.

## Failure handling

- A runtime call is bounded by `runtimeTimeoutMs` (default 15 s).
- A failed `starts.insert` stops the started body, replies `error`, and audits `error`. No body runs uncounted.
- `status` and `logtail` are not audited.
- An audit failure after an `ok` reply returns the reply.

## Review fix D (orchestrator rulings, review pass 2)

- A removed roster name's body is still stoppable by its owner. The stop checks that the caller owns the record, not that the name is still on the roster (F6). A removed name cannot start again.
- The `uncounted` set holds names whose body may still run because the compensating stop failed. It is in memory only. It resets on a supervisor restart.
- Name validation: a player name must match `/^[A-Za-z0-9_]{1,16}$/`. `__proto__` matches the pattern (accepted deviation); the tests assert that it is unknown, because it is not on the roster.
- Name case: names are compared and keyed lower-cased (the roster stores them lower-cased, `tools/mcp-tokens/src/roster.ts`).
- For C7-03b (the Docker adapter), these are required:
  - On abort or error the adapter removes the container it created. A stopped container left behind is not a body the supervisor counts.
  - Containers are named by the lower-cased player name, not by an agent id, so the one-body-per-name rule holds in Docker.
  - The admin check calls `supervisor_is_admin` (ruling b). It does not read a local flag.
  - The adapter replaces a stopped container left by the previous roster owner. The supervisor lets the roster owner start a name whose record is stopped (review fix E, finding 2).
  - The adapter logs the body in with the player's exact display name read from `mcp_players.display_name`, not the lower-cased key (orchestrator ruling, review fix E, finding 3). Roster keys stay lower-cased; golem's id derivation and the offline-mode UUID depend on the exact case.
  - On abort or error the adapter removes the container that the aborted call created, by the container id that call returned, never by the name. The name is shared with a newer attempt's container, so a removal by name kills that counted body (review fix G, finding 4).
  - `LogPort.recent` and the log store are keyed by player name only. The adapter must bound the log read to the current roster record (its creation time or its owner), so a new roster owner sees none of the previous owner's events (review fix G, finding 4).
  - Known gap, left as is (review fix G, finding 1): the compensating stops after a failed start and after a failed counted insert act by name, not by attempt. If the roster moves while one owner's start is in flight, such a stop can stop the new owner's body. Rare, since it needs a roster move inside one Docker call.

## Review fix E (review pass 3)

- A repeat start of a running body is audited as `noop`, counts nothing, and is not rate limited here. C7-04's rate limit covers repeat starts; a start retried in a loop has no counter until then.
- The composition root must pass `onAuditLost`. It is optional, so with no hook a lost audit row after an `ok` reply is silent.
- A late landing of a timed-out start is compensated unless a newer attempt is in flight or has counted its body (review fix G). A newer attempt that failed, or that the owner stopped, does not own the name.
