# C7-03a worknote: supervisor agent binding, roster scoping, audit and failure handling

Wave C7-1 fix B (review fix notes 2, 6, 7, 8). Code: `supervisor/src/service.ts`.

## Rulings recorded

- Ruling (a), orchestrator: bodies are keyed on the roster player name, not on `agentId`. The control request no longer carries `agentId`. The roster owner of the name must match the caller on every op (start, restart, stop, status, logtail). A repeat start by the owner returns `started` and counts nothing.
- Enforcement scope: `max_agents` above 1 is enforced only at `player add`. The supervisor runs one body per roster name, so one agent has at most one running body (Q3: 1 running body per agent).
- C7-03b's adapter must key containers on the player name, not on an agent id, so that the supervisor's one-body-per-name rule holds in Docker.
- Ruling (b), orchestrator: the admin check goes through `supervisor_is_admin` (added by the fix-A coder in migration 0027). That function is not on this branch. This branch has no Postgres adapter, so the supervisor cannot call it yet. Once the adapter exists, the admin check must call `supervisor_is_admin` and not read a local flag.

## Failure handling

- A runtime call is bounded by `runtimeTimeoutMs` (default 15 s).
- A failed `starts.insert` stops the started body, replies `error`, and audits `error`. No body runs uncounted.
- `status` and `logtail` are not audited.
- An audit failure after an `ok` reply returns the reply.

## Review fix D (orchestrator rulings, review pass 2)

- A removed roster name's body is still stoppable by its owner. The stop checks that the caller owns the record, not that the name is still on the roster (F6). A removed name cannot start again.
- The `uncounted` set (starts whose counter insert failed and whose body was stopped) is in memory only. It resets on a supervisor restart.
- Name validation: a player name must match `/^[A-Za-z0-9_]{1,16}$/`. `__proto__` matches the pattern (accepted deviation); the tests assert that it is unknown, because it is not on the roster.
- Name case: names are compared and keyed lower-cased (the roster stores them lower-cased, `tools/mcp-tokens/src/roster.ts`).
- For C7-03b (the Docker adapter), these are required:
  - On abort or error the adapter removes the container it created. A stopped container left behind is not a body the supervisor counts.
  - Containers are named by the lower-cased player name, not by an agent id, so the one-body-per-name rule holds in Docker.
  - The admin check calls `supervisor_is_admin` (ruling b). It does not read a local flag.
