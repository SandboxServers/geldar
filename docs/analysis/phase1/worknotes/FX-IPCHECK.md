# FX-IPCHECK worknote: the repo's IPv4 rule is enforced

Branch `feat/ip-literal-check`. The repo rule in `CLAUDE.md` says no public or private-network IPs in the repo, with `127.0.0.1` allowed. It was a sentence with no check. Decision 0132 (`docs/decisions/0132-ipv4-literal-policy.md`) states the policy: loopback (`127.0.0.0/8`, `0.0.0.0`) and the RFC 5737 documentation ranges are allowed anywhere; private and link-local ranges only in the files listed in `tools/repo-checks/src/ip-literal-allowlist.json`; a public literal fails in any file. The check is `tools/repo-checks/src/ip-literals.ts`, run by `pnpm check:repo`. It scans tracked and untracked text files, skips binaries, lockfiles, release dates, changelogs and generated code, and treats a `version` field as a version, not an address. It prints the path, the line and the class, never the address. The allowlist holds fourteen files, each with a reason: the trusted-proxy defaults in `threshold/mcp/src/config.ts` and the tests of IP, CIDR and host handling (four of them, in animus and golem, are not in the packet's list but use private addresses as non-loopback hosts). Findings on the first run: no public literal in product or test code. Three public-class matches in Gradle lockfiles and `verification-metadata.xml` are Maven version strings, so those files are excluded. Two decision-record lines (private CIDR blocks and a four-part example) failed the check and were reworded. **Owner action:** the `CLAUDE.md` repo-rule line should point at decision 0132 (agents do not edit `CLAUDE.md`). PR #73 edits some of the allowlisted test files: if its replaced literals land on `main`, re-run `pnpm check:repo` after merging.

Final gates (after merging origin/main, with the flagged C1-11a line reworded and a `noUncheckedIndexedAccess` typecheck error in `ip-literals.ts` fixed): `check:repo` ok; workspace typecheck exit 0; `vitest run tools/repo-checks` 23 files, 319 passed, 3 skipped; Biome clean on `ip-literals.ts`; merge-tree against origin/main exit 0.
