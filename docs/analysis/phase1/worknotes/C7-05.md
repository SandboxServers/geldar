# C7-05 worknotes: onboarding page and players README

## What changed

- The token is no longer in the mint or create response. Create and mint hold the new token in memory
  (`OnboardingHandoff`, one slot per session, 10-minute take-once hold) and answer 303 to `/register/onboarding`.
- `GET /register/onboarding` takes the held token once. A second load, another session, or a load after the
  hold has ended shows the "No token to show" page. The page is `no-store` with its own CSP.
- The copy buttons come from a same-origin script served at `/register/onboarding.js`. The CSP is
  `script-src 'self'` with no inline script.
- `docs/players/README.md` is rewritten (Microsoft sign-in, 90-day expiry, 14-day warning, 10-minute grace,
  token shown once and never emailed).

## Deviations from the card

- The card's `pages/onboarding*.ts` and `static/onboarding.js` paths do not exist. The page lives in
  `threshold/register/src/onboarding-pages.ts` and the script is served by the register at `/register/onboarding.js`.
- `account.ts` and `config.ts` were added to the may-edit list (the handoff lives in `account.ts`; the MCP
  override is a config field).
- `tokenPage` in `account-pages.ts` is now unused and was left in place. Removing it is more than a one-line
  deletion, and the packet said to leave it in that case.
- MCP base URL (orchestrator ruling): the derived default is the register public URL with its first label
  replaced by `mcp`. `REGISTER_MCP_PUBLIC_URL` (https, trailing slash dropped) wins when set. When neither gives
  an https address with a dotted host, the page shows no command block: it shows a "No connect command" note and
  still shows the token. Tests cover the explicit override, the derived address, the null cases and the page with
  no address.
- Session handoff key: `sessionHash` returns a Buffer, and a Buffer as a Map key compares by identity, so the
  first coder's handoff never matched. The key is now `sessionHash(id).toString('hex')`.
- Existing `account.test.ts` expectations for a successful create changed from 200 to 303 (the new contract:
  the create redirects to the onboarding page). Token checks on mint and create now use `shownToken`, which
  follows the redirect.
- The players README used the real deployment hostnames. Per the ruling, the repository now carries only
  placeholders (`glass.example.invalid`, `map.example.invalid`, `mcp.example.invalid`). The players-readme test
  checks against the same placeholder set.

  `mcp.` plus the register host with its first label removed, only when the host has at least three labels and is
