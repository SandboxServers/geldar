# C2-07c1: colo compose for the public sites

## Changed
- `compose/colo.yml` glass: `GELDAR_IN_NETWORK_HOSTS=1`, `GELDAR_GLASS_HOST=0.0.0.0`, `GELDAR_GLASS_PG_HOST=postgres` (C2-07a3 opt-in). The port stays published on `127.0.0.1:8787` only.
- Trusted proxies come from the node env: `GELDAR_GLASS_TRUSTED_PROXIES` and `GELDAR_MCP_TRUSTED_PROXIES` (default `127.0.0.1`, comma-separated). No private address is in the repo (decision 0132). The MCP reads `GELDAR_MCP_TRUSTED_PROXIES` in `threshold/mcp/src/config-read.ts`; it replaces `public.trusted_proxies` in `shards/colo-mind.yaml`, which stays the documented fallback. Because compose always sets the variable, the yaml list is used only by a run outside compose.
- New service `bluemap-web` (R27): `caddy@sha256:c3d7ee5d...adb` (the C2-04 pin), `caddy file-server --root /data/bluemap/web --listen :8100`, `paper-data:/data:ro`, published `127.0.0.1:8100:8100`. Read-only root, tmpfs `/tmp` (XDG dirs point there), cap_drop ALL, no-new-privileges, service uid, 0.25 CPU / 64m / 64 pids (`GELDAR_COLO_BLUEMAP_WEB_CPUS`, `_MEM`), logging and the Watchtower label anchor.
- `shards/colo.yaml` totals: 10.25 CPUs, 19776m. `colo-config` and `colo-services` repo checks updated (twelve services; new totals; service tests for glass env, MCP env and bluemap-web).

## Live data
BlueMap's integrated web server is off (`plugins/bluemap/config/webserver.conf` `enabled: false`) and `live-player-markers: false`, so BlueMap writes no live players file into the webroot. A repo check pins both. The caddy `file-server` CLI has no hide flag, so none is used. The whole Paper volume is mounted read only but the server root is `bluemap/web` only; the `bluemap/web` directory is created by BlueMap on its first render (until then the site answers 404).
