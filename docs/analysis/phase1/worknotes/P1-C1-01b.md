## mcp-mock `server.ts`: stopped, with the reasons

The card says to stop when a pure move cannot bring a file under 500. That is the case here, for three reasons.

1. **The body is one closure.** Lines 159 to 565 are `createMockHttp`, a single function of about 407 lines. Its inner functions (`prepareSession`, `startSession`, `dispatch`, `handle`, `endSession`, and the rest) all share the mutable state `sessions`, `byPlayer`, `superseded`, `starting`, `closing`, `openResponses` and `log`. Moving them is a restructure, not a pure move.
2. **The node-free top-level declarations are too small.** The declarations that do not touch `node:http` are the types `SessionEndReason`, `AuthDecision`, `Refusal` and `MockHttp`, the constants, `Session`, `LogContext` and `hostAllowed`. Together they are about 61 lines. Removing them gives about 510 lines with the imports and re-exports added back. That is still over 500.
3. **`node:http` may only be imported in `server.ts`.** `threshold/mcp-mock/src/sim/books.test.ts` (the source-rule block, lines 174 to 276) forbids `from 'node:http'` and `from 'node:net'` in every non-test source file except exactly `src/server.ts`. The rule matches type-only imports too. `MockHttpOptions`, `readBody`, `sendRefusal` and `rpcError` all need `IncomingMessage` or `ServerResponse`, so they cannot move without a `node:http` import outside `server.ts`. Changing that rule would weaken a test, which the brief forbids.

Next step for this file, if it is wanted: a separate packet that decides how the per-request state is held (a session-registry object passed to the request handlers), and whether the source rule should allow `node:http` types in one more file. Neither is a pure move, so neither belongs here.
