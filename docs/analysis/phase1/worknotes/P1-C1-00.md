## OPEN

### (a) Five `.it.test.ts` files not in the CI `integration` job

Files: `animus/src/link/link.it.test.ts`, `eventsink/test/eventsink.it.test.ts`, `eventsink/test/projection.it.test.ts`, `golem/src/mind-link/server.it.test.ts`, `lantern-local/test/ollama.it.test.ts`.

Answer: none of the five runs in CI.

- The root `vitest.config.ts` includes `**/src/**/*.test.ts` and `**/test/**/*.test.ts` and excludes only `*.live.test.ts`. So `pnpm test` in the `typescript` job does load them. Each gates itself with `describe.skipIf(!enabled)` on `GELDAR_IT === '1'`, and the `typescript` job does not set `GELDAR_IT`. They are loaded and skipped.
- The `integration` job sets `GELDAR_IT: '1'`, but runs `pnpm vitest run` with an explicit list of ten files (`.github/workflows/ci.yml` lines 225-236). None of the five is in it.
- `ollama.it.test.ts` also needs `GELDAR_OLLAMA=1` and a running Ollama. Its header says "Not run in `check` or CI." That is by design.
- The other four cannot simply be added to the list. `link.it.test.ts`, `server.it.test.ts` and `projection.it.test.ts` need a live NATS (`nats://127.0.0.1:4222`); the `integration` job has a Postgres service only. `eventsink.it.test.ts` and `projection.it.test.ts` need the eventsink running. Adding them needs a NATS service (and eventsink) in that job first. That is a CI change, outside this packet.

Recommendation: the owner or the phase-1 CI packet decides whether the four get a NATS service in `integration`. `ollama.it.test.ts` stays local-only.

### (b) `pnpm-lock.yaml` has two YAML documents

Investigation (read-only):

- `git show HEAD:pnpm-lock.yaml` and the file on disk both have 2510 lines. `git status` is clean for this file. So the file on disk is HEAD; there is no worktree divergence.
- `lockfileVersion: '9.0'` appears at lines 2 and 159, and `importers:` at lines 4 and 180. Line 158 is a `---` separator.
- So the file is two YAML documents. Document 1 (lines 1-158) is a short document with its own `importers` and the `packageManagerDependencies` block (for example `'@pnpm/exe.linux-x64': 12.15.0`). Document 2 (lines 159-2510) is the project lockfile, with `settings`, `overrides`, the full `importers`, `packages` and `snapshots`.
- This is how pnpm writes a lockfile that records its own package-manager dependency ahead of the project lockfile. The file is tracked on main and CI runs `pnpm install --frozen-lockfile` against it, so the file is accepted as it is. Not changed here; the lockfile is not modified.

Answer: the duplicate `lockfileVersion` and `importers:` are the two documents, not a corruption. No action is needed for this packet. If the owner wants one document, that is a pnpm-version question for a separate packet.
