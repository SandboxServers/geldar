## Deviations from the card

1. **Webserver is off, not bound to loopback.** The card's first option is loopback, or an internal
   address supplied by C1-02. BlueMap 5.29's `webserver.conf` has no bind-address key (checked in the
   jar's default config). Its server would listen on every interface. So `enabled: false` is the only
   safe setting, and the test accepts `enabled: true` only with `ip: "127.0.0.1"`. Caddy serves the
   webroot.
2. **Extra privacy settings.** `plugin.conf` `skin-download: false` (no Mojang skin fetch) and
   `core.conf` `metrics: false` (no bStats call). Both are outbound calls the card did not name.
3. **Test location.** The card's `plugins/bluemap/test/config.test.ts` is used, plus a second file,
   `plugins/bluemap/test/lock.test.ts`. The root `vitest.config.ts` includes `**/test/**/*.test.ts`,
   so `pnpm vitest run plugins/bluemap` runs both. No repo-checks index line is needed.
4. **Release-date key.** `github-release:BlueMap-Minecraft/BlueMap@v5.29` in `release-dates.json`.
   The release-age check reads pins only from manifests, Dockerfiles and compose files, so the lock
   file is not scanned by it. `lock.test.ts` checks the date entry directly.
5. **Worknote name.** The card says `C1-09.md`. The brief and the existing notes say `P1-C1-09.md`.
   This file uses the `P1-` name.
