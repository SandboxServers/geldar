# C7-04c2 worknote: body routes production wiring

Card: [c7d-packets.md](../packets/c7d-packets.md), C7-04c2. Branch `phase1/c7-04c2`. Status: built. live: pending (the live check is not written here; see below).

## What is built

- `threshold/register/src/api/body-slot.ts`: `createBodySlot()` and the `BodySlot` type. One slot per process, shared through `BodyDeps.slot`.
- `threshold/register/src/api/body.ts`: `BodyDeps.slot` (optional). The routers use `body.slot ?? createBodySlot()`; nothing else changed.
- `threshold/register/src/nats-body.ts`: `lazyCtlConnection` (the NATS link, opened on the first body request) and `bodyWiring(config, log)` (the routes and the shared slot; empty routes when NATS is off).
- `threshold/register/src/config.ts`: `RegisterConfig.nats` (null unless configured).
- `threshold/register/src/main.ts`: mounts `bodyWiring(...).routes` through `api.routes`. `server.ts` is not changed.
- Tests: `threshold/register/test/body-wiring.test.ts` (12 tests).

## Configuration (names only)

- `REGISTER_NATS_URL`: a `nats://` URL.
- `REGISTER_NATS_USER`: the NATS user (the `register` role).
- `REGISTER_NATS_PASSWORD_FILE`: a file holding the password. The password is never read from the environment or the repo.
- `REGISTER_NATS_TIMEOUT_MS`: the reply wait of one supervisor request, default 5000.

All three of the first three must be set. A partial setting, or an unreadable or empty password file, leaves NATS off: the body routes answer 404 and the service starts. A set URL that is not `nats://` fails at start, like the other URLs.

## Behaviour

- NATS off: the body routes are not mounted, so every body path is 404. This is on purpose. The card's Goal said
  "with no connection, the body routes answer 503"; that wording is superseded. 503 is only for NATS configured but
  unreachable. C7-04d and the live check expect 404 on an unconfigured node.
- The reply wait (`REGISTER_NATS_TIMEOUT_MS`) is 1 to 60000 ms; 0 and larger values fail at start.
- NATS on, server unreachable: the link is opened on the first body request. A failed connect rejects that request, which is `body_unavailable` 503 with Retry-After 30. The next request tries again.
- Retry and cap: the register has no retry loop. Each request makes at most one connect attempt, bounded by the request's own timeout. The NATS client's auto-reconnect is the contract's (`connectNats` sets `maxReconnectAttempts` to -1, so it has no cap). A fatal close drops the link and is logged; the process does not exit.
- The in-flight slot is one object shared by every body router. A second start while the first is in flight is 409 `conflict`. The slot is freed on every path, including errors.

## Revert-checks

- Shared slot: `const inFlight = body.slot ?? createBodySlot();` replaced by a private `new Set<string>()`. The test `one slot shared by two routers` fails with 202 instead of 409.
- Partial NATS setting: the early `return null` in `natsOf` replaced by a throw. Six tests fail, including `a partial NATS setting leaves NATS off and does not fail the start`.

## Not in this card

- The `nats-auth.conf` user on the live node is not changed.
- Retire (C7-04d) is not built here. The shared slot is ready for it through `bodyWiring(...).slot`.
