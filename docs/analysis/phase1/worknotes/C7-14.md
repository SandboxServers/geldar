# C7-14 worknote: operator route for the public camera and delayed public thoughts flags

Rulings (accepted from the first coder):

1. Only the thoughts flag (0016) has a 10-second window. The camera flag (0014) has none. The operator function applies
   the window to thoughts only, with outcome `too-soon`. A camera-only call has no window.
2. The operator role is `geldar`, the role tools/mcp-tokens and tools/admin connect as. EXECUTE is granted to `geldar`
   only, inside a guarded DO block, so a database without that role still migrates. Not granted to geldar_register,
   geldar_mcp, geldar_glass or geldar_supervisor.
3. `tools/admin/admin.sh` has its own verb list, so `player-flags` was added there. This edit is outside the original file
   list of the packet, by ruling.
4. The `<player-id>` argument is the player id (`ag-...`), not a roster name, as with the other `player` commands.
5. The function returns outcome codes (`ok`, `unknown-player`, `retired-player`, `no-flags`, `too-soon`). It does not raise
   on refusal, so the `register_audit` row written in the same transaction survives. Every call writes one row:
   actor `operator`, action `player.flags`.

Finding (camera window): the camera flag has no time window, by 0014. The operator route keeps that: a camera-only call
is never refused as too soon, even when the thoughts flag changed a second ago. The test
`the camera-only change ignores the thoughts window` in sql/test/check-schema-operator-flags.sql covers this.

register-definer gate (`<> 17` in check-schema.sql) still passes. Revert-checks: removing the PUBLIC revoke fails the
check at `PUBLIC cannot execute the function`; removing the audit insert fails at `every call wrote one audit row`.
