# C7-03c1 worknote: the body helper's caps, queue and shutdown

Facts about what the body helper (`body-helper/`) guarantees, and what it does not, after review fix 2.

## The global cap (GLOBAL-CAP, decision 0261)

- The count is running Bodies plus sovereign player hosts (`com.docker.compose.service=players-host`). A Body in
  `restarting` (a crash loop under `unless-stopped`) is counted, so it keeps its slot while it is down. Hosts in
  `restarting` are counted the same way.
- The cap is **exact against helper requests**. Start and stop share one process-wide queue, so the count a start
  reads is never stale with respect to another helper request: concurrent starts cannot pass the cap together.
- The cap is **soft against anything else**:
  - An operator starting a sovereign host through compose in the same instant is outside the queue. The count can
    be one behind for the length of one start, so the node can briefly reach cap + the number of such starts.
  - A Body restarted by Docker itself is outside the queue for the same reason.
- **One helper process only.** The queue is per process. Two helper processes (a deploy overlap, a scaled service)
  each have their own queue and can both pass the cap. The C7-03c2 compose entry must run exactly one instance.

## The per-request deadline

- Every start and stop holds the queue for at most `GELDAR_BODY_HELPER_DEADLINE_MS` (default 120000 ms), counted
  from when the run starts. Past it the caller is answered with code `timeout` and error `engine timeout`, and the
  queue moves on.
- The abandoned run makes no create, start or stop after its deadline, and writes no audit line after the
  `engine_timeout` line, except the one case below. It may still read (`inspect`, `countCounted`), and it removes what it made: a late start removes
  its own container at once, retrying the remove once. If both removes fail, the run audits
  `reason=late_start_remove_failed` and the sweep reports the container as `late_start_orphan` while it runs. A late
  start is never audited `accepted`. A start still in flight counts against the cap (`pendingStarts`) until its Engine calls settle,
  so a queued start never sees a slot that is still taken.
- A timed-out stop leaves the Body's state unknown: the stop may still land. The caller must issue `status` to learn
  the state. The sweep reports a timed-out stop whose Body is still running (`stop_timed_out`) until the stop lands.
- A stopped container left by an abandoned create is removed by the next start of the same name (the helper made it).
- The socket layer also times out one Engine call at 30 s (`ENGINE_TIMEOUT_MS`), so a single hung call fails sooner.

## Shutdown order (SIGTERM, SIGINT)

1. The stray sweep stops.
2. The helper's subscriptions end: no new request reaches the handler.
3. The in-flight answers are awaited, capped at 10 s.
4. The NATS connection drains (its published replies flush), then the database pool ends.

The helper's compose service must set `stop_grace_period` above 10 s (the wait) plus the pool close, or Docker's
default 10 s can send SIGKILL first. Set it in C7-03c2.

## Ownership of a Body (decision 0108)

- Each Body carries the `geldar.owner` label set from the request owner. The engine inspect returns that label as
  `owner` (null when absent), and `status` replies with the owner it holds.
- `start` needs a roster row: the owner and the name must match `supervisor_player_display_name`. Nothing else changes
  for a start: a name off the roster is refused `not on roster` before any container call.
- `stop`, `status` and `logtail` need no roster row. They act only on a container that is a helper Body (the Body
  label), has the exact name, and has a `geldar.owner` label equal to the request owner. A Body whose name left the
  roster, or whose player was retired, stays stoppable by its owner.
  - A container of the name that is not a helper Body is refused `name taken by a container the helper did not
    create`, as before. An unlabelled container is never touched.
  - A Body labelled for another owner is refused `not your body`. The reply and the audit line carry neither owner id.
  - A missing container keeps the old answer: `stop` is `not running`, `status` is `absent`.
- Roster move (A's Body, the name moves to B): B's `start` is refused `name in use by another owner's body` and
  nothing is removed or stopped. The Body is A's until A stops it (A still reaches it by `stop`, `status` and
  `logtail`). If A cannot stop it, the operator reap path (card C7-03c4) removes it. B's start is refused until then.

## Configuration to set at deploy

- `GELDAR_GLOBAL_BODY_CAP`: unset (40) or a positive whole number. An empty value is refused at start.
- `GELDAR_BODY_HELPER_DEADLINE_MS`: unset (120000) or a positive whole number of milliseconds.
