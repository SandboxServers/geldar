# C7-04a worknote: owner API core

Decisions: 0152, 0170 (admin flag per request). Card: `c7d-packets.md`, C7-04a.

## What this packet ships

- `threshold/register/src/problem.ts`: `sendProblem`, the only builder of an error body (`application/problem+json`,
  `type`, `title`, `status`, `code`). `PROBLEM_CODES` is the enum; the OpenAPI source lists the same set (a test checks it).
- `threshold/register/src/api/route.ts`: the route, context and dependency types.
- `threshold/register/src/api/auth.ts`: credential resolve. Cookie `gr_session` first (through the session store; an unknown
  or unreadable session is 401 and no Bearer is tried). Else `Authorization: Bearer gowner-...` through the C7-02b
  `OwnerKeyStore.resolve`. A `gmcp-` token, a banned owner's key, or no credentials is 401. A cookie session holds every
  scope; the CSRF token is the same HMAC derivation as the account page (`register-csrf-v1:<session id>`), compared in
  constant time.
- `threshold/register/src/api/index.ts`: router. Paths outside `/api/v1/` return false (the server answers 404 problem).
  Order: path (unknown 404, other method 405), credential (401), CSRF for a cookie write (403 `csrf_required`), scope (403
  `scope_missing`), owner window for a write (429 with `Retry-After`, skipped for an admin), handler (a throw is 500 internal).
- `threshold/register/src/api/guard.ts`: `ownedAgent`. A missing agent and another owner's agent are both null, so both get
  the same 404 body.
- `threshold/register/src/api/agents-read.ts`: `GET /agents/{playerId}` (scope `read`).
- `threshold/register/src/api/owner-api-v1.yaml`: OpenAPI source (no lint tool is wired; the test checks the problem enum).
- `threshold/register/src/server.ts`: the handler runs the kill switch and the source (IP) limit for every path, then
  dispatches `/api/` to the router. An API refusal of either is problem+json (503 `unavailable`, 429 `rate_limited` with
  `Retry-After`); a page refusal keeps its JSON shape. So no key is resolved past either guard, and the admin exemption
  never reaches the source limit (it applies only to the owner window inside the router). An uncaught throw on an API path
  answers problem+json 500 `internal`. `RegisterDeps.api` takes keys, agent loader, audit sink, `onAuditLost`, admin hook
  and extra routes.
- `threshold/register/test/owner-api.test.ts`: 21 tests (route tree, 401s, scope, CSRF, 404 byte-equal, problem table,
  admin exemption and abort path, audit-lost).
- `threshold/register/test/owner-api-gate.test.ts`: 4 tests. Kill switch on: problem+json 503 and zero resolver calls.
  Source limit with `perMinute: 3`: requests 1 to 3 reach the resolver (401), request 4 is 429 with no resolve (resolver
  count 3). A 429 body is problem+json `rate_limited`. A route throw after the key resolved is problem+json 500 `internal`.

## Not wired (deliberately)

- `main.ts`: unchanged. The composition root has no audit sink of its own (it passes `PgStore` as the store and sessions
  only), so per the card no `onAuditLost` is invented there. The hook exists in `RegisterDeps.api`; C7-04b wires the sink.
- No Postgres adapter for `OwnerKeyStore` and no production agent loader: `deps.api.ownerKeys` and `deps.api.agents` are
  unset in the composition root, so a Bearer key is refused and `GET /agents/{id}` answers 404 until C7-04b wires them.
- `isAdmin` is unset in production, so the admin exemption is inactive there (it fails closed: every owner is limited).
  C7-04b wires it.
- No migration.

## Moved to C7-04b (orchestrator ruling 2)

Recorded as explicit requirements with test lines in the C7-04b card (`c7d-packets.md`, "Tests"):

- Player token at the API is refused (black box, same store).

structurally separate (`owner_api_keys` vs `mcp_tokens`).
