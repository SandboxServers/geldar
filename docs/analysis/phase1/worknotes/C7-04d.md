# C7-04d worknote: owner API retire route

**Route.** `POST /agents/{playerId}/retire` (`threshold/register/src/api/body-retire.ts`, factory `bodyRetireRoutes`).
Cookie session only with CSRF (decision 0173): the route is `cookieOnly` and `write`, so a Bearer key is 401 and a
cookie write without or with a wrong CSRF token is 403 `csrf_required` (the router's order). Scope `manage`.

**Order.** (1) foreign, missing or retired agent: 404 before any supervisor call. (2) display name outside
`^[A-Za-z0-9_]{3,16}$`: 422 `invalid` before any supervisor call (same rule as body.ts). (3) the owner's body slot:
a stop or retire of the same owner in flight is 409 `conflict`. (4) stop through the supervisor (`stop`, the
display name as `playerName`). (5) revoke the agent's tokens through the C7-04b service (`revokePlayerTokens`, with
the router's owner window as the one charge). (6) `retirePlayer(identityHash, playerId)`, the store method of
`PgStore` (`register_retire_player`). 202 `BodyOp` on success.

**Shared slot.** The retire takes the slot from `BodyRetireDeps.slot` (required, no default), the same object the body
routers take from `BodyDeps.slot` (C7-04c2). It never creates a slot. The slot is held from before the stop until the
retire (or a failure), and freed in `finally`.

**Supervisor unavailable.** A timeout, no responders, a disconnect or an unreadable reply is 503 `body_unavailable`
with `Retry-After: 30`. Any other refusal of the stop (`busy`, `error`) is also 503. Nothing after the stop runs: no
revoke, no retire, so the agent stays live and the retry is safe. A supervisor `unknown` reply (no body of this owner
under that name) is treated as "nothing to stop" and the retire continues. That is a judgement on the card, which
says only "stop"; the orchestrator should confirm it.

**Retry and cap.** The retire route has no retry of its own and no cap of its own. A repeated call is limited only by
the router's owner window (the same window as every owner write, not changed here). The last-attempt case is: a 503
on the stop frees the slot, so the next call runs in full (test "retries safely").

**Failures after the stop.** A revoke that throws is 500 `internal` with no retire; a revoke that finds nothing is 404
with no retire. A retire write that throws is 500 `internal`. A retire that the database refuses (not the owner's or
not live) is 404 `not_found`, after the tokens were revoked; the database retire also revokes, so that case is safe.

**Mount.** Not mounted. `server.ts` and `main.ts` are not in this card's may-edit list. The C7-04c2 wiring
(`bodyWiring` in `nats-body.ts`) does not mount the route; ops adds one line that appends
`bodyRetireRoutes({ conn, shard, timeoutMs, slot, retirePlayer })` to the routes only when NATS is configured, so the
route follows the body routes' off-by-default rule. `retirePlayer` is `PgStore.retirePlayer`.

**No SQL.** The existing `register_retire_player` is used. No migration.
