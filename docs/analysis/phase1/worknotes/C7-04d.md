# C7-04d worknote: owner API retire route

**Route.** `POST /agents/{playerId}/retire` (`threshold/register/src/api/body-retire.ts`, factory `bodyRetireRoutes`).
Cookie session only with CSRF (decision 0173): the route is `cookieOnly` and `write`, so a Bearer key is 401 for every
agent (own, foreign, bad name) and a cookie write without or with a wrong CSRF token is 403 `csrf_required` (the
router's order). Scope `manage`.

**Order.** (1) foreign, missing or retired agent: 404 before any supervisor call. A retired agent is 404 even when its
display name is also outside the shape (the retired check comes first, as in body.ts). (2) display name outside
`^[A-Za-z0-9_]{3,16}$`: 422 `invalid` before any supervisor call (same rule as body.ts; the rule is a copy of
body.ts's private constant, so drift is possible; follow-up: export it from body.ts and import it). (3) the token
service is built (a missing service is 500 before anything runs). (4) the owner's body slot: a stop or retire of the
same owner in flight is 409 `conflict`. (5) stop through the supervisor (`stop`, the display name as `playerName`).
(6) revoke the agent's tokens through the C7-04b service (`revokePlayerTokens`, with the router's owner window as the
one charge). (7) `retirePlayer(identityHash, playerId)`, the store method of `PgStore` (`register_retire_player`).
202 `BodyOp` on success.

**Shared slot.** The retire takes the slot from `BodyRetireDeps.slot` (required, no default), the same object the body
routers take from `BodyDeps.slot` (C7-04c2). It never creates a slot. The slot is held from before the stop until the
retire (or a failure), and freed in `finally`. The slot is per process, the same limit as the body routes.

**Supervisor unavailable.** A timeout, no responders, a disconnect or an unreadable reply is 503 `body_unavailable`
with `Retry-After: 30`. Any other refusal of the stop (`busy`, `error`) is also 503. Nothing after the stop runs: no
revoke, no retire, so the agent stays live and the retry is safe. A supervisor `unknown` reply (no body of this owner
under that name; the supervisor's stop does not consult the roster) is treated as "nothing to stop" and the retire
continues. Ruling at review (C7-04d fix pass 1): accepted.

**Retry and cap.** The retire route has no retry of its own and no cap of its own. A repeated call is limited only by
the router's owner window (the same window as every owner write, not changed here). The last-attempt case is: a 503
on the stop frees the slot, so the next call runs in full (test "retries safely").

**Repeat after success.** A retire that succeeded leaves the agent retired, so a second call is 404 `not_found`, not an
idempotent 202. A client that lost the 202 sees 404 and the agent is retired.

**Failures after the stop.** A revoke that throws is 500 `internal` with no retire; a revoke that finds nothing is 404
with no retire. A retire write that throws is 500 `internal`. A retire that the database refuses (not the owner's or
not live) is 404 `not_found`, after the tokens were revoked; the database retire also revokes, so that case is safe.
The revoke SQL (`register_revoke_tokens`) returns the count of ended tokens, so a retry after a partial failure gets 0,
not an error, and runs through to the retire. Test "retries after the retire write throws" pins this with a 0-row
revoke.

**Mount.** Not mounted in this card. `server.ts` and `main.ts` are not in this card's may-edit list. The mount is a
follow-up card, not one line: `bodyWiring` in `nats-body.ts` takes no `retirePlayer` and `main.ts` ignores the `slot`
it returns, so the follow-up must plumb `retirePlayer` (`PgStore.retirePlayer`) through `bodyWiring` and then append
`bodyRetireRoutes({ conn, shard, timeoutMs, slot: body.slot, retirePlayer })` to the routes only when NATS is
configured (the body routes' off-by-default rule), with a test through `mountBodyApi`. Until then the route is not
reachable in production.

**No SQL.** The existing `register_retire_player` and `register_revoke_tokens` are used. No migration.
