# C7-02b worknote: owner API keys (migration 0026)

Decisions: 0170 point 2 (keys: `gowner-` plus 64 hex, HMAC-SHA256 under the token pepper, scopes read, body, manage, 90 days), 0152.

## What this packet ships

- `sql/0026_owner_api_keys.sql`: table `owner_api_keys` (hash only, `key_id` shape `gok-` plus 16 hex, scopes limited to read, body, manage, non-empty). Definer functions `register_owner_key_resolve`, `register_mint_owner_key`, `register_revoke_owner_key`, `register_list_owner_keys`. Each takes the presented key hash, resolves the presenter in the same call, and writes its audit row in the same transaction. `geldar_register` gets EXECUTE on all four and no table privilege. `PUBLIC` has no EXECUTE. `search_path` is pinned to `pg_catalog, public, pg_temp`.
- `threshold/register/src/owner-keys-policy.ts`: key shape, HMAC hash, key generation, scope parsing, 90 day expiry.
- `threshold/register/src/owner-keys-service.ts`: the store interface and the mint, revoke and list actions. The store is injected.
- `threshold/register/test/owner-keys.test.ts`: TS behaviour tests against an in-memory store.
- `sql/test/check-schema-owner-keys.sql` (wired into `ci.yml`), and the register-definer gate in `sql/test/check-schema.sql` (literal 17, which is the exact count of `register_%` SECURITY DEFINER functions on a freshly migrated database).

## Accepted assumptions

- Any banned identity on the owner makes every key of that owner fail closed (resolve refuses; the refusal writes a `key.use` audit row with outcome `refused_banned`).
- A new key's scopes must be a subset of the presenting key's scopes (no escalation). Enforced in the service (`bad_scopes`), so a request for a scope the presenter lacks never reaches the database.

## Behaviour that is pinned

- Expiry: a key is refused at its expiry instant (`expires_at <= now()`), so the boundary is refused, not accepted. Checked in SQL (fixture `a5` expires at now()).
- Revoke is immediate: the next resolve refuses the key.
- Scope check: a key without `manage` cannot mint or revoke (`scope_missing`, audited by the service). A key without `read` lists nothing.
- A DB error during mint is audited with outcome `error` and rethrown; no value is returned and no row is written (the SQL mint is one statement inside the definer function, so the row and its audit roll back together).
- Mint and revoke are windowed through an injected `charge`; an admin skips the window; a read is not windowed. The normal owner's last allowed action succeeds and the next returns `limited` with a retry-after.

## Not in this packet (C7-04 or later)

- The key HTTP routes in `threshold/register/src/server.ts`. The brief puts the key routes with C7-04, so `server.ts` is untouched here.
- A Postgres adapter for the `OwnerKeyStore` interface. The card does not put it in C7-02b. C7-04 wires it to the four definer functions.
- The black-box MCP test (an owner key refused by the MCP endpoint, a player token refused by the key resolve). This packet does not start the MCP endpoint. The MCP refusal is structural: keys live in `owner_api_keys` and never match `mcp_tokens`; the register side (a player token has no key shape and never reaches the resolve) is tested in the service test. C7-04 adds the black-box request.
- An admin's key reading another owner's agent (404). That is a read route, so it belongs to C7-04.

## Wave 2 fix H (as built)

- Scope escalation is refused in SQL: `register_mint_owner_key` raises `42501 scope_escalation` unless the requested
  scopes are a subset of the presenting key's scopes. The TS check in `owner-keys-service.ts` stays as a first line.
- Live-key cap: an owner may hold at most 10 live keys (live = not revoked and not expired). The definer function
  raises `53400 live_key_cap` for the eleventh mint. Admins are not exempt. The owner row is locked (`FOR UPDATE`)
  before the count, so concurrent mints for one owner cannot pass the cap together.
- Source rate-limiting of the key routes is not in this packet and not in SQL. It belongs to C7-04a.
- Carry-forward for C7-04a: the black-box pair. An owner key at the MCP endpoint is refused, and a player token at
  the key routes is refused. Both are black-box requests that need the routes and the MCP endpoint running together.
- The register side of the shape guard is tested in `threshold/register/test/owner-keys.test.ts`: a `gplayer-` value
  and a bad-length `gowner-` value never reach the store (`resolve` is not called).
