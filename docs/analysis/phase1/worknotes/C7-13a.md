1. Account deletion does not reach skin uploads. `sql/0039_account_deletion.sql` says skin upload rows are not
   referenced yet and that C7-13a adds them to `register_account_delete`. Migration 0031 sorts before 0039 and 0039 is
   already on main, so the fix is a new migration with the next free number above 0066 (checked against the ledger,
   not 0031). It recreates `register_account_delete` with `DELETE FROM public.skin_uploads WHERE owner_id = who`.
   Add a case to `sql/test/check-schema-account-delete.sql`: after the delete, zero skin rows reference the owner.
   `skin_uploads` has no foreign key, so until this lands an owner delete succeeds and leaves `owner_id`, `player_id`
   and the PNG bytes behind. No rows exist until the routes land, so this is not exploitable today.
   This item must appear in the routes session brief.

2. Definer functions and the count literal. The register definer functions for skin uploads are not written. The
   `register_%` count literal (25) in `sql/test/check-schema.sql` must be updated when they are added.

3. C7-13b (operator decisions). The operator role is `geldar`, the table owner, so UPDATE on `skin_uploads` needs no
   grant. The `geldar_operator` role does not exist and must not be added. Migration 0031 needs nothing for C7-13b.
