## Rate rules (in migration 0067)

SQL tests in `sql/test/check-schema-skin-rules.sql`. Rulings from decision 0172:

- The daily cap (3 uploads a day) is per agent, as 0172 point 2 says. The reject wait (1 hour) is per agent.
  One pending upload per agent. The lock (point 5) is per owner.
- The lock: 3 rejects of the owner decided within 30 days of each other, not cleared. It does not lapse with time.
  It holds until the operator clears it.
- Operator clear, one statement, run as the table owner role `geldar` (no new role). It releases every uncleared reject
  of the owner, so the next 3 rejects lock again:

  `UPDATE skin_uploads SET lock_cleared_at = now() WHERE owner_id = '<owner id>' AND status = 'rejected' AND lock_cleared_at IS NULL;`

- Admin owners (0170) are exempt from the wait, the lock and the daily cap, and from nothing else.
- The audit actor of `skin.upload` is the hashed owner id (`left(encode(sha256(convert_to(owner, 'UTF8')), 'hex'), 16)`),
  as the other owner actions; the detail is the empty string.
- Errors name no owner id and no PNG bytes; the PNG and the size are checked in the function before the table's CHECK.

The lock count reads the `skin_uploads_owner_created` index (owner_id, created_at). The daily count is per agent
(player_id) and has no index of its own yet; the table is small, and a per-agent index is a follow-up if the count
shows in plans.
