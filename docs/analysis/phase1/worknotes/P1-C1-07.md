# P1-C1-07 worknote: metrics exporters and the MCP replay bound

Branch `phase1/c1-07-metrics`, from `origin/main` (e4b9b67). Card: `docs/analysis/phase1/packets/c1-packets.md`, "Card C1-07". Owner ruling: 0130 (telemetry goes to the node's SigNoz; the URL is `GELDAR_TELEMETRY_URL`, never in the repo).

## 1. How `fromIso` is computed today (recorded before any change)

- `threshold/mcp/src/main.ts` (around line 340) calls `nats.replay(streamSubjects(shard), replayStartIso(now(), config.sovereign.replayMinutes), onMessage)`. The caller is `main.ts`, not `cli.ts`; `cli.ts` only receives the `fromIso` and passes it to `source.open` on the first open and on each reopen.
- `replayStartIso` (`threshold/mcp/src/events/stream.ts`) returns `new Date(nowMs - replayMinutes * 60_000).toISOString()`.
- The window already exists as a setting: `sovereign.mcp.replay_minutes` in `shards/phase0.yaml` (value 60), read by `threshold/mcp/src/config.ts`. Before this change it was required (a missing key threw "is missing") and was clamped to 1 to 1440 by the shared `int` helper, whose error does not name the value.
- So the card's premise ("the repo has no `replay_minutes` key") is out of date. The window is bounded today; what was missing was the default of 60 when the key is absent and the value in the refusal message.
- Consumer is ephemeral: `DeliverPolicy.StartTime`, `opt_start_time = fromIso`, explicit acks (`replay-source.ts`). A recreated container therefore starts at now minus the window, not at the stream start.
- Dedupe by stream sequence: `handleStreamMessage` and the replay settled-set (`cli.ts`, `seen`) already drop redeliveries; existing tests "fans a day_night event out to every life once, even when it is redelivered" (`events/stream.test.ts`) and "counts a poison message once toward the settled count" (`cli-replay.test.ts`) cover it.
- Observation, not changed here: `reopen` calls `source.open(subjects, fromIso)` with the startup `fromIso`. A long-running MCP that reopens the consumer replays from its startup window again. Dedupe keeps this safe, but it is a larger re-read than the window. Recorded for a follow-up; not part of the card's acceptance.

## 2. Item 1 change

- `main.test.ts`, describe "the replay window": the replay starts exactly 60 minutes before now (shipped shard); default when the key is absent; the shard value is used; 0, -3, 2.5 and 1441 are refused with the value named.

## 5. Item 2: MCP metrics module (threshold/mcp/src/metrics.ts)

- `MetricRegistry`: counters, gauges and histograms; every metric is declared with its label names first. A label named like `player`, `life` or `token` (any name containing them) is refused at declaration. A series with any other label set is refused.
- `render()`: Prometheus text format. `pushMetrics()`: one OTLP/HTTP JSON POST to `<url>/v1/metrics`, failures logged with the status code (0 for a network error) and not thrown.
- `startTelemetry()`: the only place that pushes on a timer; it returns at once with no timer and no request when the URL is unset. `GELDAR_TELEMETRY_URL` is read by the wiring, not by this module.
- MCP wiring (status, updated): the MCP has NO `/metrics` route. The orchestrator ruled push-only, so no route will be added. `main.ts` calls `startTelemetry` (line 276) with the URL that `cli.ts` reads from `GELDAR_TELEMETRY_URL`; with the URL unset nothing is pushed.

## 7. Item 3: golem exporter (P1-C1-07b, done)

- `golem/src/metrics.ts`: push-only OTLP/HTTP JSON, copied from the MCP registry by hand (no shared package exists yet; the duplication is a follow-up: move the registry and push code to a shared package once a third exporter needs it). Zero new dependencies.
- Metrics: `geldar_body_connected` (gauge 0/1), `geldar_tps` and `geldar_tick_lag_ms` (gauges, from the server's world age in `bot.time` packets over 10 s windows), `geldar_wakeups_total{reason}` (closed set: the contract's wake reasons, `new_agent_within_<n>` folded into one label, anything else `other`), `geldar_action_outcomes_total{status,reason}` (closed sets; `none` when no reason).
- Deviation from the card: the golem does not see `server_tps` events (the Java plugin emits them to NATS, and the Body only sees the world clock). TPS is therefore read from the server's time packets, which carry the same server tick.
- Wiring: `golem/src/adam/main.ts` starts it from `process.env` and stops it after the supervisor; `adam-body.ts` wraps the record sink (`countingSink`) and feeds the world age. With no `GELDAR_TELEMETRY_URL` there is no timer and no request.
- Tests: `golem/src/metrics.test.ts` (19 tests): counts and timing, closed label sets, label-name rule, push to a loopback receiver, no request without a URL, stop after `stop()`, a refused push logged with its status.
- Gap, recorded honestly: no test covers the two wiring lines in `adam/main.ts` and `adam-body.ts`. Removing the `metrics: telemetry.metrics` line leaves every adam test green (revert-checked). A wiring test needs the bot fakes in `adam-body.test.ts`; it is a follow-up.
- NATS reconnect metric skipped: there is no reconnect hook in `connectNats`.

## 8. Eventsink (P1-C1-07c, done)

- `eventsink/src/metrics.ts`: push-only OTLP/HTTP JSON, copied by hand from the MCP and golem registries (the duplication is a follow-up, see section 10). Zero new dependencies. No route, no listener.
- Metrics: `geldar_eventsink_consumed_total{type}` (the event type from the subject, from the closed list; `other` for anything else), `geldar_eventsink_written_total` (events committed to Postgres), `geldar_eventsink_failed_total{reason}` (`parse`, `validate`, `db`), `geldar_eventsink_dlq_written_total` (dead letters stored), `geldar_eventsink_consumer_pending` (gauge, the durable consumer's pending count). No payload, subject text, event id or life id is recorded.
- Off without `GELDAR_TELEMETRY_URL`: `eventsinkTelemetry` returns undefined, with no metrics object, no timer and no request. With the URL it pushes at once, then every 15 s.
- Lag: `startConsumer` samples the pending count every 15 s (`lagIntervalMs`), only when metrics are on. A failed read keeps the last value and does not stop the sink.
- Wiring: `eventsink/src/main.ts` builds the `startConsumer` options in `consumerOptions`: `metrics` is present only with telemetry on. `main()` runs only as the entry point, so the helper can be tested without connecting to NATS.
- Tests: `eventsink/src/metrics.test.ts` (14 `it` blocks), `eventsink/src/consumer.start.test.ts` (the metrics hand-off through `startConsumer`), `eventsink/src/main.test.ts` (the options with and without the URL).
- Revert-checks (each: one line changed, test run, restored, tree clean): the no-URL return of `eventsinkTelemetry` (the no-URL test and the wiring test fail); the `metrics` hand-off in `startConsumer` (the new consumer test fails; before that test was added, every test passed); the `metrics` spread in `consumerOptions` (the URL-set test fails).

## 10. Follow-ups

- Eventsink `parse` and `validate` are not split: `eventsink/src/validate.ts` counts every invalid body as `validate`, so a body that is not JSON or not UTF-8 is also counted as `validate` (`metrics.test.ts` pins this). Split `parse` from `validate`.
- Cover the `startConsumer` lag timer: only `samplePending` is tested; the interval that calls it is not.
- `adam-body.ts`: the `countingSink` and world-age wiring are untested (section 7).
- NATS reconnect metric skipped: `connectNats` has no reconnect hook to count.
- Index lines to add: the 0088 README row for ops (the metrics index entry, for the ops merge step; not added here).
- `replay_minutes` is documented as optional with a default of 60 (range 1 to 1440) in the code; the shard and README docs should say so.
- `reopen` follow-up: `reopen` calls `source.open(subjects, fromIso)` with the startup `fromIso`, so a long-running MCP replays its startup window again on each reopen. Dedupe keeps it safe; the cost is a larger re-read. Follow-up, not in this card.
