# C7-06c worknote: account page, status line and body controls

Card: C7-06c in [c7-user-management-packets.md](../packets/c7-user-management-packets.md). Branch `phase1/c7-06c`. Status: partial. live: pending.

## What is built

- Per-agent status line (`threshold/register/src/account-pages.ts`): `Body: running|starting|waiting|stopped` on the agent's
  line, only where a loader gave a state. Retired agents get no body line. The duplicate `Status: <status>` paragraph is
  removed; the agent line still shows the stored status in its header.
- `bodyStateOf(httpStatus, state)`: a 404 from the status route is `stopped`; a 200 with a known state is that state;
  anything else is unknown and shows nothing.
- `AccountDeps.bodyState` (`threshold/register/src/account.ts`): an optional per-agent loader, called for non-retired
  agents on each account page. All loader calls run in parallel (`Promise.all`). Each call is bounded by
  `boundedState` (2000 ms; a timer that is cleared in `finally`; a timed-out call gives no line). A throw, a rejection
  or a timeout logs the fixed text `body status unavailable` and that agent gets no line. The error text is not logged.
- No credit, token expiry or last-used text is shown. `PlayerRow` has no such fields and no loader provides them.
- Tests: `threshold/register/test/account-body-status.test.ts` (render tests, hostile state escaping, and Account-level
  tests through `handle` with a stub store and loader: running, throw and reject, retired agent not called, two agents
  with different states, and two loaders that never settle answering 200 within 2 s). Two existing assertions in
  `account-v2.test.ts` and `account-links.test.ts` were changed to match the removed duplicate status paragraph.
  `account-v2.test.ts` title renamed; its body is unchanged.

## Loader wiring (not done; the caveat for the wiring packet)

- `main.ts` does not pass a loader (main.ts is outside this card's may-edit list). In production the status line does
  not show yet.
- The loader must be wired only when the body routes are mounted (C7-04c2, which needs `REGISTER_NATS_*`). With NATS
  unset there is no loader and no line.
- The loader must map the in-process supervisor reply (the `ctl.body.status` answer), not the HTTP status of the
  body route.
- **404 caveat.** `bodyStateOf` maps a 404 to `stopped`. That is correct only for the supervisor reply "no such body".
  A 404 from an unmounted route (no NATS, so no body routes) is not "stopped" and would show a false line. The mapping
  has no production caller today; the wiring packet must keep the two cases apart before it passes a loader.

## Not built (and why)

- **Body start, stop and restart buttons.** The body routes (`/agents/{id}/body/*`, scope `body`) are not cookie-only. They
  read the CSRF token from the `x-csrf-token` header (`api/index.ts`). A plain HTML form cannot send that header, so the
  buttons need a fetch script with the page's CSRF token, and a CSP for it. Not built here; card C7-06d.
- **Visibility toggles as `PATCH /agents/{playerId}`.** The toggles remain the existing form POSTs to
  `/register/players/{id}/public-camera` and `/public-thoughts`. PATCH is cookie-only with the `x-csrf-token` header, so
  it needs the same fetch script. Not built; card C7-06d.
- **Token expiry, last used and credits.** Need a loader that supplies that data. Not built; card C7-06d.
