# C2-07d: colo follow-ups from C2-07c1 and C2-07c2

## Changed
- `compose/colo.yml` `admin`: also mounts the `postgres-glass.txt` file secret (short form, as `postgres-mcp.txt`), so `colo-up.sh`'s `migrate --set-role-password geldar_glass --password-file /run/secrets/postgres-glass.txt` finds the file. Before this the step would fail on a real node. The other admin secret users were checked: `geldar_mcp` (`postgres-mcp.txt`) was already mounted; `postgres` and the pepper too. Repo check in `colo-services.test.ts`.
- `deploy/colo-up.sh`: after the image pulls and before the first `up`, one `dc run --rm --no-deps --user 0:0 --cap-add CHOWN --cap-add DAC_OVERRIDE --cap-add FOWNER -v geldar-colo_paper-data:/data --entrypoint sh admin -c "mkdir -p /data/bluemap/web && chown UID:UID /data/bluemap /data/bluemap/web"`. The `bluemap-web` service mounts that directory as a volume subpath (R28), which fails when it is missing. The call is project-scoped (`-p geldar-colo`), keeps the admin service's read-only root, `cap_drop: ALL` and `no-new-privileges`, adds back only the three capabilities mkdir and chown need, mounts only the project's Paper volume, and chowns the two directories only (no `-R`). It is idempotent (`mkdir -p`, same owner) and goes through `act`, so a dry run names it and runs nothing.
- `colo-up.sh` now also refuses a release manifest without `GELDAR_ADMIN_IMAGE` (the run needs it; the pull already did).
- Tests: `deploy/test/colo-up-webroot.test.ts` (fake docker: the call happens once before the first `up`, argv scope, repeat run issues the same command, dry run, missing admin image).
