## What changed

## Card steps, as built

1. Registry is the first gate and the only whitelist: `LoginGate.classify` checks the sync flag and the registry entry before any state change. Done.
2. Unregistered: refused with `LoginGate.DENY_MESSAGE`, which names no registry, life or agent (pinned by a test). Done.
3. Ghost: admitted as spectator, blocked from `geldar:cmd`. The forced spectator game mode is NOT done in Velocity: Velocity has no game-mode API. It is Paper's job (Geldar-Core ghost enforcement, plugin/core, which the card lists as must-not-edit). Recorded in 0092.
4. Port: no port is in the repo or in this worknote. Ops runbook placeholder: `<shard TCP port>`. Check it is not already forwarded at the edge before C2-07 step 2 (live).
5. SRV (documented, created by the owner under 0071): `_minecraft._tcp` pointing at `<shard TCP port>`. Not created by this packet.

## Ghost state: the gap

The registry value is `{life_id, registered_at}`, written by the Golem registry writer (`golem/src/registry.ts`). It has no liveness field. So today no name is a ghost, and a registered name is live as long as its entry is fresh (90 s). The `live` field is the seam. A writer that sets `live: false` is a change outside this packet's `may-edit` list (golem/src), and it needs an owner decision on how a ghost is written (spec 8.4 `geldar ghost add`).
