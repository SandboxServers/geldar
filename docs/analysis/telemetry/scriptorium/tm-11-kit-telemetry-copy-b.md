## Steps

1. Same source commit `<sha>` as TM-10 (read the first line of `packages/telemetry/src/attributes.ts`).
2. Copy the three files as in TM-10 (first-line vendor comment, otherwise byte-identical, LF). In `index.ts` delete only the `createLogger` export block and the `extractTrace`/`injectTrace` export block; mark the deletion with one comment line.
3. `pnpm install` (the root script) so the lockfile records the ten OpenTelemetry packages at their exact versions. Confirm the lockfile diff names only those packages and their dependencies. Confirm each version is at least two weeks old (they are the geldar pins, merged 2026-11-15 or earlier; if the repo's `minimumReleaseAge` refuses one, stop and report).
4. Write `test/drift.test.ts`:
   - (a) for each of the six copied files, strip the first line, hash with SHA-256, compare to `manifest.json`. This does not need the geldar repository.
   - (b) if the environment variable `GELDAR_REPO` points at a geldar checkout, also compare each hash with the geldar file at the same name (skipped, with a logged reason, when unset; in CI it is unset).
   - (c) `startTelemetry({ service: 'x', version: '0' })` with no endpoint returns `enabled: false` and installs nothing (no global provider changed: compare `trace.getTracerProvider()` before and after).
   - (d) with `endpoint` set to a closed loopback port, `startTelemetry` returns quickly, a span can be created and ended, and `shutdown()` resolves within 12 s (twice the export timeout plus slack) without throwing.
5. Revert check: edit one character in `copied attributes.ts` below the header; (a) must fail naming the file. Restore. Change `startTelemetry` to throw when the endpoint is unset; (c) must fail. Restore.
