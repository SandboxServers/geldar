# Privacy and safety rules S1 to S12: the checks every card carries

Governing: 0350 (points 2, 3, 6, 7, 8), 0351 (points 3, 8, 10, 11, 12) and Principle 1 (spec section 2: nothing we build lets a human act inside the world; here, nothing the plugin does touches the world or reaches an agent). Each card in this folder names the rules it can break and adds the check below. A reviewer checks the named rules against the diff.

Full-text capture of chat, signs, books and RCON text is **owner-approved capture** (0350 point 2: no opt-out during development). It is approved only for delivery **to the gateway**. It is never delivered to the world, a player, an agent, NATS, a file in the world folder or the server console.

| Rule | Statement | The check (a test or scan that fails when broken) | Cards |
|---|---|---|---|
| S1 | The plugin only reads. No player-visible output: no `sendMessage`, action bar, title, boss bar, scoreboard, tab list change, plugin message, sign, book, entity or block change; no event mutation (`setCancelled`, `setMessage`, `setLine`, command-tree edits); no command dispatch | PT-18a source scan with the forbidden list; per-card proxy-event tests that throw on any setter; an unchanged-event assertion in PT-07d | all Paper cards, PT-18a |
| S2 | Nothing the plugin emits reaches an agent. Output goes only to OpenTelemetry logs, metrics and spans. No agent-readable NATS subject is written by Ledger. At the four Geldar-Core seams only `traceparent` and `tracestate` ride NATS headers, and the payload bytes are identical with and without a span. No telemetry word in anything an agent reads | PT-11b to 11d byte-equality tests; PT-18b agent-text scan; PT-18a (no NATS client in `plugin/ledger` or `ledger-core`) | PT-07d, PT-11a to 11e, PT-18b |
| S3 | Content (chat, sign, book, RCON, console and broadcast text) goes through `ContentLog` only, capped to 32 KiB, never as a metric attribute, never as a metric value, never to the console log | PT-03g test (content capped, reaches the sink only); PT-18a (no `getLogger().info(` of content in the content classes: the scan flags `Logger` use in `curated/TextContentFamily` and `OperatorAuditFamily`) | PT-03f, 03g, 07d, 07e, 11c, 12 |
| S4 | No secrets. The plugin never reads `rcon.*`, `server.properties` as a whole, tokens or environment variables; credential-looking attribute keys are replaced by `[redacted]` in the core; the config parser rejects credential-looking keys; exception messages and tab-completion buffers are not captured. The gateway redacts credential-looking keys too, but the plugin does not rely on it | PT-03f and PT-03c tests; PT-05b snapshot test with `rcon.password=hunter2`; PT-07e and 07f tests; scratch rows S2 and X6 (`absent <password>`) | PT-02b, 03c, 03f, 03g, 05b, 07e, 07f, 12 |
| S5 | No addresses. Never `getAddress`, `getRemoteAddress`, `getRawAddress`, `getHostAddress`; IPv4 and IPv6 literals are scrubbed from every string by the core (content text too: assumption 10) | PT-18a forbidden list; PT-03f scrub tests; per-card fakes whose address getters throw; scratch row X6 | PT-03f, 05b, 07d, 07e, 08a, 08b, 08e, 12 |
| S6 | The Paper process never blocks on the exporter. Main-thread work is O(1): primitives copied into preallocated ring slots; one emitter thread drains; every queue is bounded and drops with a counter; no `forceFlush`, no blocking queue, no synchronous I/O, no file read on the main thread. Reads of files, cgroup, stats and disk run on async threads | PT-03d tests (full ring never blocks; a blocking sink does not stop producers; no allocation); per-card fake `HostInfo` main-thread flag tests; scratch row Q1 (sink down for 10 minutes: MSPT within 0.5 ms) | PT-03c, 03d, 03e, 03g, 04, 05, 06, 07, 08, 09, 10 |
| S7 | Per-player data never goes to metric attributes (0350 point 1). Metric attribute values are low-cardinality (world, event_class, window, group) | `AttrKeys.metricAllowed` test; PT-03g bind-time throw; PT-17a dashboard test (no panel groups by life id) | PT-03 api, 03g, 06a, 08b, 09b, 11e, 17a |
| S8 | A telemetry failure never stops the server. `onEnable` catches `Throwable` and disables only the plugin, never `shutdown`; every handler body and collector start is wrapped; one collector failing disables only that collector | PT-03h tests; per-card tests with a throwing dependency | all Paper cards |
| S9 | No commands, no permissions, no `plugin.yml` entries beyond name, main, version, api-version, description and `softdepend` | PT-03a and PT-18a `plugin.yml` tests | PT-03a, 03h, 18a |
| S10 | No listener on an excluded event (the 14 gated events, the legacy chat events, `PlayerLoginEvent`, any `@Deprecated` event). Every registration is `MONITOR`. Turning the plugin off unregisters every listener | PT-06b and 06c exclusion tests; PT-03h `HandlerList` test; PT-08a source check | PT-03h, 06b, 06c, 07a, 08a |
| S11 | No chunk loading and no mutation of the world or of Chunky, BlueMap or CoreProtect: no `getChunkAt`, no forced save, no tick-manager setter; readers use counts, never `getLoadedChunks()` or `getEntities()` | PT-18a forbidden list; PT-05a and PT-10b tests | PT-04b, 05a, 10a, 10b, 18a |
| S12 | Off unless wired. With no agent present, or with `enabled=false`, the plugin does nothing: no ring writes, no queue growth, no export. The agent's `otel.sdk.disabled=true` default and the unset gateway endpoint keep the whole path inert | PT-03g test (`agentPresent=false` leaves the ring empty); PT-02b properties test; scratch row N1 | PT-02b, 03g, 11a |

Review rule: a card that adds a string attribute, a log call, an event class or a file read must say in its report which of S1 to S12 it touched and which test covers it. A card with no covering test is not done.

Known limit, stated once: the plugin cannot recognise a secret typed as plain text inside chat or an RCON command line (for example an operator pasting a token). That text is captured under 0350 point 2, is operator-only, and is erasable on request. The layers that remain are the operator's discipline, the gateway rules (PT-12) and the access limits of 0350 point 6. The outside-player erasure gap of 0350 point 3 stays open and gates any outside player's agent, not this plugin.
