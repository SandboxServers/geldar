# @geldar/psyche: the mirror contract

`psyche/` is the character engine: the sheet rules, the seeded RNG, the roll rules, the engine version and the temperament bank. The Mind kit (`packages/psyche` in the kit) mirrors it, so both sides roll the same way. This file says what the mirror copies and how a change is released. Decision 0281 is the record; worknote `docs/analysis/harness/worknotes/GX-02.md` has the release history.

## What the mirror copies

All of `psyche/src/`, byte for byte, and nothing else. Tests in `psyche/test/` stay here. `psyche/src/` has zero imports outside the package (no `@geldar/*`, no `node:*`, no third-party module), so the copy is self-contained. `psyche/RELEASE.json` is copied beside it.

## The release record

`psyche/RELEASE.json` records the version, the engine version (`ENGINE_VERSION` in `psyche/src/version.ts`), the tree hash of `psyche/src/` and the file list. It is generated by `tools/psyche-release`:

```
node tools/psyche-release/src/cli.ts --write   # regenerate psyche/RELEASE.json
node tools/psyche-release/src/cli.ts --check   # exit 1 when it differs from psyche/src
```

Each release is tagged `psyche-v<version>` on the merge commit that holds the record. The kit pins the tag name and the `tree_hash`. The kit's mirror test recomputes the hash over its copy of `src/` and compares it with the `RELEASE.json` beside it.

## The rule for any change under `psyche/src/`

1. Change `src/`.
2. Run `node tools/psyche-release/src/cli.ts --write`.
3. Bump `version` in `psyche/package.json` (semver; the engine version bumps only on a change to the seed, sheet or roll rules).
4. Commit, and after merge the owner's ops step tags `psyche-v<new version>`.

`pnpm test` (the `release.test.ts` suite) fails when `src/` and `RELEASE.json` disagree, so a change that skips step 2 fails CI first.

## The tree hash: `geldar-tree-v1`

The kit reimplements these rules (about 40 lines). Change them only under a new algorithm name.

- Files: every regular file under `psyche/src/`, recursively. Nothing is excluded. A symbolic link is refused.
- Path: relative to `psyche/src`, with `/` separators.
- Content: the bytes, with each `\r\n` turned into `\n`. A lone CR is kept.
- Order: entries sorted by the UTF-8 bytes of the path.
- `sha256` per file: lower-case hex of that content.
- `tree_hash`: the lower-case hex SHA-256 of the concatenation of `<path>\0<sha256>\n` for each entry, as UTF-8.

The reference implementation is `tools/psyche-release/src/tree-hash.ts`; the pinned vector is `tools/psyche-release/test/fixture/`.

## The temperament bank is inactive data

`psyche/src/temperament.ts` is part of the tree, so the release covers the temperament bank bytes. Nothing reads the bank yet. Its wording stays inactive until the owner approves the delivery route (decision 0281, item 8; D-HC-13). Changing a bank sentence is a `src/` change and follows the rule above; it does not turn the bank on.
