Notes and deviations:

- `MindLinkServer` takes injected `buildSnapshot(options)` (the wiring passes `(o) => buildSnapshot(bot, o)`), a `RequestServer` (`natsRequestServer(nc)` in production), the executor as `Pick<IntentExecutor, 'submit' | 'intentId' | 'intentState'>`, and the Body's `EventPublisher` from `records-nats.ts` for `plan_result` (subject `geldar.<shard>.plan_result`, msg id = `source_event_id` = `eventIdFor('plan_result:<thought_id>')`).
- `current_plan` in the snapshot is tracked by the server: the goal and program of the last plan whose intent `started`, with the executor's `intentState` as status; null when no intent runs (the executor exposes no goal).
- A snapshot request that fails (wrong life, invalid request, builder throws, invalid snapshot) gets no reply and a log line, so the Mind sees a timeout. A malformed plan gets an `invalid_plan` ack when it has a usable `thought_id`, else no reply.
- The ack is stored for each answered `thought_id` (1024 kept), rejections too; a repeat returns it and runs nothing. A plan the executor refuses after the ack is not spoken and its `plan_result` has `said: false` (the schema requires `said`; the card did not list it).
- `reason` of a `plan_result` action comes from the stored `ActionRecord.result.reason` (the record has no top-level `reason`).
- Event source: ordered consumer with `DeliverPolicy.New` (delivers from when it starts). It also drops a message whose subject type differs from its envelope type, and remembers 4096 ids so a redelivery is handed on once. Valid events of unsubscribed lives and events with no `agent_id` are counted as `otherLife`, not `invalid`.
- `reflection` events are only checked as a valid envelope with an object payload (no payload schema for it exists in the contract).
- `NatsBodyLink` also refuses a snapshot whose `agent_id` differs from its life and an ack whose `thought_id` differs from the plan sent.
