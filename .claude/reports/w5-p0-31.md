# P0-31 progress report

Done: `animus/src/reflection/{trigger,digest,reflect,apply}.ts`, tests for all four and `reflection.fixtures.ts` (30 tests).

Notes and deviations:

- No admission port exists in P0-21, so `trigger.ts` defines a small `ReflectionAdmission` (`reserve(cost)` returning a reservation with `settle` and `release`); reflection reserves 2.
- The slot (R13): the trigger holds its own in-flight flag from before the first await, optionally defers while the thinking loop is running (`thinking()` callback; the due is kept and `resume()` runs it), and brackets the run with `thoughtStarted` and `thoughtSettled`. The outcomes map to `ThoughtOutcome` as applied or degraded to `fallback_hold`, invalid to `invalid_output`, model and apply errors to `model_error`.
- The digest is built from the events the trigger buffered (`observe`) plus the journal, the beliefs, the commitment memories and inventory readings (`observeInventory`, fed from snapshots by the caller). Provenance: `observation` stays only when an own-observation digest line matches the statement (80 percent of the shorter sentence's words, two words minimum); a match against heard speech or an existing `report` belief downgrades it to `report`.
- `apply` goes through the MemoryStore port only (relationship rows are the store's decision, overnight decision 40). Memories, beliefs and the summary are embedded in one `embed` call and written in one `writeMemories`; a belief removed and added in one reflection is kept. Degraded mode keeps at most 2 `memories_to_keep` and nothing else, but still sets `last_sleep_day` (otherwise fatigue could never end). An invalid-twice, model-error or apply failure does not set `last_sleep_day`, so the day stays open.
- Episodic memories from `memories_to_keep` are `observation` (subject to the same guard); the summary is `interpretation`, subject `day_summary:<day>`.
- Reflection event payload (free-form): `thought_id`, `outcome`, `degraded`, `attempts`, `memories_written`, error codes and paths. Event ids are `ev_` plus the ULID part of a `th` id because `ids.ts` has no `ev` prefix.
- `fatigueRule` is a dependency flag (the config has only `fatigue_days`); days since sleep is `day - (last_sleep_day ?? born_day ?? day)`.
