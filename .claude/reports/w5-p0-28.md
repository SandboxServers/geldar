Design notes:

- `PgMemoryStore` and `PgJournal` take a structural `PgPool` (`query`, `connect`), so unit tests use a recording fake pool; `openPool(config)` builds the real `pg.Pool` and reads the password from its secret file through `readPostgresPassword`. All statements are parameterised; a vector is a bound `'[...]'::vector` text parameter.
- Beyond the port: `PgMemoryStore.writeMemoriesPartial` (NULL embedding allowed), `backfillEmbeddings(limit)` (needs the optional embedder given at construction), `resolveCommitment`. `MemoryRetriever.retrieve` and `.remember` implement the retrieval order and the degrade-to-deterministic rule (`degradedCount`, observer callback).
- Fatigue: an agent is fatigued when `nowDay - (lastSleepDay ?? bornDay) >= memory.fatigue_days`; the spec gives no other definition.
- Relationship ruling (decision 40): a name that resolves to an `agents` row (by `name` or `game_account`, latest life first, never the life itself) gets a `relationships` row with `otherId` the resolved id; any other name becomes a semantic memory with subject `relationship:<name>` and text `<name>: <impression> (trust <n>)`.
- Deviation: the reflection's relationship update has no `kind`, so the provenance of that memory is `interpretation`.
- Relationship ranking uses trust magnitude as the distance from the neutral 50 (trust is 0 to 100), then recency, then id.
- `retrieve` reads the whole journal (`journalSince(life, 0)`) and keeps the last N entries, because the port has no limit parameter.

Revert-checks (each made a test fail, restored afterwards): episodic dedupe, top-6 cut, fatigued window of 10, trust-magnitude ranking, embedder-failure degrade, 768-dimension check, `search_document: ` prefix, `num_gpu: 0`. Not observable with a fake pool: the SQL name resolution predicate (covered by the integration test only).
