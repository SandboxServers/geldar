# P0-30 progress report

Done: the thinking loop in `animus/src/loop/` (`thinking-loop`, `admission`, `effort`, `fallback`, `plan`, `journal-row`, plus `loop-fixtures.ts` for the tests). 37 tests; `./geldar.ps1 check` passed (all steps, Gradle included).

Behaviour decisions the card left open:

- Outcome mapping of the `thought` event: `planned` (model plan sent); `fallback_continue` (model failed, the interrupted intent was resubmitted); with nothing sent: `tired`, `model_error` or `invalid_output` (the cause); `fallback_hold` only when a plan or snapshot could not be delivered (Body unreachable). A tired cycle that continues an intent reports `fallback_continue`.
- Admission: `Admission` (shared instance, injectable clock) counts 1 per call, 2 for a reflection (`REFLECTION_COST`, for P0-31). A corrective retry reserves a second credit; if refused the cycle is `tired`. A failed call releases its credit (`creditsSettled` 0). `budget_remaining_thoughts` is the credits left when the snapshot arrives.
- `days_since_sleep` = snapshot day minus `last_sleep_day` (falls back to `born_day`, then 0).
- Rows: one `thoughts` row per model call. A tired cycle also gets a row with no call (null input and output, credits 0), because its thought id is used by the event or the fallback plan. The retry row has `wake_reason` `corrective_retry`; its messages are the first call's messages plus `validator.correctiveMessage` (the rejected text is not added as an assistant message; echoing it is the validator's job). A fallback plan carries the first call's thought id.
- One `thought` event per cycle (not per call): id `ev_` + the thought's ULID so a redelivery dedups; `thought_id` is the id of the call that produced the plan; latency is the sum of the calls.
- Effort `high`: reasoning on, 2x `max_tokens`, deadline 2x capped at 60 s (never below the configured deadline). Signals: 2 failed intents in a row (intent `failed`, or a `plan_result` of precondition_failed, invalid_arguments, unsupported_program; reset by completed or started), the previous and current wake both `precondition_failed`/`action_failed`, or a non-null `stuck`.
- Fallback continue: the loop keeps an `IntentLedger` fed from `decision.events` and `digest` (and `loop.observe(event)`, for P0-32 to wire to the EventSource). It resubmits the most recent intent whose last state is `interrupted`, whose accepted event was seen, whose program is in the local Phase 0 allow-list (`travel gather craft rest flee`), with `max_world_ticks` less the ticks between acceptance and interruption (spent budget means hold), validated with `validateThought`. Once the Body accepts the resubmission the old intent is marked and is not resubmitted again. A cancelled call (`stop()`) never falls back.
- Plan: a snapshot without `body_generation` gives generation 0. Every plan is checked with `validatePlanMessage` before sending.
- Memory retrieval is best effort: an embedder or search failure gives no episodic memories. A failed journal write or event publish is counted (`journalErrors`) and does not stop the cycle. Recent thoughts: `journalSince(tick - 24000)` cut to `memory.working_window`.
- `loopOptionsFromConfig(config, versions)` builds the options (model = first tag of the run tier, `modelConfig` from the pin and the temperature, at most 256 chars). The Body version has no source in the config, so the caller passes it.
